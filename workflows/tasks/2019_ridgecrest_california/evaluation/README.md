# Ridgecrest evaluation figures

Compares three kinds of catalog "reproductions" of the 2019 Ridgecrest sequence over the fixed evaluation window **[2019-07-04T00:00:00Z, 2019-07-07T00:00:00Z)**:

1. **Published reference catalogs** — the five audited sources of the case (`data/2019_ridgecrest_california`, gated by `reference_audit.json`): Shelly 2020 (template matching), Liu 2020 (ML picker + GaMMA), Ross 2019 QTM relocated subset, AWR 2025 v2 (long-term GaMMA), and the USGS/SCSN ComCat operational snapshot.
2. **Human-expert reproduction** — scored final since 2026-11-04: `expert/export/68_cc_relocation/60_catalog/catalog_events.csv` (17,917 events), round 57_coda_duplicates (later rounds of the line described below plus stage 66 restoring the large events and stages 65/67, 2026-10-28) with the grid precision of Match&Locate events added; positions unchanged; why the relocation was or was not adopted: `docs/research/progress/2026-11-04_hil_relocation.md`. Earlier description: this repository's `expert/` workflow, round `12_dense_layered` (`expert/export/12_dense_layered/60_catalog/ catalog_events.csv`, 18,537 events): stage-52 joint-DD events plus Match&Locate events from 1,932 templates (0.5 km cover of events passing the location-quality rule: ≥ 1 stage-52 CC link, gap ≤ 150°, NLL σx ≤ 0.8 km; N×MAD 9.5, null false fraction 0.5 %; 4 s separation, closer events only with ≥ 6 templates), the same rule applied to picked events, moved into the frame of Shelly Table 1 as published (constant layers) by stage 63. Recall vs Shelly 93.3 %, Ross 94.1 %, Liu 95.9 %, ComCat 89.0 %; median epicentral 0.44 / 0.79 / 0.46 / 0.60 km; depth vs Shelly −0.09 km (MAD 0.56); 0.5 % of events > 1 km from every Shelly/Ross/Liu event (ComCat 1.5 %). Round history in expert/PLAN.md (stages 60, 62, 63). *Update 2026-10-28:* the expert population is now round `57_coda_duplicates` = `12_dense_layered` with stage-65 direct ML, the depth-bound large events restored by stage 66 (M7.1, M6.4, M5.4) and stage-67 coda ghosts removed (expert/PLAN.md "Baseline corrections"); numbers below that name `12_dense_layered` predate it. Benchmark scores: `human_in_loop/metrics_baseline.json`.
3. **Agent pilot runs** — completed Claude Code × GLM-5.3 runs made before the 2026-10-28 prompt revision (window, field conventions, Match&Locate), kept in `runs_pilot/` (summary `archive/pilot/metrics_v1_summary_pilot.json`) so that they do not enter the formal summary: `runs_pilot/min/claude/glm-5.3/20261013T215003Z` (the Q1 `min` arm), `runs_pilot/tools/claude/glm-5.3/20261015T020300Z` (the Q2 `tools` arm; 11,611 events in window, runner session lost at 6.5 h but the agent finished — record closed via `finalize`), and the historical legacy-baseline run `runs_pilot/base/claude/glm-5.3/20261013T043225Z` (retired prompt; shown for strategy-variance context only).

## Layout

- `metrics.yaml`: the scoring configuration (references and their roles, evaluation mask, matching gates, the human-in-loop final). `metrics_adapter.py` reads this case's reference catalogs for the scorer and must stay beside it.
- `human_in_loop/`: the expert ladder and `metrics_baseline.json` (references, ceilings, the final's own scores).
- `agents/<variant>__<harness>__<model>__<run_id>/`: one folder per formal run, `scores.json` and `figures/`. Every run has the scorer's standard figures, the same for all cases: `spatial_comparison.png` (primary reference, final and run on one extent, map and two depth sections, offsets and origin times against the final) and `location_diagnostics.png` (offsets from the primary reference). `agents/metrics_summary.json` summarises each configuration.
- `comparison/figures/`: all formal runs with the references and the final (`scripts/plot_evaluation_comparison.py --runs formal`).
- `archive/pilot/`: pilot runs made before the 2026-10-28 prompt revision; not formal results.
- Across cases: [`docs/research/progress/RESULTS_OVERVIEW.md`](../../../../docs/research/progress/RESULTS_OVERVIEW.md) (one page) and [`SCORE_TABLE.md`](../../../../docs/research/progress/SCORE_TABLE.md) (every metric); both are regenerated by `python -m SeismoAgentBench.scoring.catalog_metrics table`.

## Event correspondence criteria

Greedy one-to-one pairing (nearest distance, then Δt) within **|Δ origin time| ≤ 4 s** and **epicentral separation ≤ 15 km**, applied independently for each agent run against the expert, Shelly and ComCat populations. Headline numbers:

| Arm | vs Expert | vs Shelly | vs ComCat | median \|Δt\| | median epicentral |
|---|---|---|---|---|---|
| `tools` | 8,015 (P 69.0%, R 48.0%) | 6,060 (78.5%) | 5,317 (81.0%) | 0.95 s | 1.4 km |
| `min` | 2,910 (P 28.2%, R 17.4%) | 2,620 (34.0%) | 2,518 (38.4%) | 0.42 s | 5.0 km |
| `legacy` | 1,208 (P 68.6%, R 7.2%) | 1,147 (14.9%) | 1,108 (16.9%) | 0.30 s | 2.5 km |

Medians are vs Expert. Since 2026-10-25 the expert is the stage-60 union (16,686 events), so recall *vs Expert* fell for every arm (tools: 85.9 % → 48.0 % against the 6,520-event stage-52 catalog) while precision rose; the reference columns are unchanged. The `tools` arm still roughly doubles both precision and recall over `min` against every population.

## Per-run scoring (catalog metrics, v2)

Runs are scored with the pre-registered metrics (`docs/framework/02_Catalog_Metrics.md`), configured for this case in `metrics.yaml`. From the repository root, with the evaluation environment (`/liufeng1afs/software/miniconda3/envs/seismoagent_eval/bin/python`):

```bash
# one run: output contract + catalog metrics (both declared in task_<variant>.json)
python -m SeismoAgentBench evaluate --run-dir workflows/tasks/2019_ridgecrest_california/runs/<variant>/<harness>/<model>/<run_id>
# every run, per configuration (scores unscored runs; failed runs count as zero for detection)
python -m SeismoAgentBench.scoring.catalog_metrics summary --task-dir workflows/tasks/2019_ridgecrest_california
# reference ceilings and the expert final / blind rows
python -m SeismoAgentBench.scoring.catalog_metrics baseline --task-dir workflows/tasks/2019_ridgecrest_california
```

Per run: `<run>/evaluation/metrics.json`, `location_diagnostics.png`, `audit_sample.csv`; per case: `agents/metrics_summary.json`, `human_in_loop/metrics_baseline.json`. Layout: `human_in_loop/` (`metrics_baseline.json`, `expert_ladder.{yaml,json}`, `figures/`: references + human-in-loop agent); `agents/` (`metrics_summary.json`; per run `<variant>__<harness>__<model>__<run_id>/scores.json` and `figures/`, written by the `summary` command and the figure script); `comparison/figures/` (references + human-in-loop agent + all runs). Terminology: the *human-in-loop agent* is the catalog earlier called "expert" — an Agent workflow in which we steered every stage by hand; file and metric keys keep `expert` (`expert_final`, `expert_blind`, `expert_ladder`, the `expert/` pipeline). The figures in this directory are descriptive; their matcher statistics are not benchmark scores.

## Style and palette

Figures reuse the audited publication style of `data/2019_ridgecrest_california/scripts/figures/plot_catalog_comparison.py` (180 mm width, PNG 320 dpi + PDF, DejaVu Sans, panel letters). The five published sources keep their house colors; the new populations are Expert `#E69F00`, Agent tools `#56B4E9`, Agent min `#F0E442` (dash-dot), Agent legacy `#000000` (dashed). Under a Viénot deutan simulation the adjacent-pair OKLab ΔE spans 0.09–0.65; the weakest pair is Expert orange vs Agent-min yellow (the yellow is the only unused Okabe-Ito slot), which is why agent min also carries a dash-dot line style, and every population stays identifiable from panel titles and the population bar regardless of color.
