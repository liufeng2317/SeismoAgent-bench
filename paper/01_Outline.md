# 论文大纲

**把地震学家的经验变成自动检验：让通用 Agent 检查并修复自己构建的地震目录**

*Encoding Seismologists' Experience as Automated Checks for Agent-Built Earthquake Catalogs*

当前结果见 [02_Current_Results.md](02_Current_Results.md)。本文只写论文的问题、论点、证据和结构；实验过程和决策记录见 [docs/research/](../docs/research/README.md)，checker 的完整设计见 [04_Checker_Design.md](../docs/research/04_Checker_Design.md)。

## 1. 核心问题

专家级地震目录不是一条固定工具链的输出，而是"运行 → 诊断 → 上游修复 → 重跑"的循环。驱动这个循环的是经验：

1. **方法与参数策略**：每一步哪些选择重要、什么范围是安全的；
2. **诊断**：某一步结果看起来不对时，最可能是哪个上游选择造成的；
3. **修复**：上游改什么，以及在看不到参考答案时如何确认改对了。

> **这种经验能否写成不依赖参考目录的自动检验，让通用 Agent 检查并修复自己构建的目录？它能弥合多少与专家的差距，边界在哪里？**

## 2. 贡献

1. **seismo checker。** 把专家经验写成一个确定性的、不依赖参考目录、与案例无关的检验工具，覆盖地震目录构建的六个阶段（数据、拾取、关联、绝对定位、相对定位、震级）。它只报告症状，不给原因和修复；Agent 必须对每条报警给出处置（已修复，或给出证据说明理由）。配套的知识 skill 给出方法选择、已知陷阱和"症状 → 可能原因 → 上游修复"手册。
2. **不改变 Agent 的接入方式。** checker 是命令行工具，知识是 Agent Skill，都只是加进 Agent 环境的文件；不定制 Agent 循环，不加子 Agent，因此结论适用于通用 Agent。
3. **对 checker 自身的检验。** 在 human-in-loop 目录（应当干净）和误差已知的 Agent 目录上衡量误报和检出；把误差分为可检测（A 层）、需对照实验区分（B 层）和只靠自身数据看不到（C 层）三类。
4. **边界。** 所有台站或事件共有的误差（速度模型与近地表、震级定标水平、主震尾波中的漏检）只靠 Agent 自己的数据判断不了，需要知识或参考信息；只报症状的报警还会诱导表面修复。

## 3. 论点与证据

状态：✅ 已有证据　🟡 初步　⬜ 未开始。

### 论点 1（动机）：有工具的 Agent 也做不出可信目录，而且看不出自己错了

| 子论点 | 证据 | 状态 |
|---|---|---|
| 1a 专家目录靠经验，不靠固定工具链 | 专家阶梯：检测参数只改变召回 ≤ 0.07，换成模板匹配改变 0.2–0.6；超出专家范围的单个选择造成 5–10 倍的误差 | ✅ |
| 1b 工具必要 | S0 对 S1，六个案例 | ✅ |
| 1c 工具不充分 | S1 没有一个运行可信，只找回最终目录 22–51 % 的事件 | ✅ |
| 1d 错误出在经验能覆盖的地方 | 组件替换：换专家后端后深度和时间误差大部分消失；检测差距来自没有把模板匹配加进目录；Agent 会为明显错误找理由（Prague 把 ML −8 解释为"极安静的微震"） | ✅ |

### 论点 2：专家经验可以写成可靠的无参考检验

| 子论点 | 证据 | 状态 |
|---|---|---|
| 2a 报警可靠 | human-in-loop 目录上的误报；Agent 运行上的检出；合成回归测试（每种植入错误由预期的检查报警） | ✅ 已检验，需整理成表 |
| 2b 知道自己能看到什么 | A/B/C 三层可检测性；对可信标准各判据的覆盖；删去不能区分对错的检查及原因 | ✅ |

### 论点 3：给 Agent checker 和知识后，能弥合一部分差距

| 子论点 | 证据 | 状态 |
|---|---|---|
| 3a 挡住 A 层错误 | 带与不带 checker 的 A 层错误率（震级单位与响应、拾取时移、定位设置造成的深度堆积） | 🟡 后端消融 |
| 3b 知识让 checker 更有用 | checker 对 checker + 知识的消融 | 🟡 单案例试水 |
| 3c 弥合了多少 | 按维度的差距弥合率 (S_k − S1) / (final − S1)，按分级报告 | ⬜ 需要正式运行 |
| 3d Agent 怎样处置报警 | 报警数、修复、给理由、漏报；真修复与表面修复的比例 | 🟡 后端消融已见表面修复 |

### 论点 4：剩下的差距靠自身数据到不了

| 子论点 | 证据 | 状态 |
|---|---|---|
| 4a C 层误差 | 单因素重定位；不给模型时的近地表检验和从数据建模型检验：数据只给方向不给水平 | ✅ 离线检验完成 |
| 4b 最终目录有一部分依赖参考 | human-in-loop 干预编码：执行、方法选择、无参考诊断、依赖参考的诊断四类 | 🟡 阶梯完成，编码未开始 |
| 4c 是否达到可信目录 | 各阶段的可信目录判定 | ✅ 至今没有运行可信 |

## 4. 实验设置

### 4.1 案例

六个案例按事先可知的特征分为三级，用来检验 checker 在不同难度下的作用。

| 分级 | 案例 | 类型 | 台站 | 时段 | 主要难点 |
|---|---|---|---:|---|---|
| 基础 | Prague 2011 | 诱发地震，Mw 5.7 余震 | 23 | 8 天 | 台网紧凑；台站部署变化 |
| 基础 | Magna 2020 | 中强主震–余震，Mw 5.7 | 47 | 8 天 | 盆地速度结构；深度约束 |
| 中等 | Maple Creek 2017 | 黄石震群，最大 Mw 4.4 | 27 | 8 天 | 只有垂直分量的台站；小事件密集；大事件震级 |
| 中等 | Kīlauea 2018 | 火山口塌陷，Mw 6.9 | 25 | 8 天 | 三维结构；Mw 6.9 尾波 |
| 困难 | Ridgecrest 2019 | M6.4 与 M7.1 序列 | 42 | 3 天 | 主震尾波；关联密度极高；大事件质控 |
| 困难 | Kaikōura 2016 | Mw 7.8 多断层余震 | 53 | 8 天 | 260 km 台网；三维结构；一维与三维框架偏移 |

### 4.2 Agent 阶段

同一个通用 Agent（Claude Code × GLM-5.3），只给原始波形、不给参考目录；每一级只多给一个因素。

| 阶段 | 配置 | 比上一级多给 | 作用 |
|---|---|---|---|
| S0 | `min` | 任务、数据、输出合同 | 动机 |
| S1 | `tools` | 经过验证的工具库 `seismotools` 及说明 | 动机；比较的起点 |
| S2c | `checker` | checker（只报症状）+ 处置合同 | checker 单独的作用 |
| S3 | `knowledge_checker` | checker + 知识 skill | 主实验 |
| 上限 | human-in-loop 最终目录 | — | 唯一的比较基准 |

知识中不提供任何具体速度模型。评分端用运行时的 checker 版本重跑，核对报告是否针对提交的目录、每个报警有无处置、"已修复"是否属实。

### 4.3 评估

- **基准**：human-in-loop 最终目录是唯一的比较对象和上限。
- **可信目录判定**：四个维度（事件真实性、时间、空间、震级），每个维度看准确性（相对最终目录的偏移）和稳定性（离散与一致性）；完整性单列。
- **主要度量**：不通过的可信标准数；各维度的差距弥合率。
- **辅助分析**：组件替换、专家阶梯、处置审计。
- **循环性**：checker 和知识的规则都在这六个案例上总结和校准；结果按"规则来源于该案例 / 不来源于该案例"分开报告，有条件时加一个不参与校准的保留案例。

## 5. 章节安排

1. **引言**：Agent 驱动的科学研究需要检验自己的结果；地震目录是一个完整、可客观检验的任务；核心问题与贡献。
2. **相关工作**：科学 Agent；LLM 的自我批评与验证（CRITIC、VerifiAgent 等）；地震目录自动化流程与质控文献。
3. **动机：专家目录靠经验（论点 1）**：专家阶梯；超出范围的选择的代价；S0、S1 的结果；组件替换说明错误出在哪里。
4. **seismo checker 与知识（贡献 1、2）**：设计原则（无参考、与案例无关、只报症状、确定性、只保留可靠的报警）；六个阶段的检查；报警、输入说明、测量值三类输出；处置合同；知识 skill 的内容；接入方式。
5. **实验设置**：案例与分级；Agent 阶段；评估方法与可信目录判定。
6. **结果一：checker 本身（论点 2）**：误报与检出；A/B/C 三层；对可信标准的覆盖；删去的检查。
7. **结果二：Agent 使用 checker（论点 3）**：S2c、S3 对 S1；A 层错误；知识的消融；差距弥合；处置分析与表面修复。
8. **结果三：边界（论点 4）**：C 层误差；工具约定本身是误差来源；干预编码；可信目录判定。
9. **讨论**：哪些目录维度可以交给"Agent + checker"，哪些仍需要人或参考信息；无参考检验对其他科学 Agent 任务的启示；局限（单一模型、运行数少、规则来自同一批案例）。

已定：正式比较用完整流程（含前端拾取、关联、模板匹配），后端版本只用于迭代和归因；checker 1.3 与知识 skill 已冻结。

3. 主要度量用"不通过的可信标准数"、"差距弥合率"，还是两者并列。
4. 水平偏移和深度偏差的固定 1 km 门槛，是否按最终目录自身离绝对定位参考的偏差放宽。

定下后冻结评分器、checker、知识、工具、提示词和 Agent 配置的提交号，再开始正式运行；运行后发现的问题只作附加分析。
