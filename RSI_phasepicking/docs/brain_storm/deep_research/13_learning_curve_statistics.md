# 13. 学习曲线的统计方法

## 要回答的问题

- 回合少、单次运行贵时，怎么报告学习曲线和 agent 性能：rliable（Agarwal 等 2021：IQM、分层 bootstrap 置信区间、性能剖面）、以事件和种子为随机效应的混合效应模型、同一事件的多个拾取相关时的配对/整群 bootstrap、学习曲线下面积（AUC）、斜率检验、多组之间的多重比较控制。
- 要检测给定大小的效应，需要多少种子、多少种任务顺序、多少测试事件（agent 基准的功效分析方法；如 Miller 2024 "Adding error bars to evals"、Bowyer 等、HELM 式的报告）。
- 接受记忆更新的非劣效门控检验（配对 bootstrap 置信区间下界、多个次要指标）。

影响的决定：实验规模和统计方案。

## 结论摘要

- **统计单位要分清：学习效应的单位是"学习流"（种子 × 顺序），不是事件，更不是拾取。** 自我改进 agent 的运行间差异很大：Ye 等在 WebArena 上用 3 次运行、3 种顺序，ReasoningBank 的最好与最差运行相差最多 10.4 个百分点，换顺序后从比基线 +1.5 变成约 −4.5 [7]。因此"学习有效"必须以学习流为重复单位来检验；测试事件只决定每条流的分数测得多准。
- **按设计草案的规模（每组 3 条学习流），只能检测很大的效应。** 若学习流间标准差为 3 个百分点（[7] 中观察到 2–4 个百分点），每组 3 条流时，双侧 α=0.05、功效 80% 的最小可检测差约 6.9 个百分点；5 条约 5.3；10 条约 3.8；要检测与标准差同大的差（3 个百分点）需要每组约 16 条（推断，按正态近似计算）。H3 写的是"相当"，要做等效性检验：等效界 3 个百分点时每组约 17 条流，3 条流只能证明"差别不超过约 6 个百分点"（推断）。
- **少量运行时，bootstrap 和 CLT 区间都偏窄。** Agarwal 等发现百分位 bootstrap 在 N=10 时表现良好，N=3 时低估区间 [1]；Colas 等发现小样本时 bootstrap 检验的假阳性率约 10%（名义 5%），建议用 Welch t 检验、样本少于约 20 时不用 bootstrap [4]；Bowyer 等指出几百个数据点以下 CLT 区间通常严重偏窄，推荐 Wilson 区间或贝叶斯 Beta 后验，配对比较用配对贝叶斯方法 [3]。Patterson 等认为"几乎所有情况下 5 次运行都不足以做强结论"，流程图建议每种配置至少 15 次运行起步 [5]。
- **同一事件的拾取高度相关，要按事件整群。** Miller 报告整群标准误可比朴素标准误大到约 3 倍（DROP 上 3.05 倍）[2]；层级数据的非参数 bootstrap 应在最高层（事件）有放回抽样 [14]。学习流和测试事件是交叉的（每条流都测同一批事件），交叉设计没有精确的 bootstrap（McCullagh 2000）[16]；Owen 的"鸽笼 bootstrap"（行列分别重抽）给出偏保守的方差估计 [15]。主分析建议用以事件、台站和学习流为交叉随机效应的混合模型 [17][18]，学习流很少时用层级贝叶斯模型（HiBayES 声称适合每项评估少于 20 个数据点的情形）[8]。
- **配对能显著降低所需样本。** Miller 给出配对标准误 SE_paired = √(SE_A² + SE_B² − 2·SE_A·SE_B·ρ)，题目层面的相关系数在 0.37–0.64 时，方差可降约三分之一 [2]。对本项目：各组共用相同的种子-顺序组合和相同的测试事件，按"流对"和"事件对"做配对比较（推断）。
- **门控的非劣效检验在 80 个事件上会拒掉大部分无害更新。** 若次要指标的事件级差值标准差为 0.10，在 80 个事件上做"单侧 95% 下界 > −2 个百分点"的检验，一个真实无差别的更新通过一项检验的概率约 0.56，四项独立检验同时通过约 0.10；250 个事件时分别约 0.94 和 0.77（推断，正态近似）。要求所有指标都非劣（交并检验，IUT）不需要多重比较校正（Berger 1982）[19]，但功效是各项之积。另外，每条流约 10 次门控决策，若每次 α=0.05 且所有更新其实无效，至少误收一次的概率约 40%（推断）。
- **学习曲线的汇总统计**：每条流计算三个量——归一化 AUC（反映学得多快多好，Patterson 等称其为"回报率"，结果依赖实验长度 [5]）、终点分数、分数对 log₂(练习事件数) 的斜率；在这些"每流一个数"的量上做组间比较。rliable 的 IQM、分层 bootstrap、性能剖面、改进概率 [1] 可作为补充展示，但它们的设计前提是"多任务 × 多运行"，本项目流数少，不宜作为唯一的检验。

## 详细发现

### 1. 少量运行时的报告方法

#### 1.1 rliable（Agarwal 等，NeurIPS 2021 杰出论文）[1]

| 工具 | 定义 | 优点 | 局限 |
|---|---|---|---|
| IQM（四分位均值） | 去掉最低和最高各 25% 的运行，对中间 50% 求平均（即 25% 截尾均值） | 比均值稳健，比中位数偏差小、效率高，运行少时区间窄得多 | 本身不处理运行间的相关 |
| 分层 bootstrap 置信区间 | 每个任务内有放回抽 N 次运行，算总体统计量，重复多次 | 能在少量运行时给区间 | 百分位区间在 N=10 时表现良好，**N=3 时低估区间** |
| 性能剖面 | 画出分数超过阈值 τ 的运行比例（跨任务和运行） | 对离群运行稳健，一个离群运行最多移动 1/(MN) | 需要较多 运行 × 任务 |
| 改进概率 | 算法 X 在某任务上胜过 Y 的概率，跨任务平均 | 直观 | 不反映改进的大小 |

其他发现 [1]：
- Atari 100k 上，之前的论文多数只用 3 或 5 次运行；样本中位数有偏，且偏差因算法而异（某算法 5 次与 100 次运行的偏差约等于其报告改进的 36%）。
- 经验说法是 20–30 次运行足够，但该基准上中位数的置信区间需要约 50–100 次运行才可靠。
- 作者推荐置信区间而不是显著性检验，并警告：不显著不等于没有差别。**这一点直接针对 H3 的"相当"：不能用"A-physics 与 A-label 差异不显著"来论证二者相当。**

#### 1.2 RL 实验设计的其他建议

- **Colas 等（2018）**[4]：
  - 例子：Half-Cheetah 上两种 DDPG 变体，N=5 时 Welch p=0.1（不显著），bootstrap 区间却不含 0（显著）；功效分析显示 N=5 时功效约 0.49，N=10 时约 0.81；N=10 的最终运行中两种检验都显著。
  - 小 N 时 bootstrap 检验的假阳性率约 10%（名义 5%），Welch 也略高于 5%。
  - 建议：用 Welch t 检验而不是 bootstrap；α 取小于 0.05；做多重比较校正；**预实验至少 20 个种子来估计标准差**；最终样本量取得比功效分析给出的更大。
- **Patterson 等（JMLR 2024）**[5]：
  - "几乎所有情况下 5 次运行都不足以做强结论"；分布偏斜严重时 30 次也可能不够；流程图建议每种配置至少 15 次起步。
  - 推荐用 bootstrap 置信区间作为默认（假设少）；不推荐报标准误（"低置信度的置信区间"）；区分置信区间（随运行数缩小）和容忍区间（反映单个 agent 的分布，不随运行数缩小）。
  - 学习曲线下的平均回报（AUC）适合在线学习的比较，但依赖实验长度。
- **Henderson 等**较早指出随机种子和实现细节会显著改变深度 RL 的结论 [6][未打开原文]。
- **自我改进 agent 的实测方差**（Ye 等 2026）[7]：
  - WebArena/VisualWebArena/SCUBA，GPT-5-mini，3 次运行 × 3 种顺序。
  - 无记忆基线的运行间标准差最高 1.98%（最好–最差差 4.44%）；ReasoningBank 在 WebArena Multisite 上标准差 4.28%、最好–最差 10.42 个百分点；加记忆后方差在 24 种情形中有 17 种上升。
  - 用 3 次运行的 Welch t 检验，默认顺序下 +1.5 个百分点的收益 p=0.23。
  - 作者认为每个任务再重复 3 次会使成本变成 9 倍，难以承受；正文只报告了 n=3，附录提到扩展到 n=6。

#### 1.3 LLM 评测的误差棒

- **Miller（2024）**[2]：
  - 均值标准误 SE = √(Var(s)/n)；二元分数时 SE = √(p(1−p)/n)。
  - **整群标准误**：加上同群内交叉项；DROP 上整群/朴素 = 3.05 倍，MGSM 1.88 倍，RACE-H 1.10 倍。建议报告群数和题数。
  - **重复采样降方差**：每题采 K 次，题内方差变为 σ²/K；在作者的例子中 K=2 降 1/3，K=4 降 1/2，上限 2/3。不建议用降温度来降方差（会引入偏差）。
  - **配对比较**：在题目层面做差值；例中题目层面相关系数为 0.50（MATH）、0.64（HumanEval）、0.37（MGSM）。
  - **功效分析**：n = (z_{α/2} + z_β)² (ω² + σ_A²/K_A + σ_B²/K_B) / δ²；例：ω²=1/9、δ=0.03、α=0.05、功效 80% 时约需 969 道题。
- **Bowyer、Aitchison、Ivanova（ICML 2025 立场论文）**[3]：
  - N=100、目标 95% 时，IID 情形下 CLT 区间实际覆盖率只有 92.5%；N 越小越差；全对或全错时 CLT 区间宽度为 0。
  - 单模型：推荐 Wilson 区间或 Beta(1+S, 1+N−S) 后验；Clopper-Pearson 过于保守。
  - 两模型同题比较：推荐配对贝叶斯方法；有聚类结构时推荐贝叶斯 Beta-Binomial 模型，Miller 的整群 CLT 修正仍偏窄。
  - 提供 Python 库 `bayes_evals`。
- **HiBayES（Luettgau 等，英国 AISI，2025）**[8]：用层级贝叶斯广义线性模型处理"回答嵌套在题目中、题目嵌套在领域中、多次重复运行"的数据，声称适用于每项评估少于 20 个数据点的情形，并有 Python 包。
- **其他方差来源**：Madaan 等用 10 个只差初始化种子的 Llama-2-7B 估计"种子方差"，主张声称的改进应大于这个噪声 [9]；Heineman 等用"信号（区分好坏模型的能力）/ 噪声（训练步间的随机波动）"衡量基准可靠性 [10]；Bouthillier 等指出数据抽样、初始化和超参数选择都显著影响结果，应同时随机化多个变异来源 [11]。
- **HELM 式报告**（Liang 等）[12]：多指标（准确率、校准、稳健性、公平性、偏差、毒性、效率共 7 项）、所有模型在相同条件下评测、公开全部提示和原始输出。对本项目的对应：拾取、极性、定位、覆盖度、成本一起报，公开每次运行的决策记录。
- **Kapoor 等**[23]：agent 评测要把成本和准确率一起优化和报告，并要有真正的留出集，否则会过拟合基准。

### 2. 相关数据：拾取嵌套在事件中

#### 2.1 数据结构

```
学习组（arm） ─┬─ 学习流 s（= 种子 × 顺序）── 记忆快照（0, 25, 50, 100, 200 个练习事件后）
              │                                      │
测试事件 e ───┴──────────── 交叉 ─────────────────────┘
   └── 台站 k ── 拾取（P/S）
```

- 学习流与测试事件**交叉**（每条流都测同一批事件）；拾取**嵌套**在事件中；台站跨事件重复出现，也是一个交叉因素。

#### 2.2 Bootstrap 方案

| 方案 | 做法 | 依据 | 适用 |
|---|---|---|---|
| 事件整群 bootstrap | 有放回抽事件，事件内全部拾取一起带走 | 层级数据应在最高层重抽 [14] | 固定一条流或一个基线时，比较 agent 与 PhaseNet 等（配对：同一事件上两种方法一起抽） |
| 配对事件 bootstrap | 同上，统计量是两种方法在每个事件上的差 | Koehn 的配对 bootstrap 重抽 [13]；对比研究发现 bootstrap、配对 bootstrap 和近似随机化检验的显著性差别很小 [13] | 门控、开源模型替代判定 |
| 两向（鸽笼）bootstrap | 学习流和事件分别有放回重抽 | 交叉随机效应没有一致的重抽方差估计 [16]；鸽笼法偏保守，作者建议可与朴素 bootstrap 组合修正 [15] | 组间学习效应的稳健性检查 |
| 只在流层面重抽 | 每条流先在全部事件上算一个分数，再对流重抽 | rliable 分层 bootstrap [1] | 流数 ≥10 时；流数 3–5 时区间偏窄 [1][4] |

#### 2.3 混合效应模型

- **交叉随机效应**：心理语言学中"被试 × 题目"交叉设计的标准做法 [17]；本项目中"学习流"对应被试，"测试事件"对应题目。
- **随机效应结构**：Barr 等的模拟表明，验证性检验应包含设计所允许的最大随机效应结构，只有随机截距的模型在很多情况下比传统 F1 分析更差 [18]。
- **建议模型**（推断）：
  - 事件级连续指标（如事件内 P 拾取 F1，或定位误差的对数）：
    `y ~ arm * log2(1 + n_practice) + stratum + (1 + log2(1 + n_practice) | stream) + (1 + arm | event)`
  - 拾取级二元指标（0.1 s 内命中）：同样结构的 logit GLMM，加 `(1 | station)`。
  - `stream` 嵌套在 `arm` 中；若各组共用同一组种子-顺序，可加 `(1 | order)` 作为交叉因素，以吸收"顺序难度"。
  - 流数少（每组 3–5 条）时，流层面方差估计不稳定，自由度用 Kenward-Roger 或 Satterthwaite 近似；更稳妥的是贝叶斯层级模型（如 HiBayES、brms）配弱信息先验 [8]。
- **学习效应**是 `arm × log2(1 + n_practice)` 交互项（斜率差）；"某组是否在学"是该组斜率是否大于 0。

### 3. 学习曲线的汇总量和检验

| 量 | 计算 | 回答的问题 | 注意 |
|---|---|---|---|
| 终点分数 | 最后一个（或门控选出的）快照的分数 | 学完后好不好 | 受最后几次更新的随机性影响大 |
| 归一化 AUC | 在 log₂(1+n) 轴上对快照分数做梯形积分，除以轴长 | 学得多快、多稳 | 依赖实验长度和快照位置 [5]；快照位置要事先固定 |
| 斜率 | 每条流上分数对 log₂(1+n) 的回归斜率 | 是否在持续变好 | 非线性曲线时只是平均趋势 |
| 单调性 | 相邻快照中分数下降的比例；或每条流的 Kendall τ | H2 的"近似单调" | 快照少（5 个）时 τ 的取值很离散 |
| 相对增益 | (A-physics − A-placebo) / (A-label − A-placebo) | H3 恢复了标签反馈收益的多少 | 分母接近 0 时不稳定，用 Fieller 区间或 bootstrap |

- 组间比较在"每流一个数"上做（Welch t 检验 [4] 或流层面配对 bootstrap），并用混合模型复核。
- 不做逐快照的检验（会造成大量多重比较）。

### 4. 功效分析：要多少流、多少顺序、多少事件

#### 4.1 学习流数（推断，正态近似，双侧 α=0.05，功效 80%）

最小可检测差（单位与 σ 相同；σ = 学习流间终点分数的标准差，未配对）：

| σ（百分点） | 3 流/组 | 5 流/组 | 8 流/组 | 10 流/组 | 15 流/组 | 20 流/组 |
|---|---|---|---|---|---|---|
| 2 | 4.6 | 3.5 | 2.8 | 2.5 | 2.0 | 1.8 |
| 3 | 6.9 | 5.3 | 4.2 | 3.8 | 3.1 | 2.7 |
| 4 | 9.1 | 7.1 | 5.6 | 5.0 | 4.1 | 3.5 |

- 检测 δ/σ = 1 需每组约 16 条流；δ/σ = 1.5 需约 7 条；δ/σ = 2 需约 4 条。
- 等效性检验（TOST，单侧 α=0.05，功效 80%，真实差为 0）：σ=3、等效界 3 时每组约 17 条；等效界 4 时约 10 条；等效界 5 时约 6 条。
- **配对**（各组共用种子-顺序组合）能降低所需流数，降多少取决于"同一顺序下不同组之间的相关"——这个相关没有文献数字，需在预实验中估计。
- σ 的参考：[7] 中运行间标准差 2–4 个百分点（WebArena 成功率）；本项目指标（拾取 F1、0.1 s 内命中率）的 σ 未知。Colas 等建议**预实验至少 20 个种子**估计 σ [4]——这在 GPT 上太贵，但在开源模型上可行。

#### 4.2 顺序

- [7] 中换顺序造成约 6 个百分点的摆动，大于种子带来的差异。顺序应作为设计因素：例如 5 种顺序 × 2 个种子 = 10 条流，各组共用这 10 个组合（推断）。
- 顺序应随机生成，并在报告中说明是否按难度分层；默认顺序可能是隐藏的课程 [7]。

#### 4.3 测试事件数

- 事件级配对差值的标准差 sd_d 未知；单侧 α=0.05、功效 80% 时的最小可检测差（推断）：

| sd_d | 80 个事件 | 150 | 200 | 400 |
|---|---|---|---|---|
| 0.05 | 1.4 pp | 1.0 | 0.9 | 0.6 |
| 0.10 | 2.8 pp | 2.0 | 1.8 | 1.2 |
| 0.15 | 4.2 pp | 3.1 | 2.6 | 1.9 |

- 对 agent 与基线（PhaseNet 等）的比较，400 个分层事件已经够用；学习效应的瓶颈在流数，不在事件数（推断：在 400 个事件上测量的流终点分数，其测量噪声远小于 2–4 个百分点的流间差异）。
- 因此**中间快照可以用较小的固定曲线集（100–150 个事件）评估，只有终点快照用全部 400 个**，把预算转移到更多的流上（推断）。
- 按 Miller 的公式，每个事件重复运行 K 次只能降低事件内采样方差，事件间方差 ω² 不变 [2]；当 ω² 占主导时，增加事件比增加重复更有效。

#### 4.4 预算示例（推断）

| 方案 | 组数 | 流/组 | 快照 × 曲线集事件 | 终点 × 400 | 评估运行合计 | 学习运行（200 练习 + 门控） |
|---|---|---|---|---|---|---|
| 设计草案 | 3 | 3 | 4 × 100 | 1 × 400 | 约 7.2k | 约 5.4k |
| 推荐（开源模型） | 4（label、physics、placebo、generic） | 10 | 4 × 100 | 1 × 400 | 约 32k | 约 24k |
| 推荐（GPT 确认） | 3 | 3 | 只测终点 | 1 × 400 | 约 3.6k | 约 5.4k |

开源模型方案按设计 §8.3 的 0.5–1 GPU 分钟/事件估计，约 470–930 GPU 小时 [待在试点中实测]。

### 5. 多重比较

- **事先固定少数主比较**，例如：
  1. A-label vs A-placebo（H2：学习是否超过安慰剂）；
  2. A-physics vs A-placebo（H3a：物理反馈是否有用）；
  3. A-physics vs A-label（H3b：等效性或相对增益）；
  4. A-label vs A-bestofN（学习是否超过等算力）。
  对这一族用 Holm 校正 [20][未打开原文]。Colas 等也建议做多重比较校正 [4]。
- **次要指标和分层**（P/S、i/e、震级、震中距）：只报效应量和置信区间；若要检验，用 Benjamini–Hochberg 控制错误发现率 [20][未打开原文]。
- 消融（无内循环、只用数值等）视为探索性，不做确认性检验。

### 6. 门控的非劣效检验

#### 6.1 设计草案的规则

- 主指标：配对 bootstrap 90% 置信区间下界 > 0（等价于单侧 α=0.05 的**优效**检验，不是非劣效）。
- 次要指标：P/S recall 降幅 ≤2 个百分点，极性 ≤2 个百分点，定位中位误差增幅 ≤10%。草案没有说明这是看点估计还是置信区间。

#### 6.2 统计性质（推断，正态近似）

- **主指标的功效**：80 个事件、sd_d=0.10 时，最小可检测改进约 2.8 个百分点。单条规则的真实收益可能只有 1–2 个百分点，多数有益更新会被拒绝。
- **次要指标如果按置信区间做非劣效**（单侧 95% 下界 > −2 pp）：

| 门控事件数 | sd_d=0.05 | 0.08 | 0.10 | 0.15 |
|---|---|---|---|---|
| 80：通过一项 / 四项都通过 | 0.97 / 0.90 | 0.72 / 0.27 | 0.56 / 0.10 | 0.33 / 0.01 |
| 150 | 1.00 / 1.00 | 0.92 / 0.72 | 0.79 / 0.39 | 0.50 / 0.06 |
| 250 | 1.00 / 1.00 | 0.99 / 0.96 | 0.94 / 0.77 | 0.68 / 0.21 |

（真实差为 0 的更新通过的概率；四项按独立计算，实际正相关时会略高。）

- **交并检验（IUT）**：要求每项都非劣时，各项都可以用完整的 α，不需要多重比较校正 [19]；临床试验中"在全部终点上非劣、在部分终点上优效"的组合检验沿用这一原理 [19]。代价是总功效等于各项功效之积，项数多时很保守 [19]。
- **反复门控的误收**：每条流约 8–10 次门控决策，若每次 α=0.05 且更新都无效，至少误收一次的概率约 34–40%。
- **门控集的适应性过拟合**：同一批 80 个事件反复用于决定是否接受，会逐渐过拟合门控集。Dwork 等的"可重用留出集"（Thresholdout）只在检测到过拟合时才透露留出集结果，能在大量自适应查询下保持有效性 [21]。草案的"每接受 10 次更新轮换一半"在接受很少时可能一直不轮换。

#### 6.3 非劣效界的设定

- 临床试验中，非劣效界的设定依据"对照组相对安慰剂的历史效应"（M1）和其中必须保留的比例（M2）[22][未打开原文，定义来自检索摘录]。
- 对本项目的类比（推断）：界值应小于"当前记忆相对空记忆的已有收益"的一部分，例如不超过该收益的一半；否则连续几次"非劣但略差"的更新会把已有收益吃光。

## 对本项目的影响

### 实验规模

1. **H2/H3 的确认性检验放在开源模型上做，每个主要组至少 10 条学习流（5 种顺序 × 2 个种子），各组共用这 10 个组合。** GPT 上每组 3 条流，只作为方向一致性的确认，不单独做显著性结论。如果开源模型不通过 §8.1 的测试，就必须把 H3 降级为探索性结论，并在文中写明最小可检测差。
2. **预实验**：先在开源模型上跑一个组（如 A-label）的 10–20 条短流（50 个练习事件），估计流间标准差 σ 和同顺序组间相关，再按 §4.1 的表定最终流数 [4]。
3. **H3 改写**：从"相当"改为"物理反馈恢复了标签反馈收益的 X%（95% 区间）"，或事先给出等效界（如 4 个百分点）并做 TOST。不能用"差异不显著"论证相当 [1]。
4. **评估集分两级**：中间快照（0、25、50、100）用固定的 100–150 个事件；终点快照用全部 400 个分层事件。快照位置在 log 轴上大致均匀，事先固定。

### 统计方案

1. **主分析**：每条流算终点分数、归一化 AUC、斜率；组间用 Welch t 检验（流数 ≥10 时也报流层面 bootstrap），Holm 校正 4 个主比较。
2. **复核**：交叉随机效应混合模型（流、事件、台站），流少时用贝叶斯层级模型 [8][17][18]；两向（鸽笼）bootstrap 作稳健性检查 [15]。
3. **agent 与基线的比较**（H1）：按事件配对整群 bootstrap [2][13][14]；小子集上的比例用 Wilson 区间或 Beta 后验 [3]；报告拾取数和事件数。
4. **展示**：IQM + 分层 bootstrap（以 P/S × i/e × 震级档为"任务"）、性能剖面、改进概率 [1]，标明 N=3 时区间偏窄。
5. **试点中按拾取计算的 p 值（如 p=4e-7）要全部按事件整群重算** [2]。

### 门控协议

1. **门控集每次从练习池中新抽**（2020–2023 年 Ridgecrest/Coso 已终审事件数量充足），不重复使用同一批 80 个事件；成本不允许时，至少用 Thresholdout 式的做法 [21]，并把"每接受 10 次轮换一半"改为"每 2–3 次决策轮换一半"。
2. **主指标**：保持"配对 bootstrap 90% 区间下界 > 0"，但要知道在 80 个事件上它只能检测约 3 个百分点以上的改进；可把门控事件数提高到 150，或者对同一事件跑 2 个种子取平均以降低事件内噪声 [2]。
3. **次要指标**：只对 1–2 个关键指标（S recall、P recall）用置信区间非劣效（IUT），其余用点估计护栏；否则大部分无害更新会被拒（见 §6.2 表）。非劣效界应与"当前记忆已有收益"挂钩。
4. **累计检查**：每 5 次接受后，在一个从未用于门控的留出集上比较"当前版本 vs 5 次之前的版本"，防止多次"非劣但略差"的累积退化。
5. **报告门控本身的统计**：每条流的提议数、接受数、拒绝原因分布；这本身就是 H2"门控后学习可靠"的证据。

## 未解决与待核

- 本项目指标的流间标准差 σ、事件级差值标准差 sd_d、同顺序组间相关都没有数据；§4 和 §6 的所有数字都是在假设值下的正态近似，必须用预实验替换。
- Colas 等关于 bootstrap 最小样本量的说法，正文中有"少于 10"和"少于 20"两种 [4]，以结论部分的 20 为准。
- HiBayES 在"流数很少"情形下的实际表现、Owen 鸽笼 bootstrap 在本项目这种"流少、事件多"的不平衡交叉设计下的保守程度，都未核 [8][15]。
- Berger（1982）、Holm（1979）、Benjamini–Hochberg（1995）、FDA 非劣效指南只通过二手来源确认了内容 [19][20][22]。
- 序贯检验（随时有效的置信序列）可以在门控中提前停止明显的好/坏更新、节省成本，但本次没有查证具体方法 [待核]。
- [7] 的附录有 n=6 的扩展结果，我没有读到；值得补读，看 3 次和 6 次运行的结论是否一致。
- 需要问老师：能否接受"H3 在 GPT 上只做方向确认、确认性检验在开源模型上做"的安排。
