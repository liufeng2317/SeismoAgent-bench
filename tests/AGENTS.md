# 测试维护规则

本目录统一保存自动化回归测试。来源核验命令与正式 benchmark 评测不是这里的测试用例；完整原始数据核验仍由对应工具执行。

## 组织方式

- 按稳定功能域分组，不逐案例、逐函数、逐配置字段复制测试文件。当前来源准备测试集中在 `source_prepare/`。
- `source_prepare/test_registry.py` 只覆盖来源元数据注册和路径边界；完整目录、波形和原生解析核验不属于默认回归套件。
- 共用代码直接从代码包导入；只有不在包中的入口脚本才按文件路径加载。不把共享函数测试挂在某一个真实案例名下。
- 不在 `scripts/` 或 `benchmark_source/` 下继续散放 `test_*.py`。新专业功能确有测试需求时，再建立相应功能域，避免提前创建空层级。

## 何时新增

- 新增前先说明要防止的具体错误：已发生的 bug、稳定公共行为，或会改变数据语义/完整性的关键边界。
- 同一个行为只是输入不同，优先加入现有参数表并用 `subTest` 标出失败场景。
- 同一行为在 CLI 或端到端测试中已经有效覆盖时，不再逐层复制相同断言；只有下层存在不同失败模式时才单独补充。
- 文档措辞、文件移动、简单配置改名等可逆低风险改动，默认做一次链接、导入或语法检查，不为它们新增永久测试。
- 不按函数数量、文件数量或覆盖率指标机械增加测试；也不为降低测试数量把互不相关的行为塞进一个大测试。
- 修改实现时同步检查旧测试是否失效、重复或只是在复述实现，必要时合并或删除。删减不能丢失已确认的科学语义和完整性边界。

## 夹具和依赖

- 默认使用最小合成输入和临时目录；不把论文、真实大目录、完整核验 JSON、波形或远程服务作为日常测试依赖。
- 原生格式回归只保留触发问题的最小样例。完整目录条数、全部哈希及统计结果通过显式核验命令检查，不复制成大快照。
- 无重复需求时不建立通用 fixture 框架、共享 mock 层或新的测试依赖。
- 测试不下载数据、不更改原始资料、不依赖 `.env` 和个人路径。

## 运行

从仓库根目录执行全部测试：

```bash
python -B -m unittest discover -s tests -v
```

只运行来源准备测试：

```bash
python -B -m unittest discover -s tests/source_prepare -v
```

与改动相关的测试通过后，只在出现新改动、失败或未解决问题时扩大验证；不把反复运行全量资料核验当作默认流程。
