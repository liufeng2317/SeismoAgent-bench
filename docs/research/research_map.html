保持"通用 Agent"的结论成立

知识和 checker 的形式

两层，都是放进环境的文件

  • 诊断：确定性的命令行工具 seismo_checker/，读 Agent 自己的拾取和目录，输出 checker_report.json。里面没有 LLM，不会把异常解释掉。
  • 知识和修复经验：Agent Skill（SKILL.md + 参考文件）。不支持 skill 的 Agent 从 prompt 链接同样的文件。
  • 唯一的强制：输出约定要求附报告和处置；评分时重跑 checker 核对。不写自定义循环。

不用 subagent 的原因

  • subagent 的定义方式各平台不同，结论只能代表一个平台。
  • 多一个 LLM 就多一份算力和意见，提升分不清来自知识还是架构。
  • 已观察到的问题是自我合理化：Prague tools 把 ML −8 解释成"超安静台阵的微震"。确定性标记加必须处置，比再问一个 LLM 更对症。

初步结论

目前能说什么

工具是必要条件

没有工具时，Agent 要从头实现整条流程：Prague 和 Magna 的 min 都没交出有效结果；Prague 补评的拾取整体早 2.5 s。交出结果的两个 min 也有根本问题：Maple Creek 的目录基本是噪声（1 s / 3 km 门限下召回 0.04，80 % 事件在区域外，深度落在速度模型分层面上），Kīlauea 的震级尺度偏 −2.4。

工具不是充分条件

四个 tools 运行没有一个达到可信目录标准，完整度也只有 final 的 22–51 %。完整度的差距基本对应模板匹配：Agent 调用了 Match&Locate，却几乎没用它新增事件。可信度的问题集中在空间和强度，来自后端选择：与 final 相比深度差 +1.10 / −1.94 / −2.18 km，Maple Creek 发震时刻整体晚 1.0 s，Magna 平移 2.5 km，Prague 震级尺度错 2.77。换用专家定位器后，这些误差大部分消失。

Agent 识别不了自己的系统误差

2.5 s 的时间偏移、2.7 个单位的震级偏差、2.5 km 的平移，都能用不依赖参考目录的简单检查发现，但 Agent 没有做，或做了却给出错误解释。这正是 S2 知识和 S3 checker 要检验的部分。

单模型、每个配置只跑一次，已评分四个案例。评估已从 metrics v1 升级到 v2：v1 的宽门限和稀疏主参考目录让散乱、偏移的目录也拿到高分（Maple Creek min 在 v1 下 recall_norm 1.06，tools 1.12）。Kaikōura、Ridgecrest 的结果出来后再定结论。

可信目录标准

事件真实
区域外 ≤ max(10 %, final + 5 %)；盲审虚假率 ≤ 2 %
时间
准确：与 final 的时间偏差 ≤ 0.3 s；稳定：离散 ≤ 0.3 s，大震后不漏检
空间
准确：平移 ≤ 1 km，深度偏差 ≤ 1 km；稳定：离散、偏离结构、深度堆积
强度
准确：震级偏差 ≤ |final| + 0.2，M ≥ 4 齐全；稳定：离散、无尺度压缩
完整度
单独报告（找回 final 的比例、recall_norm），不计入判定
