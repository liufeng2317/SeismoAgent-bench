# 研究计划 A：Agent 构建地震目录的基准（SeismoAgentBench）

**定位：** 备选工作。主线是 [研究计划 B：checker](./01_Research_Plan_Checker.md)。两条线可以共用评分和已有运行，但目标和实验需求不同：本计划要的是覆盖面（更多案例、更多模型和 harness），计划 B 要的是深度（少数案例上把方法做扎实）。

**名称：** SeismoAgentBench（Agentic Seismic Catalog Benchmark），仓库和命令行用 `seismoagent-bench`。

## 1. 要回答的问题

> **当前的 Agent 和大模型在地震监测任务上能做到什么程度，彼此差别多大？工具和领域知识对地震目录构建有多重要？**

目标结论有两类：
1. **Agent 和模型之间的差异：** 不同模型、不同 harness 在同一任务上的完成率、目录质量和失败方式。
2. **工具和知识的重要性：** 没有工具、有工具、有工具加知识三种条件下，目录质量差多少，差在哪个环节（检测、定位、震级）。

评估完整工作流（连续波形 → 拾取 → 关联 → 模板匹配 → 绝对定位 → 相对定位 → 震级 → 目录），不评单个算法。参考目录对 Agent 扣留。

## 2. 实验需求

### 2.1 案例：至少 10 个

现有六个案例覆盖三个难度级别。基准的结论要能推广到不同的地震情形、台网和地区，所以至少补充到 10 个。

| 分级 | 现有案例 | 情形 |
|---|---|---|
| 基础 | Prague 2011、Magna 2020 | 诱发地震余震；中等主震–余震 |
| 中等 | Maple Creek 2017、Kīlauea 2018 | 火山区震群；火山山顶塌陷 |
| 困难 | Ridgecrest 2019、Kaikōura 2016 | 大震序列；多断层复杂余震 |

补充的候选（[候选案例池](../data/02_Case_Pool.md) B 级），选择时优先考虑三点：补齐缺少的情形和地区，波形公开可下载，参考目录有高精度重定位：

| 候选 | 情形 | 补充的方面 |
|---|---|---|
| South Napa 2014 | Mw 6.0 余震 | 加州中等主震，三维模型下的高精度参考 |
| Westmorland 2020 | 短时震群（与慢滑移有关） | 震群类型，事件密集 |
| Puerto Rico 2020（一月子集） | 前震–Mw 6.4–余震 | 加勒比，稀疏台网 |
| Samos 2020 | Mw 7.0 余震 | 地中海，离岸序列 |
| Central Italy 2016（子集） | 多主震级联 | 欧洲，参考目录层级丰富 |

每个新案例都需要：下载波形和台站元数据、整理参考目录和评分配置、跑一遍 human-in-loop 流程得到最终目录（作为标尺）。现有六个案例从数据准备到最终目录约用了三周（并行进行）。

### 2.2 模型和 harness：扩充

结论要针对"Agent"这类方法，而不是某一个模型，所以至少需要两个 harness，每个 harness 两个模型。

| harness | 模型（候选） | 现状 |
|---|---|---|
| Claude Code | GLM-5.3；Claude（Opus / Sonnet） | GLM-5.3 已在六个案例上运行 |
| Codex | GPT-5.6-sol 等 | 运行器已支持，正式运行未做 |
| 开源 harness（候选） | 一个开源权重模型 | 未接入 |

Agent、harness 和模型只作为重复维度，不改动任务、工具和评分。

### 2.3 条件：工具和知识

| 条件 | 变体 | Agent 额外得到 |
|---|---|---|
| 无工具 | S0 `min` | 任务、数据、输出约定 |
| 有工具 | S1 `tools` | 验证过的工具库 `seismotools/` 及其文档 |
| 有工具和知识 | S3 `knowledge` | + 知识 skill 和 checker（见计划 B） |

正式比较用完整流程（2026-11-05 决定）。其他输入条件（给常规目录、给拾取）和指导设置（开放文献、专家指导）可作为扩展任务。

### 2.4 规模和成本

一次完整流程运行 5–27 小时。全部组合（10 个案例 × 3 个条件 × 4 个模型–harness 组合 × 2 次重复 = 240 次）太贵，分两层：

- **主矩阵：** 10 个案例 × 3 个条件 × 1 个主配置 × 2 次重复 = 60 次，回答"工具和知识的重要性"。
- **模型对比：** 每个分级取一个案例 × S1、S3 × 其余 3 个配置 × 1 次 = 18 次，回答"模型和 harness 的差异"。

## 3. 评分

- **标尺：** human-in-loop 最终目录（上限，在迭代中看过参考目录）；差距用专家阶梯归因。
- **可信目录标准：** 事件真实性，以及时间、空间、强度（震级）的准确性和稳定性。完整性单独报告。门槛对所有条件和模型相同。
- **产出：** 一张能力图谱，不排行，不给综合分数：完成率、各维度离专家多远、瓶颈在哪个环节、失败方式、计算成本，以及这些如何随案例、模型、harness 变化。
- 定义见 [`03_Scoring_Method.md`](./03_Scoring_Method.md) 和 [`02_Catalog_Metrics.md`](../framework/02_Catalog_Metrics.md)。

## 4. 有效性

- **泄漏：** 参考目录和目标论文对 Agent 扣留；记录 Agent 访问过的网址和路径，命中扣留产品的运行排除。
- **运行环境：** 共享环境写保护；每次运行记录工具库、checker 和 harness 的版本。
- **公平：** 所有模型拿到相同的提示词、工具、时间预算和输出约定。

## 5. 现状（2026-11-05）

- 六个案例的数据、参考目录、human-in-loop 最终目录和评分已完成；S0、S1 在 Claude Code × GLM-5.3 上已运行。
- 已有结论：工具让所有案例都能完成，但没有一个运行达到可信标准；S1 只找回最终目录 22–51 % 的事件，五个 tools 运行没有把模板匹配的检测加进目录（[大纲 §4](./02_Paper_Outline.md)）。
- 缺口：补充至少 4 个案例；接入并运行第二个 harness 和更多模型；S3 和重复运行。
