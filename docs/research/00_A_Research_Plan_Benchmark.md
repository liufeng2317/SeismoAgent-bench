# 研究计划 A：Agent 构建地震目录的基准（SeismoAgentBench）

**定位：** 备选工作。主线是 [研究计划 B：checker](./00_B_Research_Plan_Checker.md)。两条线共用评估方法，但目标和实验需求不同：本计划要覆盖面（更多案例、更多模型和 harness），计划 B 要深度（少数案例上把方法做扎实）。

**名称：** SeismoAgentBench（Agentic Seismic Catalog Benchmark），仓库和命令行用 `seismoagent-bench`。

## 1. 问题与意义

### 1.1 问题

> **当前的 Agent 和大模型，能在多大程度上把连续地震波形独立地处理成可信的地震目录？不同模型和 harness 差别多大？工具和领域知识各自贡献多少？**

### 1.2 为什么重要

- **对地震监测：** 地震目录是地震学最基础的数据产品。全球台网和密集的临时台阵每天产生海量连续波形，目录生产仍高度依赖分析人员，新序列发生后往往要等数周到数月才有研究级目录。Agent 如果能承担其中的常规处理，就能把监测和研究的时效从"月"缩短到"天"。但在把监测交给 Agent 之前，台网和研究者需要一个客观的依据：它们现在能做到什么程度，在哪些情形下不可信。
- **对 AI：** 构建地震目录是一个少见的科学任务，同时具备三个特点：
  - **长程：** 一次运行数小时到一天，要连续做几十个相互依赖的决定；
  - **真实：** 使用真实的观测数据和领域工具，没有简化；
  - **可客观检验：** 有独立发表的高精度目录作精度标准。

  这样的任务能检验 Agent 在真实科学工作流中的规划、工具使用和自我判断，而不只是写代码或回答问题。

### 1.3 为什么是现在

通用 Agent 已经能长时间自主写代码、调用工具和调试，领域专用的科学 Agent 也开始出现在地震学中。但还没有人在完整、真实的地震监测任务上系统地检验过它们，也不清楚性能的瓶颈在模型能力、工具，还是领域知识。

### 1.4 已有工作的空缺

- **科学 Agent 基准**（如 ScienceAgentBench、MLE-bench）的任务多为数据分析或机器学习竞赛，时长短，答案可由代码直接比对，很少涉及多步骤的物理数据处理和对结果可靠性的判断。
- **地震学的机器学习基准**（如 SeisBench 中的拾取器评测）只评单个算法，不评整个工作流中的决策：选什么模型、参数怎么调、结果对不对。
- **自动化目录流程**（如 QuakeFlow、LOC-FLOW）是专家预先设计好的固定流程，检验的是算法组合，不是 Agent 自己做决定的能力。

## 2. 假设与成功标准

**要检验的假设：**
- **H-A1 工具必要：** 有工具（S1）比无工具（S0）的完成率更高、不通过的判据更少。
- **H-A2 工具不充分：** 有工具的 Agent 在多数案例上达不到可信目录标准，差距集中在少数环节，例如检测的完整性和绝对定位。
- **H-A3 知识有用：** 加上知识（S3）后，差距缩小，并且缩小发生在 S1 的薄弱环节上。
- **H-A4 条件比模型更重要：** 条件（工具、知识）造成的差别，大于同一条件下模型和 harness 之间的差别。
- **H-A5 难度分级有效：** 同一配置的表现随难度级别单调下降。

**基准本身的成功标准（建议，冻结前确定）：**
- **有区分度：** 主要配置之间的差别超出重复运行的离散；
- **没有饱和：** 最好的配置在困难级案例上仍有判据不通过，留有提升空间；
- **分级有效：** 难度级别与表现的排序一致（H-A5）；
- **可复用：** 别人能在可接受的成本下复现主要结论（见 §5）。

## 3. 实验设计

### 3.1 案例：至少 10 个

案例要覆盖不同的地震情形、台网条件和地区，并按运行前已知的特征（台网孔径、事件率、结构复杂度、窗口内最大震级）分为基础、中等、困难三级。每个案例取 3–8 天的连续波形，要求波形公开可下载，并且有已发表的高精度目录。

| 来源 | 案例 | 情形 |
|---|---|---|
| 已准备 | Prague 2011、Magna 2020 | 诱发地震余震；中等主震–余震 |
| 已准备 | Maple Creek 2017、Kīlauea 2018 | 火山区震群；火山山顶塌陷 |
| 已准备 | Ridgecrest 2019、Kaikōura 2016 | 大震序列；多断层复杂余震 |
| 补充候选 | South Napa 2014 | 加州中等主震余震 |
| 补充候选 | Westmorland 2020 | 短时震群 |
| 补充候选 | Puerto Rico 2020（一月子集） | 前震–主震–余震，稀疏台网 |
| 补充候选 | Samos 2020 | 离岸大震余震 |
| 补充候选 | Central Italy 2016（子集） | 多主震级联 |

补充候选来自[候选案例池](../data/02_Case_Pool.md) B 级。每个新案例需要：下载波形和台站元数据、整理参考目录并规定各自承担的评估角色、用 human-in-loop 流程得到可达结果（§4.1）。

### 3.2 模型和 harness

结论要针对"Agent"这一类方法，而不是某一个模型。至少两个 harness，每个 harness 两个模型：

| harness | 模型（候选） |
|---|---|
| Claude Code | GLM-5.3；Claude（Opus / Sonnet） |
| Codex | GPT 系列 |
| 开源 harness（可选） | 一个开源权重模型 |

所有组合拿到相同的提示词、工具、时间预算和输出约定。

### 3.3 条件

| 条件 | 变体 | Agent 额外得到 |
|---|---|---|
| 无工具 | S0 `min` | 任务、数据、输出约定 |
| 有工具 | S1 `tools` | 验证过的工具库 `seismotools/` 及其文档 |
| 有工具和知识 | S3 `knowledge` | + 知识 skill 和 checker（见计划 B） |

每一条件只比上一个多一个因素，Agent、harness 和模型不变。S3 中的知识和 checker 作为一个整体条件，它们各自的作用由计划 B 分开检验。

### 3.4 运行矩阵

一次完整流程运行预计 5–27 小时，全部组合（10 × 3 × 4 × 2 = 240 次）太贵，分两层：

- **主矩阵：** 10 个案例 × 3 个条件 × 1 个主配置 × 2 次重复 = 60 次，检验 H-A1、H-A2、H-A3、H-A5。
- **模型对比：** 每个难度级别一个案例 × S1、S3 × 其余 3 个配置 × 1 次 = 18 次，检验 H-A4。

## 4. 评估

### 4.1 标准和参照

- **精度标准：** 已发表的高精度地震目录（模板匹配、波形互相关、双差重定位等方法得到）和官方业务目录。每个目录只承担它能支撑的角色：检测、绝对定位、相对结构、震级、震相拾取；震级以官方目录为准。参考目录之间也不能完全互相召回，所以检测用"独立参考之间能达到的召回"作为上限来归一化。
- **可达结果：** 在同一数据上，由工具加专家经验（human-in-loop）得到的目录，代表 Agent 引入工具和专家经验后能够达到的结果。它不是精度标准，用来衡量差距弥合：(S − S1) / (可达结果 − S1)。
- **事件配对：** 一对一贪心配对，|Δt| ≤ 2 s 且震中距 ≤ 5 km（Kaikōura 为 4 s / 15 km）；另报 1 s / 3 km 和 4 s / 15 km 的敏感性。每次配对都对平移 60 s 的参考重复一次，扣除偶然匹配。

### 4.2 可信目录标准

先判事件是否真实，再分别判时间、空间、强度三个维度的准确性（系统偏差）和稳定性（离散和一致性）。四个维度都通过才算可信目录。门槛是绝对值；可达结果本身达不到的门槛，放宽到可达结果的值加余量。

| 维度 | 判据 | 怎么算 | 通过条件 |
|---|---|---|---|
| 真实性 | 事件在台网覆盖内 | 位于台站凸包外扩 10 km 之外的事件比例 | ≤ 5 % |
| 真实性 | 假事件少 | 盲审抽样中判为假的比例 | ≤ 2 % |
| 时间 | 发震时刻偏差（准确性） | 配对事件发震时刻差的中位数 | ≤ 0.3 s |
| 时间 | 发震时刻离散（稳定性） | 发震时刻差的中位绝对偏差 | ≤ 0.3 s |
| 时间 | 大事件后的检测（稳定性） | 大事件后时段与其他时段召回率之比 | ≥ 0.8 × 可达结果 |
| 空间 | 水平偏移（准确性） | 配对事件东西、南北差的中位数构成的共同偏移 | ≤ 1 km |
| 空间 | 深度偏差（准确性） | 配对事件深度差的中位数 | ≤ 1 km |
| 空间 | 水平离散（稳定性） | 扣除共同偏移后的震中差中位数 | ≤ 1 km |
| 空间 | 偏离构造（稳定性） | 离所有高精度参考事件都较远的事件比例 | ≤ 5 % |
| 空间 | 深度堆积（稳定性） | 落在同一深度值上的事件比例 | ≤ 5 % |
| 强度 | 震级偏差（准确性） | 相对官方目录震级差的中位数 | ≤ 0.2 |
| 强度 | 大事件齐全（准确性） | M ≥ 4、M ≥ 5 事件的召回 | 全部找到 |
| 强度 | 震级离散（稳定性） | 震级差的标准差 | ≤ 0.3 |
| 强度 | 震级标度（稳定性） | 震级差对震级的回归斜率（负值表示大事件被压缩），至少 30 对 | 绝对值 ≤ 0.2 |

**完整性单独报告，不参与判定：** 对每个检测参考的召回率（扣除偶然匹配）、归一化召回、各震级档的 F1、完整性震级 Mc。漏掉小事件但每个事件都准确的目录仍可信，官方目录就是这样。

**成本也要报告：** 每次运行的墙钟时间、token 用量、工具调用次数，用来回答"用 Agent 是否划算"。

完整定义见 [`03_Scoring_Method.md`](../framework/03_Scoring_Method.md) 和 [`02_Catalog_Metrics.md`](../framework/02_Catalog_Metrics.md)。

### 4.3 有效性

- **泄漏：** 参考目录和目标论文对 Agent 扣留；记录 Agent 访问过的网址和路径，命中扣留产品的运行排除。
- **运行环境：** 共享环境写保护；每次运行记录工具库、checker、harness 和模型的版本。

## 5. 产出与复用

**发布的内容：** 每个案例的任务说明、波形和台站元数据的获取脚本（或整理好的数据包）、参考目录及其角色、可达结果、评分程序和运行记录。

**降低复用成本：**
- **后端轨道：** 给定拾取和关联，只做定位、相对定位和震级，一次 1–3 小时；
- **精简轨道：** 每个案例取 1–2 天的子窗口；
- **完整轨道：** 本计划的全部设置。

## 6. 风险

- **成本：** 主矩阵加模型对比约 80 次运行；如超出预算，先砍重复次数，保留案例数。
- **新案例的工作量：** 每个案例都要整理参考目录和得到可达结果；数据不全或参考目录质量不够的候选需要替换。
- **参考目录的局限：** 参考之间框架不同（例如一维与三维模型），绝对定位只用承担定位角色的参考来评估。
- **结论过时：** 模型更新很快，具体配置的成绩会过时；持久的价值在任务、数据、评估方法和失败方式的分析。
