## 4. 正式实验方案（计划 B，待冻结）

**设计**

| 项目 | 内容 |
|---|---|
| 案例 | 现有六个案例；评估窗口和区域见各案例 `evaluation/metrics.yaml` |
| Agent | Claude Code × GLM-5.3（`SeismoAgentBench/configs/agents/claude.yaml`） |
| 主比较 | S1 `tools`（工具库）对 S3 `knowledge`（S1 + checker + checker skill + 知识 skill + 震级资源 + checker 输出约定），每个案例各 2 次，共 24 次 |
| 消融（按需） | S2c `checker`：S1 + checker 和 checker skill，无知识 |
| 任务 | 完整流程，从连续波形到目录和拾取；时间预算 48 小时；提示词不写研究区域 |
| 冻结的材料 | 评分器、各案例评分配置和可达结果、`checker-v1.3`、`seismotools/` 的提交号、各案例提示词和输出约定、Agent 运行配置 |

**评估：** 精度标准为已发表的高精度目录和官方目录；可达结果用于计算差距弥合率 (S3 − S1) / (可达结果 − S1)；可信目录标准见[计划 A §4.2](./00_A_Research_Plan_Benchmark.md)；高精度按[计划 B §4.1](./00_B_Research_Plan_Checker.md)；评分端重跑 checker 核对报告和处置。

**假设和判定规则**

| 编号 | 假设 | 主要度量 | 判定为支持的条件（建议值） |
|---|---|---|---|
| H-B1 | checker 的报警可靠 | 可达结果上的误报数；植入错误的检出 | 可达结果上平均每个案例 ≤ 1 个报警；每类植入的可检测错误都被报出 |
| H-B2 | S3 消除了自身数据能看到的错误 | 震级单位和响应、深度堆积、网格边界、重复事件的发生次数 | S3 的 12 次运行少于 S1 的 12 次运行 |
| H-B3 | S3 弥合了差距 | 不通过的判据数；各维度差距弥合率 | 至少 4 个案例中 S3 的判据数少于 S1，且差别大于同条件两次重复之间的差别 |
| H-B4 | 看不到的误差只在知识提供可用资料时改善 | 发震时刻偏差、深度偏差 | 描述性报告 |
| H-B5 | 多数报警得到真修复 | 修复、给出理由、表面修复、证据不足的比例 | 真修复加有证据的理由 > 50 % |

**分析：** 以运行为单位，同一案例的 S1、S3 配对；逐案例报告数值和方向，跨案例用符号检验；同条件两次重复的差别作为噪声尺度；按"规则来源 / 非来源案例"分开报告；所有运行都报告，主分析之外的标为探索性。

**排除：** 外部原因或框架缺陷中断的运行标为 `EXCLUDED` 并重跑；Agent 自身原因未完成的计为失败运行；泄漏扫描命中扣留产品或共享环境被改动的运行报告但不进主分析。

**已有数据：** 登记前的 S0、S1 正式运行，后端消融和试水，以及离线分析，都是预实验，不进入主分析；S1 因工具已修复而重跑（B9）。
