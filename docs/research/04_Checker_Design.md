# Checker 设计文档

状态：开发中，门槛未冻结（2026-10-30）。本文写给研究者：每项检查测什么、怎么算、为什么这样设计、目前的门槛、已知局限和检验结果。给 Agent 看的工具说明是 `seismotools/checker/README.md`，在冻结后编写，只说明测什么和怎么用，不出现原因、修复方法或任何案例数据。研究设计中的位置见 [`00_Research_Plan.md`](00_Research_Plan.md) §2.4–2.5；经验来源见 [`01_Expert_Experience_and_Checker.md`](01_Expert_Experience_and_Checker.md) §3。

## 1. 定位与原则

checker 是 seismotools 里的一个确定性命令行工具，在 S2c（工具 + checker）和 S3（工具 + 知识 + checker）中提供给 Agent。它回答一个问题：**只看 Agent 自己交出的目录、拾取和台站信息，这个目录有哪些可测量的异常？**

| 原则 | 含义 |
|---|---|
| 不依赖参考目录 | 只读 Agent 的 `catalog.csv`、`picks.csv` 和输入里的台站 StationXML；不读任何参考目录或 human-in-loop 结果 |
| 不针对具体案例 | 规则和门槛对六个案例完全相同，不含任何案例的数字或名称 |
| 只报告症状 | 每个报警只说"测到了什么、偏离预期多少"，不说原因、不给修复方法。判断和修改由 Agent 自己决定（2026-10-30 决定） |
| 确定性 | 同样的输入得到同样的报告；里面没有 LLM，不会把异常"解释掉" |
| 只做能可靠做到的事 | 一项检查只有在干净目录上基本不报警、在有已知错误的目录上能报警时，才保留报警；否则只作为信息报告数值（2026-10-30 决定） |

## 2. 输入与输出

```bash
python seismotools/checker/interface/run.py --catalog catalog.csv --picks picks.csv \
    --stations <StationXML 文件或目录 | stations.csv> --output-dir checker/ [--no-model-ensemble]
```

- **输入：** 输出约定的两个文件（`rejected` 行不参与）；台站来自 StationXML（解析 Network/Station 的经纬度和高程，同一台站多个时段取中位数）或 CSV（`station_id, latitude, longitude, elevation_m`）。拾取的 `station_id` 为 `NET.STA`。
- **预处理：** 以台站中位位置为原点建局部平面坐标（km）。每条已关联拾取连接到其事件和台站，计算震中距、震源距（深度用海平面以下深度加台站高程，即相对台站的深度）和走时 `tt = 拾取时刻 − 发震时刻`。
- **输出：** `checker_report.json`（每项检查的测量值、单位、预期范围、样本数、是否报警、症状描述、细节；报警汇总；所用参数；输入文件哈希）和 `checker_diagnostics.png`（事件与台站分布、深度直方图、P 走时–震源距、Wadati 发震时刻差直方图）。退出码 0，无论是否报警；输入无法读取时为 2。

## 3. 检查项目

按可信目录判定的四个维度组织（[`03_Scoring_Method.md`](03_Scoring_Method.md) §2.6）。"状态"一栏是根据 §4 检验结果的当前判断：**保留报警**、**需校准**、**仅报告**（测量值写进报告，不报警）。

### 3.1 事件真实性

**events_outside_network：台网外事件**
- 计算：台站平均位置为台网中心，台网半径 R = 台站到中心的最大距离；统计震中到中心距离超过 1.25 R 的事件占比。
- 门槛：占比 ≤ 10 %。
- 依据：台网之外的定位约束差，大量台网外事件往往是错误关联或定位发散。
- 局限：火山侧翼、海上余震等真实事件也可能在台网外（Kīlauea human-in-loop 目录 28 %）。
- 状态：需校准（放宽倍数或门槛）。

**isolated_events：孤立事件**
- 计算：每个事件到最近邻事件的震中距 d；门限 L = max(2 km, 5 × d 的中位数)；统计 d > L 的事件占比。
- 门槛：占比 ≤ 10 %。
- 依据：真实地震沿断层或震群聚集，散乱的孤立事件常是噪声或错误定位。门限随目录自身的密度变化，因此紧凑震群和区域台网都适用。
- 状态：目前在所有目录上都未超过门槛（最高 9 %），区分力有限，需校准。

**duplicate_events：重复事件**
- 计算：按发震时刻排序，任意两个事件时间差 ≤ 1.5 s 且震中距 ≤ 3 km 即记为重复；统计涉及重复的事件占比。
- 门槛：占比 ≤ 2 %。
- 依据：同一地震被关联成两个事件，会虚增事件数。
- 状态：所有目录均 ≤ 1 %，保留报警（低成本的安全检查）。

**events_with_few_picks：拾取过少的事件**
- 计算：每个事件在已知台站上的 P 拾取数；统计少于 4 个的事件占比。
- 门槛：占比 ≤ 20 %。
- 依据：P 拾取少于 4 个时，位置和发震时刻基本不受约束，常是关联放得过宽或虚假事件。
- 状态：**保留报警**。human-in-loop 目录全部为 0 %；Prague tools 21 %、Maple tools 31 %、Maple min 59 % 报警。

### 3.2 时间

**wadati_origin_offset / wadati_origin_spread：Wadati 发震时刻**
- 计算：对每个事件，取同一台站的 P、S 拾取对，拟合 `(tS − tP) = a·(tP − t0) + b`。直线在 S−P = 0 处的截距给出数据本身隐含的发震时刻 `t0_W = t0 − b/a`，斜率给出 Vp/Vs = 1 + a。要求每个事件至少 4 对，且 Vp/Vs 在 1.4–2.2 之间。报告所有合格事件的 `t0_W − t0` 中位数（offset）和中位绝对偏差（spread）。
- 门槛：|中位数| ≤ 0.3 s（至少 20 个事件）；离散 ≤ 0.5 s。
- 依据：Wadati 方法不需要速度模型。如果目录的发震时刻整体偏晚或偏早，数据隐含的发震时刻会系统地偏离目录值。
- 局限：均匀介质的线性关系在分层介质和高程台站下不严格成立，干净目录也会有 0.5–0.9 s 的整体偏移（Maple human-in-loop +0.82 s、Magna −0.89 s、Ridgecrest −0.63 s）。相对 human-in-loop 的差值能准确反映真实误差（Maple tools −1.08 s，真实误差为晚 1.15 s），但 Agent 没有这个基线。
- 状态：offset **仅报告**（或只在 |中位数| 超过约 1 s 时报警）；spread 需校准。

**travel_time_intercept：走时截距**
- 计算：取 P 拾取中震源距最近的 60 %；按震源距分成 20 个等样本区间，取每区间走时中位数；对 (距离, 走时) 做加权直线拟合 `tt = c + d/v`。报告截距 c 和视速度 v。
- 门槛：|c| ≤ 0.3 s。
- 依据：发震时刻正确时，走时外推到零距离应接近 0；整体偏移的发震时刻会表现为非零截距。
- 局限：低速表层和速度梯度会让近距离走时偏离直线，干净目录也有 0.7–1.0 s 的截距（Maple、Kīlauea、Kaikōura human-in-loop）。
- 状态：**仅报告**（或只在 |c| 超过约 1 s 时报警，例如 Kīlauea min 1.19 s）。

**rate_after_largest：大震后的事件率**
- 计算：每小时事件数的中位数为基准；取震级最大的 3 个事件，统计每个之后 1 小时内的事件数；报告最小比值。
- 门槛：比值 ≥ 0.5。
- 依据：大震尾波里的小震容易漏检，或被质量控制规则误删；大震后反而更安静是可测的症状。
- 状态：目前所有目录都未报警（Prague tools 0.67 最低），需校准。

**model_ensemble_time：模型组发震时刻**（见 §3.5）

### 3.3 空间

**depth_single_value / depth_at_edges：深度堆积**
- 计算：深度保留到 0.01 km，统计同一深度值上的最大事件占比；以及落在目录最浅或最深深度值上的事件占比。
- 门槛：各 ≤ 5 %。
- 依据：固定深度、定位网格的上下边界、速度模型的分层面，都会让事件堆在同一深度。
- 状态：**保留报警**。在 human-in-loop 中间轮次上查出的都是文档记录过的真实问题（Prague 2.00 km 分层面 9 %、Ridgecrest 第一轮网格顶部 16 %），在 Maple min、Kīlauea min/tools 上也报警。

**sp_depth_offset：S−P 深度**
- 计算：同一台站的 S−P 时间与震源距成正比，`D = K·(S−P)`。先用远台（震中距 > 3 倍深度，此时 D 近似等于震中距）估计 K = 震中距 / (S−P) 的中位数；再对近台（震中距 < 深度）由 `z_SP = sqrt((K·(S−P))² − 震中距²)` 得到数据隐含的深度。报告每个事件 (z_SP − 目录深度) 中位数的全目录中位数。
- 门槛：|中位数| ≤ 1 km（至少 20 个事件）。
- 依据：不需要速度模型的绝对值，也不依赖发震时刻，只用 S−P 和台站几何；目录深度整体偏浅或偏深时会表现出来。
- 局限：K 在远台和近台之间并不相同（速度随深度变化），干净目录也有偏移（Prague human-in-loop +1.08 km）。相对基线能反映真实误差（Magna tools +1.5、Maple tools +1.5，真实分别为浅 1.9、2.2 km），但 Agent 没有基线。
- 状态：需校准（门槛放宽到约 1.5 km 时干净目录不报警）。

**station_residual_outliers / station_residual_azimuth：台站残差**
- 计算：用走时截距拟合的直线作为参考，计算每条近距离 P 拾取的残差，取每个台站的中位数（至少 20 条）。统计 |残差| > 0.5 s 的台站数；并对残差随台站方位（相对事件中心）做 `r = a + b cos θ + c sin θ` 拟合，报告振幅 sqrt(b² + c²) 和最大方向。
- 门槛：没有台站超过 0.5 s；方位振幅 ≤ 0.25 s。
- 依据：个别台站的系统残差提示时钟、坐标或拾取问题；残差随方位呈正弦变化提示整体水平位置偏移。
- 局限：三维结构也会产生方位性残差（Kaikōura human-in-loop 18 个台站、振幅 0.32 s）。
- 状态：需校准；未能查出 Magna tools 2.35 km 的整体平移（振幅 0.08 s）。

**model_ensemble_depth：模型组深度**（见 §3.5）

### 3.4 强度

**magnitude_range：震级范围**
- 计算：震级中位数，以及低于 −2 的事件占比。
- 门槛：中位数在 [−1, 5] 之间，且低于 −2 的占比 ≤ 5 %。
- 依据：局地台网记录到的目录，震级中位数几乎不会低于 −1；大量 −2 以下的震级通常是单位或换算错误。
- 状态：**保留报警**。查出 Prague tools 的单位错误（中位数 −2.47）；但 Kīlauea min 整体偏 −2.4 时中位数为 −0.21，没有查出。

**b_value：b 值**
- 计算：震级按 0.1 分档，最大曲率处 +0.2 作为完备震级 Mc；对 Mc 以上至少 50 个事件用 Aki–Utsu 公式 `b = log10(e) / (平均震级 − (Mc − 0.05))`。
- 门槛：b 在 [0.6, 1.6] 之间（至少 100 个震级）。
- 依据：b 值远离 1 常提示震级尺度被压缩或拉伸。
- 状态：目前所有目录都在范围内（0.74–1.25），区分力有限，保留作为安全检查。

**计划中：震级与检测距离的一致性。** 由每个事件的震级和最远检测台站的距离，按局地震级的距离衰减经验关系推算出"被检测到的最小振幅"。正确的震级尺度会给出合理且大致恒定的值；整体偏低 2 个单位时，推算振幅会低到不合理。这项检查用来补上 Kīlauea min 这类没被查出的震级偏差，尚未实现。

### 3.5 模型组敏感性：model_ensemble_depth / model_ensemble_time

- **目的：** 速度模型造成的整体时间和深度偏差，在不知道真实结构时无法从数据里直接分辨（§3.2、§3.3 的局限）。这项检查不判断哪个模型对，而是测量"这个目录的深度和发震时刻对速度模型有多敏感、落在通用模型给出的范围的哪里"。
- **通用模型（只用全球模型，不含案例信息）：**

| 名称 | 来源 | 构造 |
|---|---|---|
| crust1 | CRUST1.0（1°×1°，9 层） | 台站和事件中心所在格点的剖面，去掉水层和冰层，按到各自固体地表的深度做慢度平均，放在这些格点的平均地表高程；水深超过 0.2 km 的海上格点在有陆地格点时排除 |
| litho1 | LITHO1.0（40,962 个节点） | 台站和事件中心最近的节点，同样平均 |
| ak135、iasp91、PREM | 全球一维模型 | 地壳和最上地幔部分（PREM 的海水层换成上地壳） |
| crust1_wadati_vpvs | CRUST1.0 | Vp 不变，Vs = Vp / 目录 Wadati 拟合得到的 Vp/Vs（在 1.5–2.1 之间时才加入） |

- **计算：**
  1. 取至少 8 个震相（其中至少 2 个 S）的事件，按震相数从多到少取前 300 个；
  2. 用 Agent 自己的拾取，以每个模型分别调用 seismotools 的 NonLinLoc 目录定位器重新定位（EDT_OT_WT，分层模型，参考高程取台站最高高程向上取整到 0.1 km）；
  3. 对所有模型都定位成功的事件，计算目录深度（或发震时刻）超出全部模型解范围的量：在范围内为 0，比所有解更深（更晚）为正，比所有解更浅（更早）为负；
  4. 报告超出量绝对值大于 1 km（0.3 s）的事件占比和超出量中位数，以及每个模型的中位深度差、中位发震时刻差、残差中位数，和各模型解之间的中位离散。
- **暂定门槛：** 超出占比 ≤ 50 %。
- **运行时间：** 每个目录约 10 分钟（6 个模型 × 300 个事件，8 线程）。可用 `--no-model-ensemble` 跳过。
- **第一个测试（Maple tools）：** 6 个模型都定位了全部 300 个事件，各模型解的深度相差 5.4 km（中位），说明这里深度高度依赖模型。但所有通用模型都把事件定得比目录更浅（CRUST1.0、LITHO1.0 浅约 5.8 km，三个一维模型浅 1.7–2.3 km），而目录本身已比 final 浅 2.2 km。黄石地壳速度远低于全球模型，正确答案落在整组模型的范围之外，报警方向与真实错误相反。
- **状态：** 待完整检验（§4）。如果干净的 human-in-loop 目录也常落在范围外，这项检查只报告各模型的差异和离散（"深度对模型的敏感程度"），不报警。

## 4. 检验方法与当前结果

**方法：** 用 `workflows/tools_case_validation/validate_checker.py` 在两类目录上运行 checker：
- 每个案例 human-in-loop 的定位目录（组件替换所用轮次的第 04 步事件和第 03 步拾取），应当基本干净，用来衡量误报；
- 每个已完成的正式 Agent 运行，它们相对 final 的误差已知（[`progress/SCORE_TABLE.md`](progress/SCORE_TABLE.md)），用来衡量检出。

结果写在 `workflows/tools_case_validation/outputs/checker/summary.md`（git 忽略）。

**结果（不含模型组检查；⚑ 为报警）：**

| 检查 | 在 human-in-loop 目录上 | 在 Agent 运行上 | 判断 |
|---|---|---|---|
| 拾取过少 | 全部 0 % | Prague tools 21 % ⚑、Maple tools 31 % ⚑、Maple min 59 % ⚑ | 保留报警 |
| 深度堆积 | Prague 9 % ⚑、Kīlauea 10 % ⚑、Ridgecrest 16 % ⚑（都是已记录的真实问题） | Maple min ⚑、Kīlauea min/tools ⚑ | 保留报警 |
| 震级范围 | 无震级 | Prague tools −2.47 ⚑；Kīlauea min 未查出 | 保留报警，补震级–距离检查 |
| 重复事件 | ≤ 1 % | ≤ 1 % | 保留（安全检查） |
| 台网外事件 | Kīlauea 28 % ⚑ | Kīlauea min 33 % ⚑ | 需校准 |
| 台站残差 | Kaikōura 18 站 ⚑、振幅 0.32 s ⚑ | Maple min、Kīlauea min ⚑ | 需校准 |
| Wadati 发震时刻 | Magna −0.89 ⚑、Maple +0.82 ⚑、Ridgecrest −0.63 ⚑、Kaikōura +0.49 ⚑ | Maple tools −0.26（真实晚 1.15 s，未查出） | 仅报告或放宽 |
| 走时截距 | Maple 0.90 ⚑、Kīlauea 0.72 ⚑、Kaikōura 0.97 ⚑ | Kīlauea min 1.19 ⚑ | 仅报告或放宽 |
| S−P 深度 | Prague +1.08 ⚑ | Magna tools +2.03 ⚑、Maple tools +1.19 ⚑、Maple min −1.44 ⚑ | 放宽到约 1.5 km |

**结论：**
1. 质量类检查（拾取过少、深度堆积、震级范围、重复事件）能可靠地区分，保留报警。
2. 时间和深度的物理一致性检查测得很准，但被结构偏差盖住：相对 human-in-loop 的差值能反映真实误差，绝对值却在干净目录上也会报警。速度模型造成的整体偏差无法只靠 Agent 自己的数据可靠判定，这是 checker 的根本边界，也是 S3 中知识部分要解决的问题。
3. 模型组检查的完整检验正在运行（6 个 human-in-loop 目录 + 8 个 Agent 运行），结果出来后决定它是报警还是仅报告。

**循环性：** 检查规则和门槛都是在这六个案例上总结和校准的。报告 S2c、S3 结果时，按"规则来源于该案例 / 不来源于该案例"分开统计（[`00_Research_Plan.md`](00_Research_Plan.md) §2.5），并在冻结前固定所有门槛。

## 5. 在实验中的用法

- **S2c（工具 + checker）：** checker skill 只说明这个工具存在、测什么、怎么运行，以及输出里必须包含 `checker_report.json` 和每个报警的处置记录（已修复并说明改了什么，或说明不修的理由）。不提供任何原因或修复方法。
- **S3（工具 + 知识 + checker）：** 另有知识 skill，包括"症状 → 可能原因 → 上游修复"的手册，以及速度模型的选择方法（来源、敏感性比较、发震时刻与深度的互相抵消）。
- **评分：** 评分时对提交的文件重新运行 checker，核对报告；统计报警数、已修复、给出理由、未处理，以及 Agent 在提交前运行 checker 的次数（从运行记录统计）。
