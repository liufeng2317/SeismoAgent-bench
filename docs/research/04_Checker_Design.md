# Checker 设计文档

状态：各阶段已实现并合并进 `seismotools/checker`，门槛已按检验结果定下但尚未冻结；有效性分类见 §10.1（2026-10-31）。本文写给研究者，按地震目录构建的处理阶段组织：每个阶段 checker 需要什么输入、算哪些数值检查、给 Agent 看哪些图。给 Agent 看的工具说明 `seismotools/checker/README.md` 在冻结后编写，只说明测什么和怎么用，不出现原因、修复方法或案例数据。研究设计中的位置见 [`00_Research_Plan.md`](00_Research_Plan.md) §2.4–2.5；经验来源见 [`01_Expert_Experience_and_Checker.md`](01_Expert_Experience_and_Checker.md) §3。

## 1. 定位与原则

checker 是 seismotools 里的一个确定性命令行工具，在 S2c（工具 + checker）和 S3（工具 + 知识 + checker）中提供给 Agent。它回答：**只看 Agent 自己的数据和产物，当前这一步有哪些可测量的异常？**

| 原则 | 含义 |
|---|---|
| 不依赖参考目录 | 只读 Agent 的输入数据和它自己的产物；不读任何参考目录或 human-in-loop 结果 |
| 不针对具体案例 | 规则、门槛和图的画法对六个案例完全相同 |
| 只报告症状 | 数值检查只说"测到了什么、偏离预期多少"；图只展示数据和产物。不说原因、不给修复方法，判断由 Agent 自己做 |
| 分阶段、随时可用 | 每个处理阶段都有对应的检查，Agent 可以在任一阶段之后运行，以便在上游及时纠错；何时运行由 Agent 决定 |
| 确定性 | 同样的输入得到同样的报告和图；代表性样本按固定规则选取 |
| 只保留可靠的报警 | 一项数值检查只有在干净目录上基本不报警、在有已知错误的目录上能报警时才报警；否则只报告数值 |

**输出：**
- **数值检查**：分三类写进 `checker_report.json`。`flags`（报警）是 Agent 产物超出预期范围，写一句症状，提交时每个报警都要有处置记录；`input_notes`（输入说明）是输入数据本身的性质超出常见范围（台站缺数据、数据缺口、采样率不一致等），只说明数据允许做到什么，Agent 改变不了，不要求处置；`measurements`（测量值）是测得准、但单独不能说明目录对错的量（§10 的仅报告检查），只给数值和"为什么不评判"的通用说明，不给预期范围，以免 Agent 把它们当成问题去修；
- **可视化**：代表性波形、拾取叠加、剖面图等，写成 PNG，供 Agent 自己查看和判断。它们不报警，但每张图都配有一段数值摘要，写进报告（模型看不了图时仍有信息，见 §9）。

## 2. 阶段总览

| 阶段 | 命令 | 需要的输入 | 数值检查 | 可视化 | 实现状态 |
|---|---|---|---|---|---|
| 1. 数据与预处理 | `--stage data` | StationXML、波形目录；可选 `--processed-waveforms` | 有数据的台站、每日台站数、台网几何、分量与采样率、数据缺口、仪器响应、预处理时移 | 台站分布图、数据可用性矩阵、代表时窗预处理前后对比与频谱 | 已实现（开发副本） |
| 2. 震相拾取 | `--stage picks` | 拾取文件；可选波形目录 | 无拾取台站、无拾取台站日、重复拾取、S/P 比、拾取–初动偏差、拾取信噪比 | 代表时窗叠加拾取、单台站拾取对齐图 | 已实现（开发副本） |
| 3. 震相关联 | `--stage association` | 拾取文件 + 事件表（可以还没有位置） | 已关联占比、忙碌时段关联、拾取过少的事件、重复事件、事件走时一致性 | 每小时拾取数、事件数和关联占比；代表事件的走时剖面 | 已实现（开发副本） |
| 4. 绝对定位 | `--stage location` | 已定位的目录 + 拾取 | 台网外、孤立、方位空隙、深度堆积、深度分层条带、Wadati、走时截距、S−P 深度、台站残差、模型组敏感性 | 震中图、深度直方图、走时–距离图、Wadati 图、东西和南北剖面、台站残差地图、模型组对比图 | 已实现，门槛部分待定 |
| 5. 相对定位 | `--stage relocation` | 重定位目录（`--catalog`）+ 重定位前目录（`--catalog-before`）；可选 `--dtcc` | 发生移动的比例、整体平移、大位移比例、局部厚度变化 | 前后对比的震中图和两个剖面、位移矢量、位移和深度变化直方图 | 已实现（开发副本） |
| 6. 震级 | `--stage magnitude` | 有震级的目录 + 拾取；可选波形和 StationXML | 震级范围、b 值、震级–检测距离、震级复算、大震后事件率 | 频度–震级图、震级对最远检测距离 | 已实现 |

`--stage all` 运行给定输入允许的全部检查。每个阶段同时运行它之前各阶段中用已有输入就能做的检查；两个耗时的部分只在各自阶段运行：代表时窗扫描只在 data（和 all）；模型组默认关闭，只有在 location（或 all）阶段加 `--model-ensemble` 时运行（每个目录 10–45 分钟，且只报告）。提交时，输出约定要求附上对最终目录运行全部阶段的报告和每个报警的处置记录。模板匹配新增的事件进入第 3–4 阶段的检查；专门针对模板检测的检查（零假设检测率、每个模板的检测数）列为后续扩展。

每张图都在 `checker_report.json` 中配有数值摘要（§9）：数据阶段每条代表记录的信噪比、主频和时移；拾取阶段每个时窗的拾取数和每个台站的初动偏差；关联阶段每个代表事件的 P、S 数，P 视速度和残差；定位阶段的深度分位数和每个通用模型相对目录的深度、发震时刻差。

## 3. 阶段 1：数据与预处理

**目的：** 在拾取之前确认用了哪些台站、数据是否完整、分量是否齐全、预处理是否合理。

**输入约定：** `--waveforms` 指向 `NET.STA.LOC.CHA__start__end.mseed` 命名的波形目录。目录或其上一级有 `waveform_inventory.json`（基准任务的输入都有）时，覆盖率、缺口和采样率直接从中读取（由 MiniSEED 头信息统计）；没有时 checker 自己读头信息。`--processed-waveforms` 指向 Agent 预处理后的记录，命名规则相同；只需包含 checker 选中的时窗所在的台站日，报告的 `processed_files_needed` 列出这些文件。很多工具（例如 PhaseNet）在内部做预处理，Agent 可以只用这个选项检查自己显式做的预处理。

**数值检查：**

| 检查 | 计算 | 预期范围 | 状态 |
|---|---|---|---|
| 有数据的台站 | 有元数据的台站中处理时段内有波形的占比；列出有元数据无数据、有数据无元数据的台站 | 有数据无元数据的台站时写输入说明（无法定位使用） | 已实现，输入说明 |
| 每日台站数 | 每天有数据的台站数 | 某天低于中位数一半时写输入说明 | 已实现，输入说明 |
| 台网几何 | 孔径、最近台站间距中位数、以台网中心为准的最大方位空隙 | 报告 | 已实现 |
| 分量与采样率 | 每个台站的分量类型（ZNE、Z12、只有垂直）、仪器类型；采样率是否一致；Z12 通道是否缺方位角；N/E 通道方位偏离标称值超过 5°；缺少仪器响应的通道 | 同一台站采样率不一致时写输入说明，其余报告 | 已实现，输入说明 |
| 数据缺口 | 每个通道日覆盖率低于 90 % 的占比 | ≤ 5 % | 已实现，输入说明（Maple 输入 8.6 %，属于输入数据本身的问题，Agent 应当知道但改变不了） |
| 预处理时移 | 预处理后的记录与同一记录零相位 2–20 Hz 滤波结果的互相关时移，取代表记录的中位数 | \|中位数\| ≤ 0.1 s | 已实现，仅在提供 `--processed-waveforms` 时计算 |

**代表时窗的选择（固定规则）：** 每个台站的垂直分量取每秒一阶差分的峰值，除以该台站全时段的中位峰值；某 20 s 区间内比值超过 8 的台站数最多（相邻两个区间合并以覆盖台网内的走时差）、彼此相隔至少 1 h 的 4 个区间即为代表时窗，大概率是地震。每个时窗取比值最高的 6 个台站，从最早的能量起始前 8 s 开始画 40 s。

**可视化：** `data_stations.png`（台站按分量和仪器类型着色，标出台网中心和 30° 方位扇区）；`data_availability.png`（台站 × 日覆盖率）；`data_window_N.png`（左列原始记录、中列预处理后记录，右列垂直分量的信号和噪声频谱；没有 `--processed-waveforms` 时中列是标准处理，图上注明）。

**检验：** 六个案例的输入上，除 Maple 的数据缺口外不报警；合成数据上，混合采样率和 0.3 s 的预处理时移都能查出。Prague 一次运行约 2 分钟（扫描 552 个日文件）。

## 4. 阶段 2：震相拾取

**目的：** 拾取方法和参数是否合适：台站是否都用上、拾取是否准、有没有系统偏差。

**数值检查：**

| 检查 | 计算 | 门槛 | 状态 |
|---|---|---|---|
| 无拾取台站 | 有波形的台站中没有任何拾取的占比；列出其中只有垂直分量的台站 | ≤ 10 % | **报警**：Maple tools 30 %、Kīlauea tools 20 %（都是只有垂直分量的台站）；Ridgecrest human-in-loop 第一轮 12 % 也是真实问题；其他 human-in-loop ≤ 8.5 % |
| 无拾取台站日 | 在其他日子有拾取的台站，有数据却无拾取的台站日占比 | ≤ 5 % | 安全检查（各目录 ≤ 0.6 %） |
| 重复拾取 | 同台站同震相、间隔 ≤ 0.3 s 的拾取占比 | ≤ 2 % | **报警**（Maple min 11 %） |
| S/P 比 | S 拾取数 / P 拾取数；列出有 P 无 S 的台站 | ≥ 0.3 | 仅报告 |
| 拾取–初动偏差 | 固定抽样（均匀间隔的 40 个台站日，每个最多 10 个拾取）；在拾取前后 3 s 内对 2–20 Hz 零相位滤波记录用 AIC 找初动，P 用垂直分量，S 用两个水平分量中信噪比高者，且 S 从同一事件同一台站 P 拾取之后开始找；只统计初动信噪比 ≥ 3 的拾取 | P：\|中位数\| ≤ 0.2 s；S 仅报告 | P：干净拾取 0.01–0.11 s，整体早 2.5 s 的合成偏差测得 −2.46 s，**报警**。S：仅报告，AIC 在 P 尾波里找 S 初动不可靠：修正搜索窗口后 Magna tools 从 0.68 s 降到 0.20 s，但 Maple tools 的 S 拾取与 human-in-loop 几乎相同（中位差 0.00 s、MAD 0.01 s），测得的偏差却分别是 +0.45 s 和 +0.25 s |
| 拾取信噪比 | 拾取后 2 s 与拾取前 2 s 的均方根振幅比 < 2 的占比 | — | 仅报告：干净目录也有 30–64 %（保留了大量弱拾取） |

零相位滤波会让 AIC 初动略早，所以干净拾取的 P 偏差约 +0.05 s，门槛按此留出余量。拾取–初动偏差专门针对 Prague min 那类错误：所有拾取整体早 2.5 s（PhaseNet 的 blinding 长度换算错误），对照波形就能看出来，不需要参考目录；同样的偏移也会让拾取信噪比降到 1 左右。

**可视化：** `picks_window_N.png`：按每分钟拾取数挑 3 个最密集（相隔至少 1 h）和 2 个稀疏（2–4 个拾取）的时窗，显示最先拾取的 8 个台站的垂直分量和一个水平分量（2–20 Hz，按 99.5 % 分位数裁剪），P 红线、S 蓝线，实线为已关联、虚线为未关联，标出概率；`picks_station_stacks.png`：拾取最多的 4 个台站各取最多 40 个 P 拾取，以拾取时刻对齐叠放（显示 ±4 s），初动应当排在 0 处。

## 5. 阶段 3：震相关联

**目的：** 关联是否把拾取正确地组成了事件：有没有漏关联、拆分或合并。

**数值检查：**

| 检查 | 计算 | 门槛 | 状态 |
|---|---|---|---|
| 已关联占比 | 有事件编号的拾取占全部拾取的比例 | ≥ 20 % | 仅报告（很多 Agent 只提交已关联拾取） |
| 忙碌时段关联 | 拾取最多的 10 % 小时里的关联占比 ÷ 全部时段的关联占比 | ≥ 0.5 | 安全检查 |
| 拾取过少的事件 | P 拾取少于 4 个的事件占比 | ≤ 20 % | **报警**（Prague tools 21 %、Maple tools 31 %、Maple min 59 %；human-in-loop 全部 0 %） |
| 重复事件 | 1.5 s（有位置时加 3 km）以内另有事件的事件占比 | ≤ 2 % | 安全检查 |
| 事件走时一致性 | 以目录自己的中位走时曲线（每个震相，按等拾取数的距离分箱）为参考，去掉每个事件的中位残差后，残差超过 1 s 的拾取占该事件拾取 20 % 以上的事件占比 | — | 仅报告：human-in-loop 1.4–18 %（Kaikōura 最高，区域台网的三维结构），Agent 运行 0.7–8.6 %，不能区分。先试过对每个事件拟合直线，弯曲的区域走时曲线使干净目录更差，已放弃 |

**可视化：** `association_rates.png`：每小时拾取数、事件数和关联占比，标出震级最大的 3 个事件；`association_events.png`：拾取最多、最少（≥ 3）和最忙时段各 2 个事件，横轴震中距（没有位置时按到达先后排序），纵轴拾取时刻减发震时刻，P、S 和同一时段未关联的拾取分色。数值摘要给出每个事件的 P 视速度和残差标准差：Kīlauea tools 上拾取最多的事件残差 0.08–0.12 s，最忙时段两个相隔 14 s 的事件残差 0.6–0.7 s、P 视速度 84 km/s，拾取被混在一起。图能展示这类错误，但对整个目录的统计（上一行）区分不了，所以只作为图和摘要提供。

## 6. 阶段 4：绝对定位

**目的：** 位置和发震时刻是否合理、对速度模型有多敏感。

**数值检查：**

| 检查 | 计算 | 门槛（暂定） | 检验后的判断 |
|---|---|---|---|
| 台网外事件 | 震中距台网中心超过 1.25 倍台网半径的事件占比 | — | 仅报告：Kīlauea human-in-loop 有 28 % 在台网外（火山侧翼的真实事件） |
| 孤立事件 | 最近邻距离超过 max(2 km, 5 倍中位最近邻距离) 的事件占比 | ≤ 10 % | 安全检查：所有目录 ≤ 9 % |
| 方位空隙 | 每个事件有拾取的台站的最大方位空隙；空隙 > 180° 的事件占比 | 报告 | 已实现 |
| 深度堆积 | 同一深度值（0.01 km）的最大占比；落在最浅或最深深度值上的占比 | 各 ≤ 5 % | **报警**：查出的都是真实问题（Prague 2.00 km 分层面、Ridgecrest 网格顶部、Maple min、Kīlauea） |
| 深度分层条带 | 0.1 km 薄层中，事件数 ≥ 10、超过 ±1 km 内各薄层中位数的 3 倍且超过 4 个泊松标准差的部分，占全部事件的比例；只看最浅和最深深度 0.2 km 以内之外的薄层（边缘由上一项负责） | ≤ 5 % | **报警**：干净 human-in-loop 0–2.7 %；Kīlauea min 93 %、Maple min 52 %、Kīlauea tools 11 %、Maple tools 6.5 %、Magna tools 5.9 %（条带在 2.9–3.0、4.9–5.0 km 等速度分层界面上）；Prague human-in-loop 轮次 13 % 是已知的 2.0 km 分层面 |
| Wadati 发震时刻 | 每个事件拟合 (tS − tP) = a(tP − t0) + b，数据隐含的发震时刻与目录发震时刻之差的中位数和离散 | 中位数仅报告；离散 ≤ 0.5 s | 中位数仅报告：结构使干净目录也偏离 0.5–0.9 s。离散**报警**：干净目录 ≤ 0.46 s，Kīlauea min 0.67 s、Maple min 0.63 s，门槛偏紧 |
| 走时截距 | 近距离 P 走时对震源距的加权直线拟合，零距离截距 | 0.3 s | 仅报告：干净目录也有 0.7–1.0 s |
| S−P 深度 | 远台定 S−P 与距离的比例 K，近台由 K·(S−P) 反推深度，与目录深度之差的中位数 | 1.5 km | **报警**：干净目录最大 1.08 km（Prague）；Magna tools 2.03 km，方向与真实误差（偏浅 1.94 km）一致；Maple tools 1.19 km 方向对但未超门槛，Maple min −1.44 km 方向相反。2026-10-31 全部运行：超过门槛的 2 个（Magna tools、Ridgecrest min +1.70）方向都对；门槛以下的方向常常相反（Prague tools +1.04 实际偏深，Ridgecrest tools −1.07 实际偏浅 2.31，Kaikōura tools −1.00 实际偏深）。报警可信，门槛以下的数值会误导；已改为门槛以下只报大小、不报方向 |
| 台站残差 | 相对走时直线的每台站中位残差；残差随方位的正弦拟合振幅 | — | 仅报告：三维结构使干净的区域目录也有大的台站项（Kaikōura 18 个台站超过 0.5 s，方位振幅 0.32 s） |
| 模型组敏感性 | 默认关闭，`--model-ensemble` 开启。抽 100 个记录最好的事件（300 个时 Magna 单个目录需约 40 分钟，运行中不可用），用 Agent 的拾取以 6 个通用模型（CRUST1.0、LITHO1.0、ak135、iasp91、PREM、CRUST1.0 加数据 Vp/Vs）分别重新定位；报告目录深度和发震时刻相对整组解的位置，以及各模型解之间的离散 | — | 仅报告。各通用模型的解之间深度差 3–19 km、发震时刻差 0.25–1.3 s，大于大多数真实误差。时间项在 Kīlauea min、Kīlauea tools、Magna tools 上方向正确，但把干净的 Maple 目录判为深度和时间都超出（黄石实际速度远低于通用模型），对 Maple tools 的深度给出相反方向。报告中保留每个模型相对目录的深度和发震时刻差及对比图，作为对速度模型敏感程度的信息 |

通用模型的来源和区域提取方法见 `seismotools/checker/runtime/velocity_models/README.md`：取台站和事件中心所在格点的剖面，按到各自固体地表的深度做慢度平均，海上格点在有陆地格点时排除。

## 7. 阶段 5：相对定位

**目的：** 双差或聚类重定位是否只改善了相对位置，而没有引入整体平移或虚假结构。

**输入：** 重定位后的目录（`--catalog`）和重定位之前的绝对定位目录（`--catalog-before`），按 `event_id` 对应；可选 `--dtcc`（hypoDD 格式的 dt.cc，报告事件对数、每对观测数和相关系数分位数）。重定位阶段同时对重定位后的目录运行阶段 2–4 的检查。

**数值检查：**

| 检查 | 计算 | 门槛 | 状态 |
|---|---|---|---|
| 发生移动的比例 | 位置有变化的事件占重定位前已定位事件的比例 | ≥ 50 % | 已实现 |
| 整体平移 | 移动事件的东、北、深度位移的中位数 | 水平和深度各 ≤ 1.5 km | 已实现。Magna r6 双差（被采纳）为 0.87 km，所以从 1 km 放宽到 1.5 km |

## 9. 让 Agent 看图：测试结果

可视化只有在 Agent 能看图时才有用。正式运行用的是 Claude Code × GLM-5.3。

- **测试（2026-10-30）：** 让 Agent 用 Read 打开一张 PNG（标题含数字、一个红色圆、一个蓝色三角形）并回答内容。GLM-5.3 自己看不到图（它说 Read 返回的是一个 CDN 链接），随后调用了 Z.ai 服务端内置的 `analyze_image` 工具：图片上传到 bigmodel.cn，由另一个视觉模型返回文字描述。三项内容全部答对。
- **含义：** Agent 能间接"看图"，但它得到的是视觉模型写的文字摘要，不是图本身；图里的细节（例如拾取是否落在初动上）能否被准确转述，取决于那个视觉模型。因此 §1 的要求不变：每张图都必须在报告中配有数值摘要，关键判断不能只依赖图。
- **第二次测试（2026-10-30）：** 给 Agent 两张单台站拾取对齐图，文件名为 figure_A、figure_B，问题保持中性（只问初动相对红线在哪里、是否对齐、估计系统偏移）：A 是 Prague human-in-loop 拾取整体提前 2.5 s，B 是原始拾取。视觉摘要对 A 给出"初动在 +2 到 +3 s，各台站一致，拾取整体早约 2.5 s，属于全局原因而非单个拾取误差"，对 B 给出"初动基本在 0 处对齐，偏差零点几秒，个别离散属正常"，两张都判断正确。前提是图的时间范围要能容纳偏移：最初对齐图只显示 ±2 s，2.5 s 的偏移使初动落在图外，图上只剩噪声；已改为 ±4 s。
- **结论：** 图可以作为数值检查之外的独立信息来源；数值摘要仍然必需，因为能否看出取决于图的范围和另一个视觉模型。

## 10. 检验方法与当前结果

**方法：** `workflows/tools_case_validation/validate_checker.py` 在两类目录上运行 checker：每个案例 human-in-loop 的定位轮次（组件替换所用轮次的拾取、关联和定位结果，应当基本干净，衡量误报），以及每个已完成的正式 Agent 运行（相对 final 的误差已知，见 [`progress/SCORE_TABLE.md`](progress/SCORE_TABLE.md)，衡量检出）。`--stages` 按阶段运行（数据阶段每个案例只跑一次，因为同一案例的运行输入相同），结果写入被忽略的 `outputs/checker_stages*`。可视化不参与检验，但会对代表目录生成，人工检查图是否清楚、样本选得是否有代表性。

**合成回归测试：** `seismotools/checker/examples/smoke/run.sh` 生成 10 个台站、80 个事件、2 小时 50 Hz 的合成数据（含平坦速度响应的 StationXML），运行 14 个场景：每个阶段的干净输入不报警；混合采样率、预处理时移 0.3 s、拾取整体早 2.5 s、10 % 重复拾取、40 % 事件压在同一深度、震级偏 −3、重定位整体加深 2 km、重定位压到 4 个点、震级按 nm/mm 混用偏 −2.68（与复算一致的目录不报警），各自由预期的检查报警（其他阶段对同一错误的连带报警单独列出并允许）。全部通过，约 5 分钟。写测试时发现并修正了三个问题：S−P 很短时 S 的 AIC 搜索找到 P 初动；完全压缩的簇厚度为 0 时比值变成 NaN 而不报警；稀疏目录中泊松涨落被当成分层条带。

**各阶段的检查：**

| 阶段 | 报警 | 仅报告或作安全检查 | 需校准或复核 |
|---|---|---|---|
| 数据 | 预处理时移（其余数据检查是输入说明：有数据无元数据、每日台站数、混合采样率、数据缺口） | 台网几何、分量类型、响应、方位角 | — |
| 拾取 | 无拾取台站、重复拾取、P 拾取–初动偏差 | 无拾取台站日、S/P 比、拾取信噪比、S 拾取–初动偏差 | — |
| 关联 | 拾取过少的事件 | 已关联占比、忙碌时段关联、重复事件、事件走时一致性 | — |
| 绝对定位 | 深度堆积、深度分层条带、Wadati 离散、S−P 深度（1.5 km） | 台网外、孤立（安全检查）、Wadati 发震时刻、走时截距、方位空隙、台站残差、模型组 | — |
| 相对定位 | 整体平移、局部变薄、大位移、移动比例 | dt.cc 统计 | 只有一个真实的干净样本（Magna r6） |
| 震级 | 震级范围、震级–检测距离、震级复算 | b 值、大震后事件率 | — |

**仅报告和输入说明如何实现：** `checks.py` 中的 `REPORT_ONLY` 表列出所有测得准、但在检验集上分不开干净和有错目录的检查（含拾取信噪比、事件走时一致性、方位空隙），`INPUT_CHECKS` 列出描述输入数据的检查；`run.py` 在写报告前统一设定每项的类别（`kind`：product / input / report_only）。`REPORT_ONLY` 的原因会显示给 Agent，因此只写通用说明、不出现案例名或案例数值，案例证据只记在本文。S 拾取–初动偏差在拾取检查内部只报告。seismotools 中的代码和注释同样不出现案例名。

**主要结论：** 质量类检查能可靠区分。时间和深度的物理一致性检查测得准，但被结构偏差盖住：相对 human-in-loop 的差值能反映真实误差，绝对值在干净目录上也会报警。速度模型造成的整体偏差只靠 Agent 自己的数据无法可靠判定，这是 checker 的边界，也是 S3 中知识部分（速度模型的选择方法）要解决的问题；checker 能提供的是"对模型有多敏感"的测量。新加的检查里，分层条带和震级–检测距离补上了以前查不出的两类错误（速度分层界面上的深度堆积、震级整体偏移）；关联的混合错误仍然只能通过图和代表事件的摘要提供给 Agent。

**最终版对已评分运行的覆盖（2026-10-30，不含模型组）：** 干净的 Kaikōura、Maple、Magna human-in-loop 不报警；Prague、Kīlauea、Ridgecrest 的 human-in-loop 中间轮次报出的（2.0 km 分层面、地表或网格顶部堆积、5 个无拾取台站）都是那一轮的真实问题。

| 运行 | 未通过的可信标准（已知误差） | checker 报警 | 查出 |
|---|---|---|---|
| Prague tools | 深度 +1.1 km；震级 −2.77（单位错误） | 震级范围、震级–检测距离、拾取过少的事件 | 震级 ✓，深度 ✗ |

**无效（已为仅报告，本次再次确认）：** 台网外事件、Wadati 发震时刻偏移、走时截距、台站残差（离群和方位）、模型组、拾取信噪比、S 拾取–初动偏差、事件走时一致性（Kaikōura min 0.64 是唯一突出值）、已关联占比、忙碌时段关联、S/P 比、方位空隙。无拾取台站日（所有目录约 0）和重复事件（≤ 1 %）从未触发，开销小，保留作安全检查。

**错误：** b 值（final 自己低于门槛，§8 表）；大震后事件率（无效且数值无意义）；已降级的 S 拾取–初动偏差和模型组。

**对可信标准的覆盖：**

| 可信标准 | 覆盖 |
|---|---|
| 深度堆积 | 全部查出 |
| 震级偏移 | 实现错误 3/3；区域标定差异（Magna、Maple min、Ridgecrest min、Kaikōura tools）查不出，由知识部分的区域系数库处理 |
| 发震时刻 | 离散类全部查出（Wadati 离散）；整体偏差（Maple tools、Kīlauea tools）查不出 |
| 深度偏差 | 部分：S−P 深度 2 个，堆积间接反映 2–3 个 |
| 水平偏移、离散、偏离构造、区域外 | 基本查不出（孤立事件 1 个） |
| 大事件 | 漏检（主震尾波）查不出；最大事件的震级偏低由新增检查部分查出（§8），见下 |

**大事件：两个独立的问题。** 可信标准"大事件"统计的是参考目录中 M ≥ 4 的事件被匹配上的比例，即漏检。(a) **主震尾波中的漏检**：Ridgecrest tools 漏掉的 12 个 M4+ 事件中 10 个在 M7.1 后 1 小时内；Kaikōura tools 只漏 1 个 M4.6，不在主震附近。尾波期间所有台站能量都高，能量扫描和事件率都分辨不出，这是与完整性同类的边界，留给知识部分（大震后用模板匹配补检）。(b) **最大事件的震级被低估**：数据阶段能量最强的 4 个时窗在所有运行里都有事件，但 Ridgecrest tools 把 M7.1、M6.4 记为 5.3、5.2（min 为 6.0、6.0），Kaikōura tools 有时窗事件没有震级。新增的"大事件震级"检查（§8）针对 (b)；按拾取数抽样的震级复算覆盖不到最大的事件。

**作为方案比较器：** 同一批拾取、Agent 自选模型与区域模型的两个目录（§2.4 of [`01_Expert_Experience_and_Checker.md`](01_Expert_Experience_and_Checker.md)），按"报警少者为好"选对 3/5：Kīlauea（报警 3 → 0，Wadati 偏移 0.43 → 0.05 s，与真实发震时刻偏差同时消失）、Magna（区域模型 19 % 压顶）、Maple（区域模型 42 % 分层条带）选对；Prague（区域模型界面条带 13.5 %，但实际更好）和 Ridgecrest（LITHO1.0 消除压顶但整体偏深 2.3 km）选错。比单独判断有用，但需要知识补充：台阶模型的界面条带不代表模型错；所有候选都不合格时应寻找更好的知识而不是挑最不差的。

**据此做的修改（2026-10-31）：**
1. b 值、大震后事件率改为仅报告（`REPORT_ONLY`）。
2. S−P 深度：只有超过门槛时报告方向；门槛以下只报大小，并写明方向不可靠。
3. 新增"大事件震级"检查（§8）：候选事件取拾取台站最多的和目录震级最大的，用长窗口、剔除削波记录复算。没有用能量扫描，因为最大的事件同时也是拾取台站最多的，不必另做耗时的扫描。合成回归测试加入对应预期，14 个场景通过。
4. 报告的预期范围说明中写明：分层条带也会出现在正确分层模型的界面上，不能单独用来比较模型；拾取过少的事件衡量约束程度，不是定位对错。

**循环性：** 检查规则和门槛都是在这六个案例上总结和校准的。报告 S2c、S3 结果时，按"规则来源于该案例 / 不来源于该案例"分开统计（[`00_Research_Plan.md`](00_Research_Plan.md) §2.5），并在冻结前固定所有门槛。

## 11. 在实验中的用法

- **S2c（工具 + checker）：** checker skill 说明工具存在、每个阶段测什么、怎么运行、图在哪里，以及输出里必须包含最终报告和每个报警的处置记录（已修复并说明改了什么，或说明不修的理由）。不提供原因或修复方法。
- **S3（工具 + 知识 + checker）：** 另有知识 skill，包括"症状 → 可能原因 → 上游修复"的手册和速度模型的选择方法。
- **评分：** 对提交的文件重新运行 checker 核对报告；统计每个阶段的运行次数、报警数、已修复、给出理由、未处理（从运行记录统计）。
