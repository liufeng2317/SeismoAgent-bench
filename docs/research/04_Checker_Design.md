# Checker 设计文档

状态：开发中，门槛未冻结（2026-10-30）。本文写给研究者，按地震目录构建的处理阶段组织：每个阶段 checker 需要什么输入、算哪些数值检查、给 Agent 看哪些图。给 Agent 看的工具说明 `seismotools/checker/README.md` 在冻结后编写，只说明测什么和怎么用，不出现原因、修复方法或案例数据。研究设计中的位置见 [`00_Research_Plan.md`](00_Research_Plan.md) §2.4–2.5；经验来源见 [`01_Expert_Experience_and_Checker.md`](01_Expert_Experience_and_Checker.md) §3。

## 1. 定位与原则

checker 是 seismotools 里的一个确定性命令行工具，在 S2c（工具 + checker）和 S3（工具 + 知识 + checker）中提供给 Agent。它回答：**只看 Agent 自己的数据和产物，当前这一步有哪些可测量的异常？**

| 原则 | 含义 |
|---|---|
| 不依赖参考目录 | 只读 Agent 的输入数据和它自己的产物；不读任何参考目录或 human-in-loop 结果 |
| 不针对具体案例 | 规则、门槛和图的画法对六个案例完全相同 |
| 只报告症状 | 数值检查只说"测到了什么、偏离预期多少"；图只展示数据和产物。不说原因、不给修复方法，判断由 Agent 自己做 |
| 分阶段、随时可用 | 每个处理阶段都有对应的检查，Agent 可以在任一阶段之后运行，以便在上游及时纠错；何时运行由 Agent 决定 |
| 确定性 | 同样的输入得到同样的报告和图；代表性样本按固定规则选取 |
| 只保留可靠的报警 | 一项数值检查只有在干净目录上基本不报警、在有已知错误的目录上能报警时才报警；否则只报告数值 |

**两类输出：**
- **数值检查**：有预期范围，超出时写一句症状，进入 `checker_report.json` 的报警列表；
- **可视化**：代表性波形、拾取叠加、剖面图等，写成 PNG，供 Agent 自己查看和判断。它们不报警，但每张图都配有一段数值摘要，写进报告（模型看不了图时仍有信息，见 §9）。

## 2. 阶段总览

| 阶段 | 命令 | 需要的输入 | 数值检查 | 可视化 | 实现状态 |
|---|---|---|---|---|---|
| 1. 数据与预处理 | `--stage data` | StationXML、原始波形目录；可选：预处理后的波形目录 | 台站覆盖、方位分布、分量与采样率、数据缺口 | 台站分布与方位图、数据可用性矩阵、代表波形预处理前后对比与频谱 | 待实现 |
| 2. 震相拾取 | `--stage picks` | 拾取文件；波形目录 | 无拾取台站、无拾取台站日、重复拾取、S/P 比、拾取–初动偏差、拾取信噪比 | 代表性波列叠加拾取 | 部分实现 |
| 3. 震相关联 | `--stage association` | 拾取文件 + 事件表（可以还没有位置） | 已关联占比、忙碌时段关联、拾取过少的事件、重复事件 | 事件率与拾取率时间序列、代表事件的走时剖面 | 部分实现 |
| 4. 绝对定位 | `--stage location` | 已定位的目录 + 拾取 | 台网外事件、孤立事件、方位空隙、深度堆积、Wadati、走时截距、S−P 深度、台站残差、模型组敏感性 | 震中图与剖面、深度直方图、走时–距离图、Wadati 图、台站残差图、模型组对比 | 已实现（门槛待定） |
| 5. 相对定位 | `--stage relocation` | 绝对定位目录 + 相对定位目录；可选 dt.ct / dt.cc | 重定位比例、整体平移、单事件位移、簇厚度、深度堆积 | 前后对比的震中图和剖面、位移矢量 | 待实现 |
| 6. 震级（建议增加） | `--stage magnitude` | 有震级的目录 + 拾取 | 震级范围、b 值、震级–检测距离一致性、大震齐全 | 频度–震级图、震级–最远检测距离图 | 部分实现 |

每个阶段同时运行它之前各阶段中、用已有输入就能做的检查。提交时，输出约定要求附上对最终目录运行全部阶段的报告和每个报警的处置记录。模板匹配新增的事件进入第 3–4 阶段的检查（它们也是事件和位置）；专门针对模板检测的检查（零假设检测率、每个模板的检测数）列为后续扩展。

## 3. 阶段 1：数据与预处理

**目的：** 在拾取之前确认用了哪些台站、数据是否完整、分量是否齐全、预处理是否合理。

**数值检查（全部待实现）：**

| 检查 | 计算 | 预期范围（暂定） |
|---|---|---|
| 台站覆盖 | 有元数据的台站中，在处理时段内有波形的台站数和占比；每天有数据的台站数 | 报告；某天台站数低于中位数一半时报警 |
| 台网几何 | 台网孔径、台站最近邻间距中位数；以台网中心为准的最大方位空隙 | 报告（定位阶段再按事件计算方位空隙） |
| 分量 | 每个台站的通道组合：三分量 ZNE、未定向的 Z12（需要按 StationXML 的方位角旋转）、只有垂直分量；同一台站内采样率是否一致；仪器类型（宽频带、短周期、强震） | 报告各类台站数；同一台站采样率不一致时报警 |
| 数据缺口 | 按波形头信息统计每个台站日的缺口和重叠时长 | 缺口超过 10 % 的台站日占比 > 5 % 时报警 |
| 仪器响应 | StationXML 中每个通道是否有完整响应 | 缺少响应的通道列出（影响震级计算） |

**可视化：**
- 台站分布图：按分量类型和仪器类型着色，标出台网中心和方位扇区；
- 数据可用性矩阵：台站 × 日，颜色表示覆盖率；
- 代表波形预处理前后对比：从数据里按固定规则挑 3–4 个高振幅时窗（多数台站同时出现能量突增，大概率是地震），每个时窗取最近的 6 个台站、三个分量，上排是原始记录，下排是 Agent 预处理后的记录，旁边是两者的频谱。如果 Agent 没有提供预处理后的波形，下排用一个标准处理（去均值、去趋势、2–20 Hz 带通）作对照，并在图上注明。

**需要确定的输入约定：** Agent 的预处理结果以什么形式交给 checker。建议：`--processed-waveforms` 指向与原始数据同样命名规则的 MiniSEED 目录（只需包含 checker 选中的时窗所在的台站日；checker 会在报告里列出它需要哪些文件）。很多工具（例如 PhaseNet）在内部做预处理，Agent 可以只用这个选项检查自己显式做的预处理。

## 4. 阶段 2：震相拾取

**目的：** 拾取方法和参数是否合适：台站是否都用上、拾取是否准、有没有系统偏差。

**数值检查：**

| 检查 | 计算 | 门槛 | 状态 |
|---|---|---|---|
| 无拾取台站 | 有波形的台站中没有任何拾取的占比；列出其中只有垂直分量的台站 | ≤ 10 % | 已实现，**保留报警** |
| 无拾取台站日 | 在其他日子有拾取的台站，有数据却无拾取的台站日占比 | ≤ 5 % | 已实现，安全检查 |
| 重复拾取 | 同台站同震相、间隔 ≤ 0.3 s 的拾取占比 | ≤ 2 % | 已实现，**保留报警** |
| S/P 比 | S 拾取数 / P 拾取数；列出有 P 无 S 的台站 | ≥ 0.3 | 已实现，仅报告 |
| 拾取–初动偏差 | 对抽样拾取，在拾取时刻 ±3 s 内用 AIC 方法在 Agent 自己选用的波形上重新找初动，统计 (拾取 − 初动) 的中位数和离散 | \|中位数\| ≤ 0.1 s | 待实现 |
| 拾取信噪比 | 拾取后 2 s 与拾取前 2 s 的振幅比（同一分量）；统计信噪比 < 2 的拾取占比 | 报告；占比 > 30 % 时报警 | 待实现 |
| 拾取率时间序列 | 每个台站每小时的拾取数 | 报告（供图使用） | 待实现 |

拾取–初动偏差专门针对 Prague min 那类错误：所有拾取整体早 2.5 s（PhaseNet 的 blinding 长度换算错误），这类偏差只要对照波形就能看出来，不需要参考目录。

**可视化：**
- 代表性波列叠加拾取：按固定规则挑 4–6 个时窗，覆盖拾取密集（大概率是地震）和拾取稀疏两种情况；每个时窗显示最近的 6–8 个台站、三个分量，滤波后的波形上标出 P、S 拾取和概率。Agent 自己判断拾取是否落在初动上、S 是否拾在 S 波上、是否漏拾或误拾；
- 单台站的拾取叠加图：同一台站多个拾取以拾取时刻对齐叠放，直观看出拾取是否一致地落在初动上。

## 5. 阶段 3：震相关联

**目的：** 关联是否把拾取正确地组成了事件：有没有漏关联、拆分或合并。

**数值检查：**

| 检查 | 计算 | 门槛 | 状态 |
|---|---|---|---|
| 已关联占比 | 有事件编号的拾取占全部拾取的比例 | ≥ 20 % | 已实现，仅报告（很多 Agent 只提交已关联拾取） |
| 忙碌时段关联 | 拾取最多的 10 % 小时里的关联占比 ÷ 全部时段的关联占比 | ≥ 0.5 | 已实现，安全检查 |
| 拾取过少的事件 | P 拾取少于 4 个的事件占比 | ≤ 20 % | 已实现，**保留报警** |
| 重复事件 | 1.5 s（有位置时加 3 km）以内另有事件的事件占比 | ≤ 2 % | 已实现，安全检查 |
| 每个事件的拾取 | 每个事件的 P、S 拾取数分布 | 报告 | 待实现（并入报告） |

**可视化：**
- 时间序列：每小时拾取数、事件数和关联占比，标出震级最大的几个事件；
- 代表事件的走时剖面：按固定规则挑 4–6 个事件（拾取多、拾取少、忙碌时段各若干），横轴震中距（用关联器给的初始位置；没有位置时按到达先后排序），纵轴拾取时刻，标出 P、S 和同一时段未关联的拾取。拾取应当排成随距离增加的走时曲线，散乱的点提示关联错误。

## 6. 阶段 4：绝对定位

**目的：** 位置和发震时刻是否合理、对速度模型有多敏感。

**数值检查（已实现，门槛待定）：**

| 检查 | 计算 | 门槛（暂定） | 检验后的判断 |
|---|---|---|---|
| 台网外事件 | 震中距台网中心超过 1.25 倍台网半径的事件占比 | ≤ 10 % | 需校准：火山侧翼等真实事件也会在台网外 |
| 孤立事件 | 最近邻距离超过 max(2 km, 5 倍中位最近邻距离) 的事件占比 | ≤ 10 % | 需校准：区分力有限 |
| 方位空隙 | 每个事件的最大方位空隙；空隙 > 180° 的事件占比 | 报告 | 待实现 |
| 深度堆积 | 同一深度值（0.01 km）的最大占比；落在最浅或最深深度值上的占比 | 各 ≤ 5 % | **保留报警**：查出的都是真实问题（Prague 2.00 km 分层面、Ridgecrest 网格顶部、Maple min、Kīlauea） |
| Wadati 发震时刻 | 每个事件拟合 (tS − tP) = a(tP − t0) + b，数据隐含的发震时刻与目录发震时刻之差的中位数和离散；Vp/Vs = 1 + a | 0.3 s / 0.5 s | 仅报告：结构使干净目录也偏离 0.5–0.9 s |
| 走时截距 | 近距离 P 走时对震源距的加权直线拟合，零距离截距 | 0.3 s | 仅报告：干净目录也有 0.7–1.0 s |
| S−P 深度 | 远台定 S−P 与距离的比例 K，近台由 K·(S−P) 反推深度，与目录深度之差的中位数 | 1 km | 需校准：放宽到约 1.5 km 时干净目录不报警 |
| 台站残差 | 相对走时直线的每台站中位残差；残差随方位的正弦拟合振幅 | 0.5 s / 0.25 s | 需校准：三维结构也会产生方位性残差 |
| 模型组敏感性 | 抽 300 个记录最好的事件，用 Agent 的拾取以 6 个通用模型（CRUST1.0、LITHO1.0、ak135、iasp91、PREM、CRUST1.0 加数据 Vp/Vs）分别重新定位；报告目录深度和发震时刻相对整组解的位置，以及各模型解之间的离散 | 超出范围的事件 ≤ 50 % | 检验中：Maple tools 上整组模型都比真实更浅，报警方向与真实错误相反 |

通用模型的来源和区域提取方法见 `seismotools/checker/runtime/velocity_models/README.md`：取台站和事件中心所在格点的剖面，按到各自固体地表的深度做慢度平均，海上格点在有陆地格点时排除。

**可视化（已实现前四项）：** 震中图、深度直方图、P 走时–震源距图（叠加拟合直线）、Wadati 发震时刻差直方图；待加：东西向和南北向深度剖面、台站残差地图、模型组对比图（每个模型的深度分布与目录深度分布并列）。

## 7. 阶段 5：相对定位（全部待实现）

**目的：** 双差或聚类重定位是否只改善了相对位置，而没有引入整体平移或虚假结构。

**输入：** 绝对定位目录（重定位之前）和重定位后的目录，按 `event_id` 对应；可选 `dt.ct`、`dt.cc`（hypoDD 格式）。

**数值检查：**

| 检查 | 计算 | 预期范围（暂定） |
|---|---|---|
| 重定位比例 | 重定位成功的事件占绝对定位事件的比例 | 报告；< 50 % 时报警 |
| 整体平移 | 重定位前后的质心水平和深度差 | 水平 ≤ 1 km、深度 ≤ 1 km |
| 单事件位移 | 每个事件重定位前后的位移分布；位移大于 5 km 的事件占比 | ≤ 5 % |
| 簇厚度 | 每个事件 20 个最近邻的最小主轴标准差的中位数，前后对比 | 报告；比重定位前薄 5 倍以上时报警（例如 Ridgecrest 第 62 阶段用模板导出的到时做双差，把检测压到模板上，厚度只有 0.05 km） |
| 深度堆积 | 同阶段 4，重定位后再算一次 | 同阶段 4 |
| 差分时数据 | 每个事件对的 dt.cc 数量和相关系数分布；dt.ct 中由模板检测派生的到时占比（若能识别） | 报告 |

**可视化：** 重定位前后并排的震中图和两个方向的深度剖面；位移矢量图；簇厚度直方图。

## 8. 阶段 6：震级（建议增加）

| 检查 | 计算 | 门槛 | 状态 |
|---|---|---|---|
| 震级范围 | 震级中位数；低于 −2 的事件占比 | 中位数在 [−1, 5]，−2 以下 ≤ 5 % | 已实现，**保留报警**（查出 Prague tools 单位错误） |
| b 值 | 最大曲率 + 0.2 作 Mc，Aki–Utsu 公式 | [0.6, 1.6] | 已实现，安全检查 |
| 震级–检测距离 | 由震级和最远检测台站的距离，按局地震级距离衰减经验关系推算"被检测到的最小振幅"，看其是否合理 | 待定 | 待实现（用来补上 Kīlauea min 整体偏 −2.4 那类没被查出的错误） |
| 大震后事件率 | 最大的 3 个事件之后 1 小时的事件数 ÷ 每小时事件数的中位数 | ≥ 0.5 | 已实现，安全检查 |

**可视化：** 频度–震级图（累计和非累计）；震级对最远检测距离的散点图。

## 9. 让 Agent 看图：需要先确认的前提

可视化只有在 Agent 能看图时才有用。正式运行用的是 Claude Code × GLM-5.3：Claude Code 可以读取 PNG 并交给模型，但 GLM-5.3 是否支持图像输入还没有验证。

- 在实现可视化之前，先做一次小测试：让 Agent 读一张 checker 生成的图并描述内容。
- 如果模型不能看图，每张图配的数值摘要就是 Agent 唯一的信息来源；这也是 §1 要求每张图都附数值摘要的原因。

## 10. 检验方法与当前结果

**方法：** `workflows/tools_case_validation/validate_checker.py` 在两类目录上运行 checker：每个案例 human-in-loop 的定位轮次（组件替换所用轮次的拾取、关联和定位结果，应当基本干净，衡量误报），以及每个已完成的正式 Agent 运行（相对 final 的误差已知，见 [`progress/SCORE_TABLE.md`](progress/SCORE_TABLE.md)，衡量检出）。可视化不参与检验，但会对每个目录生成一次，人工检查图是否清楚、样本选得是否有代表性。

**已检验的检查：**

| 阶段 | 保留报警 | 仅报告或作安全检查 | 需校准 |
|---|---|---|---|
| 拾取 | 无拾取台站（Maple tools 8/27、Kīlauea tools 5/25，全部只有垂直分量；Ridgecrest human-in-loop 第一轮 5/42 也是真实问题）、重复拾取（Maple min 11 %） | 无拾取台站日、S/P 比 | — |
| 关联 | 拾取过少的事件（Prague tools 21 %、Maple tools 31 %、Maple min 59 %；human-in-loop 全部 0 %） | 已关联占比、忙碌时段关联、重复事件 | — |
| 绝对定位 | 深度堆积 | Wadati 发震时刻、走时截距 | 台网外、孤立、S−P 深度、台站残差、模型组（检验中） |
| 震级 | 震级范围（Prague tools −2.47） | b 值、大震后事件率 | — |

**主要结论：** 质量类检查能可靠区分。时间和深度的物理一致性检查测得准，但被结构偏差盖住：相对 human-in-loop 的差值能反映真实误差，绝对值在干净目录上也会报警。速度模型造成的整体偏差只靠 Agent 自己的数据无法可靠判定，这是 checker 的边界，也是 S3 中知识部分（速度模型的选择方法）要解决的问题；checker 能提供的是"对模型有多敏感"的测量。

**循环性：** 检查规则和门槛都是在这六个案例上总结和校准的。报告 S2c、S3 结果时，按"规则来源于该案例 / 不来源于该案例"分开统计（[`00_Research_Plan.md`](00_Research_Plan.md) §2.5），并在冻结前固定所有门槛。

## 11. 在实验中的用法

- **S2c（工具 + checker）：** checker skill 说明工具存在、每个阶段测什么、怎么运行、图在哪里，以及输出里必须包含最终报告和每个报警的处置记录（已修复并说明改了什么，或说明不修的理由）。不提供原因或修复方法。
- **S3（工具 + 知识 + checker）：** 另有知识 skill，包括"症状 → 可能原因 → 上游修复"的手册和速度模型的选择方法。
- **评分：** 对提交的文件重新运行 checker 核对报告；统计每个阶段的运行次数、报警数、已修复、给出理由、未处理（从运行记录统计）。

## 12. 实施顺序

1. 完成模型组检查的检验，决定报警还是仅报告；把已实现的分阶段代码（拾取、关联）合并回 seismotools，并把现有检查按本文的阶段重新归类。
2. 测试 GLM-5.3 能否读图（§9）。
3. 实现阶段 1（数据与预处理）和阶段 2 的可视化及拾取–初动偏差、拾取信噪比。
4. 实现阶段 5（相对定位）和阶段 6 的震级–检测距离检查；补阶段 3、4 的可视化。
5. 对新检查做同样的检验，确定门槛；用合成数据写回归测试。
6. 编写给 Agent 看的 README 和 skill，冻结 checker（记录提交号）。
