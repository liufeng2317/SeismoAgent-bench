# Checker 设计文档

状态（2026-11-05）：现行为 1.3（标签 `checker-v1.3`，与知识 skill 一起冻结），在 1.2 之上加了 Wadati 偏差的判定和区域接口；B 层后端运行用的是 1.0，统一测试试水用的是 1.2，下一轮统一测试用 1.3（§13）。本文写给研究者，只写 checker 现在是什么、为什么这样设计、得到了哪些经验；每一轮检验的方法、数据和读数记在 [`progress/checker_validation/`](progress/checker_validation/README.md)。给 Agent 看的工具说明是 `seismo_checker/README.md`，只说测什么和怎么用，不出现原因、修复方法或案例数据。研究设计见 [`00_B_Research_Plan_Checker.md`](00_B_Research_Plan_Checker.md) §3–§4（阶段划分见 [`00_A_Research_Plan_Benchmark.md`](00_A_Research_Plan_Benchmark.md) §3）；经验来源见 [`progress/expert_experience_evidence.md`](progress/expert_experience_evidence.md) §2。

## 1. 定位与原则

checker 是 seismotools 里的一个确定性命令行工具，在 S2c（工具 + checker）和 S3（工具 + 知识 + checker）中提供给 Agent。它回答：**只看 Agent 自己的数据和产物，当前这一步有哪些可测量的异常？**

| 原则 | 含义 |
|---|---|
| 不依赖参考目录 | 只读 Agent 的输入数据和它自己的产物；不读任何参考目录或 human-in-loop 结果 |
| 不针对具体案例 | 规则、门槛和图的画法对六个案例完全相同；代码、注释和给 Agent 的说明里不出现案例名 |
| 只报告症状 | 数值检查只说"测到了什么、偏离预期多少"；图只展示数据和产物。不说原因、不给修复方法；原因和排查方法放在知识 skill 里（S3） |
| 分阶段、随时可用 | 每个处理阶段都有对应的检查，Agent 可以在任一阶段之后运行，以便在上游及时纠错；何时运行由 Agent 决定 |
| 确定性 | 同样的输入得到同样的报告和图；代表性样本按固定规则选取 |
| 只保留可靠的报警 | 一项检查只有在干净目录上基本不报警、在有已知错误的目录上能报警时才判定；否则只报告数值，并写明为什么不判定 |
| 不是选择标准 | 检查和测量值说明产物有没有症状，不用来在模型或参数之间挑选；离线检验中按任何单一测量值挑速度模型都会选错（§11 第 3 条） |
| 参考计算只作对照 | checker 自带的通用速度模型和 IASPEI 标准震级复算，只用来显示结果对模型的敏感程度、震级代码有没有单位或响应错误，不是推荐的定位模型或震级公式 |

**输出：**
- **数值检查**：分三类写进 `checker_report.json`。`flags`（报警）是 Agent 产物超出预期范围，写一句症状，提交时每个报警都要有处置记录；`input_notes`（输入说明）是输入数据本身的性质超出常见范围（台站缺数据、数据缺口、采样率不一致等），只说明数据允许做到什么，Agent 改变不了，不要求处置；`measurements`（测量值）是测得准、但单独不能说明目录对错的量，只给数值和"为什么不判定"的通用说明，不给预期范围，以免 Agent 把它们当成问题去修。
- **可视化**：代表性波形、拾取叠加、剖面图等，写成 PNG，供 Agent 自己查看和判断。它们不报警，但每张图都配有一段数值摘要写进报告，因为模型看图要经过另一个视觉模型转述（§9）。
- **范围**：每项检查标有 `scope`：`item`（逐个拾取、事件、台站的性质，小批量上就能判断）或 `population`（整个目录的分布，例如堆积、分层、孤立事件、b 值，只在全量上判断）。`run.py --pilot` 在小批量上只报告 `population` 检查的数值、不判定。

## 2. 阶段总览

| 阶段 | 命令 | 需要的输入 | 判定的检查 | 只报告或输入说明 | 可视化 |
|---|---|---|---|---|---|
| 1. 数据与预处理 | `--stage data` | StationXML、波形目录；可选 `--processed-waveforms` | 预处理时移 | 有数据的台站、每日台站数、台网几何、分量与采样率、数据缺口（输入说明） | 台站分布、数据可用性矩阵、代表时窗预处理前后对比与频谱 |
| 2. 震相拾取 | `--stage picks` | 拾取文件；可选波形目录 | 无拾取台站、无拾取台站日、重复拾取、S/P 比、P 拾取–初动偏差 | S 拾取–初动偏差；低信噪比拾取比例（细节） | 代表时窗叠加拾取、单台站拾取对齐图 |
| 3. 震相关联 | `--stage association` | 拾取文件 + 事件表（可以还没有位置） | 已关联占比、忙碌时段关联、拾取过少的事件、重复事件 | 共用拾取的事件对（细节） | 每小时拾取数、事件数和关联占比；代表事件的走时剖面 |
| 4. 绝对定位 | `--stage location` | 已定位的目录 + 拾取 | 孤立事件、Wadati 发震时刻离散和偏差、深度堆积（单一值、边缘）、深度分层条带、S−P 深度 | 台站覆盖外的事件、走时截距、台站残差、深度约束、堆积与定位设置、台站延迟、模型组 | 震中图、深度直方图、走时–距离图、Wadati 图、剖面、台站残差地图、模型组对比 |
| 5. 相对定位 | `--stage relocation` | 重定位目录 + 重定位前目录；可选 `--dtcc` | 整体平移、大位移、局部变薄 | 发生移动的比例；dt.cc 统计 | 前后对比的震中图和剖面、位移矢量、位移和深度变化直方图 |
| 6. 震级 | `--stage magnitude` | 有震级的目录 + 拾取；可选波形和 StationXML | 震级范围、震级–检测距离、震级复算、大事件震级 | b-positive（细节含标准 b 值） | 频度–震级图、震级对最远检测距离 |

`--stage all` 运行给定输入允许的全部检查。每个阶段同时运行它之前各阶段中用已有输入就能做的检查；两个耗时的部分只在各自阶段运行：代表时窗扫描只在 data（和 all）；模型组默认关闭，只在 location（或 all）阶段加 `--model-ensemble` 时运行（每个目录 10–45 分钟，只报告）。提交时，输出约定要求附上对最终目录运行全部阶段的报告和每个报警的处置记录。模板匹配新增的事件进入第 3–4 阶段的检查；专门针对模板检测的检查评估后没有加（§13）。

配套工具（都在 `seismo_checker/interface/`）：

| 工具 | 用途 |
|---|---|
| `run.py` | 按阶段运行检查，写报告和图；`--pilot`（小批量）、`--location-setup`（声明的定位设置，供堆积诊断）、`--model-ensemble` |
| `compare.py` | 两份同阶段、同输入的报告按预先固定的规则比较，结论为更好、更差、矛盾、不确定、无差别；`--change` 说明改动类型，不能比较该类改动的检查列出但不计入（换速度模型时的分层条带）。结论只说明检查偏向哪个产品，不说明哪个对 |
| `pilot.py` | 选小批量：`events`（已有目录）或 `windows`（还没有目录）；每个小批量分代表性（60 %）、最繁忙时段（20 %）、最大事件（20 %）三部分，只有代表性部分代表全目录 |
| `region.py` | 台站覆盖（台站凸包外扩 10 km）和用户给定的区域；输出 `region.json` 和每个事件的归属，不删事件，由 Agent 决定并说明过滤规则 |

## 3. 阶段 1：数据与预处理

**目的：** 在拾取之前确认用了哪些台站、数据是否完整、分量是否齐全、预处理是否合理。

**输入约定：** `--waveforms` 指向 `NET.STA.LOC.CHA__start__end.mseed` 命名的波形目录。目录或其上一级有 `waveform_inventory.json`（基准任务的输入都有）时，覆盖率、缺口和采样率直接从中读取；没有时 checker 自己读 MiniSEED 头信息。`--processed-waveforms` 指向 Agent 预处理后的记录，命名规则相同，只需包含 checker 选中时窗所在的台站日（报告的 `processed_files_needed` 列出这些文件）。很多工具（例如 PhaseNet）在内部做预处理，Agent 可以只用这个选项检查自己显式做的预处理。

| 检查 | 计算 | 门槛 | 类别 | 依据 |
|---|---|---|---|---|
| `stations_with_data` | 有元数据的台站中有波形的占比；列出有元数据无数据、有数据无元数据的台站 | 有数据无元数据时写说明 | 输入说明 | 描述输入 |
| `daily_station_count` | 每天有数据的台站数 | 某天低于中位数一半 | 输入说明 | 描述输入 |
| `network_geometry` | 孔径、最近台站间距中位数、以台网中心为准的最大方位空隙 | — | 输入说明 | 描述输入 |
| `channel_sample_rates` | 分量类型（ZNE、Z12、只有垂直）、仪器类型、采样率是否一致、方位角缺失或偏离、缺少响应的通道 | 同一台站采样率不一致 | 输入说明 | 描述输入 |
| `data_gaps` | 通道日覆盖率低于 90 % 的占比 | ≤ 5 % | 输入说明 | 六个案例只有 Maple 的输入超出（8.6 %） |
| `processing_time_shift` | 预处理后记录与同一记录零相位 2–20 Hz 滤波结果的互相关时移，代表记录的中位数 | \|中位数\| ≤ 2 个采样点（至少 0.02 s） | 判定 | 合成数据上 0.3 s 时移查出；门槛按文献（零相位处理不应产生时移） |

**代表时窗（固定规则）：** 每个台站垂直分量取每秒一阶差分的峰值，除以该台站全时段的中位峰值；某 20 s 区间内比值超过 8 的台站数最多（相邻两个区间合并以覆盖台网内的走时差）、彼此相隔至少 1 h 的 4 个区间即为代表时窗，大概率是地震。每个时窗取比值最高的 6 个台站，从最早的能量起始前 8 s 开始画 40 s。

**可视化：** `data_stations.png`（台站按分量和仪器类型着色，标出台网中心和 30° 方位扇区）；`data_availability.png`（台站 × 日覆盖率）；`data_window_N.png`（原始记录、预处理后记录、垂直分量的信号和噪声频谱）。

## 4. 阶段 2：震相拾取

**目的：** 拾取方法和参数是否合适：台站是否都用上、拾取是否准、有没有系统偏差。

| 检查 | 计算 | 门槛 | 类别 | 依据 |
|---|---|---|---|---|
| `silent_stations` | 有波形的台站中没有任何拾取的占比；列出其中只有垂直分量的台站 | ≤ 10 % | 判定 | Maple tools 30 %、Kīlauea tools 20 %（只有垂直分量的台站）报警；human-in-loop ≤ 8.5 % |
| `station_day_gaps` | 在其他日子有拾取的台站，有数据却无拾取的台站日占比 | ≤ 5 % | 判定（安全检查） | 各目录 ≤ 0.6 % |
| `duplicate_picks` | 同台站同震相、间隔 ≤ 0.3 s 的拾取占比 | ≤ 2 % | 判定 | Maple min 11 % |
| `s_to_p_ratio` | S 拾取数 / P 拾取数；列出有 P 无 S 的台站 | 0.3–1.5 | 判定 | 读数 0.62–1.14；上限按文献（抓 S 拾在噪声上） |
| `pick_onset_offset` | 固定抽样（40 个台站日，每个最多 10 个拾取）；2–20 Hz 零相位滤波记录上用 AIC 找初动（P 用垂直分量，S 用信噪比高的水平分量、从 P 之后找），只统计初动信噪比 ≥ 3 的拾取；细节含拾取前后振幅比 < 2 的拾取比例 | P：\|中位数\| ≤ 0.2 s；S 只报告 | 判定（P） | 干净拾取 0.01–0.11 s；整体早 2.5 s 的合成偏差测得 −2.46 s。S 只报告：AIC 在 P 尾波里找 S 初动不可靠 |

零相位滤波会让 AIC 初动略早，所以干净拾取的 P 偏差约 +0.05 s，门槛按此留出余量。拾取–初动偏差针对的是 Prague min 那类错误（PhaseNet 的 blinding 长度换算错误使所有拾取整体早 2.5 s），对照波形就能看出来，不需要参考目录。

**可视化：** `picks_window_N.png`（3 个最密集和 2 个稀疏时窗，最先拾取的 8 个台站，P 红线、S 蓝线，实线已关联、虚线未关联）；`picks_station_stacks.png`（拾取最多的 4 个台站各取最多 40 个 P 拾取，按拾取时刻对齐叠放，显示 ±4 s，初动应当排在 0 处）。

## 5. 阶段 3：震相关联

**目的：** 关联是否把拾取正确地组成了事件：有没有漏关联、拆分或合并。

| 检查 | 计算 | 门槛 | 类别 | 依据 |
|---|---|---|---|---|
| `associated_share` | 有事件编号的拾取占全部拾取的比例 | ≥ 10 % | 判定（只抓极端） | 发表研究有 12–19 %；很多 Agent 只提交已关联拾取 |
| `association_busy_hours` | 拾取最多的 10 % 小时里的关联占比 ÷ 全部时段的关联占比 | ≥ 0.5 | 判定（安全检查） | 从未触发 |
| `events_with_few_picks` | P 拾取少于 4 个的事件占比 | ≤ 20 % | 判定 | Prague tools 21 %、Maple tools 31 %、Maple min 59 %；human-in-loop 0 %。衡量约束程度，不是定位对错 |
| `duplicate_events` | 1.5 s（有位置时加 3 km）以内另有事件的事件占比；细节给出共用 ≥ 2 个拾取的事件对数 | ≤ 2 % | 判定（安全检查） | 共用拾取只在 Maple min 出现（100 对，已知的重复录入），用来区分重复录入与真实双震 |

**可视化：** `association_rates.png`（每小时拾取数、事件数和关联占比，标出最大的 3 个事件）；`association_events.png`（拾取最多、最少和最忙时段各 2 个事件的走时剖面，P、S 和同时段未关联拾取分色）。数值摘要给出每个事件的 P 视速度和残差：Kīlauea tools 最忙时段两个相隔 14 s 的事件残差 0.6–0.7 s、P 视速度 84 km/s，拾取被混在一起。这类混合错误在整个目录的统计上分辨不出，所以只通过图和摘要提供。

## 6. 阶段 4：绝对定位

**目的：** 位置和发震时刻是否合理、对速度模型有多敏感。

| 检查 | 计算 | 门槛 | 类别 | 依据 |
|---|---|---|---|---|
| `isolated_events` | 最近邻距离超过 max(2 km, 5 倍中位最近邻距离) 的事件占比 | ≤ 10 % | 判定（population） | human-in-loop ≤ 9 %；Ridgecrest min 12 % 对应"偏离构造"不通过 |
| `events_beyond_stations` | 台站凸包外超过 10 km 的定位事件占比（`region.py` 同一算法） | — | 只报告 | 这类事件几乎都不属于所研究的序列；但局部台网之外可以有真实地震（Kīlauea 最终目录 25 %） |
| `wadati_origin_spread` | 每个事件拟合 (tS − tP) = a(tP − t0) + b，数据隐含的发震时刻与目录发震时刻之差的离散（MAD） | ≤ 0.5 s | 判定 | 干净目录 ≤ 0.46 s；Kīlauea min 0.67、Maple min 0.63、Kaikōura min 1.78、tools 0.52，都对应发震时刻不通过 |
| `wadati_origin_offset` | 同上，差值的中位数；细节含数据 Vp/Vs | \|中位数\| ≤ 1.5 s | 判定（1.3） | 结构使正确目录也偏离：human-in-loop −0.89 至 +0.82 s；1.5 s 只抓严重的整体时间错误（试水运行自拟的过慢模型 +2.47 s）。只用拾取的 S−P 时间，台站延迟吸收不了它 |
| `travel_time_intercept` | 近距离 P 走时对震源距的加权直线拟合，零距离截距 | — | 只报告 | 干净目录也有 0.7–1.0 s |
| `depth_single_value`、`depth_at_edges` | 同一深度值（0.01 km）的最大占比；落在最浅或最深深度值上的占比 | 各 ≤ 5 % | 判定（population） | 查出的都是真实问题（台阶界面、网格或搜索区顶部、固定深度）；"深度堆积"不通过的运行全部查出 |
| `depth_layers` | 0.1 km 薄层中事件数 ≥ 10、超过 ±1 km 内中位数 3 倍且超过 4 个泊松标准差的部分占全部事件的比例（不含最浅、最深 0.2 km） | ≤ 5 % | 判定（population） | human-in-loop 0–2.7 %；Kīlauea min 93 %、Maple min 52 %。正确的台阶模型在界面上也会形成条带，不能用来比较模型（`compare.py` 换模型时不计） |
| `sp_depth_offset` | 远台定 S−P 与距离的比例 K，近台由 K·(S−P) 反推深度，与目录深度（海平面以下）之差的中位数 | 1.5 km | 判定 | human-in-loop 最大 1.08 km；超过门槛的两个运行（Magna tools 2.03、Ridgecrest min 1.70）方向都对；门槛以下方向常常相反，所以只报大小 |
| `station_residual_outliers`、`station_residual_azimuth` | 相对走时直线的每台站中位残差；残差随方位的正弦拟合振幅 | — | 只报告 | 三维结构使正确的区域目录也有大台站项（Kaikōura 18 个台站超过 0.5 s） |
| `depth_constraint` | 每个事件的台站几何（方位空隙、二次空隙、最近台站）、1.4 倍深度内有无 S 拾取、最常见深度上事件的组成 | — | 只报告（归因） | 描述数据能约束什么；无约束事件的堆积指向定位设置，整数深度指向固定或试探深度 |
| `pile_against_setup` | 配合 `--location-setup`：最常见深度到声明的界面、搜索边界、网格节点、试探深度的距离 | — | 只报告（归因） | 例如 Prague 台阶模型的堆积显示为"距界面 0.22 km、在网格节点上" |
| `station_delays` | 每台 P、S 中位残差及其比值 δS/δP（时钟型约 1，路径型约 Vp/Vs） | — | 只报告（归因） | human-in-loop 目录也有 0–5 个时钟型台站 |
| `model_ensemble_depth`、`model_ensemble_time` | 默认关闭。100 个记录最好的事件用 6 个通用模型重新定位，报告目录相对整组解的位置和各模型间的离散 | — | 只报告 | 通用模型间深度差 3–19 km、时间差 0.25–1.3 s，大于大多数真实误差；作为对模型敏感程度的信息 |

通用模型的来源和区域提取方法见 `seismo_checker/runtime/velocity_models/README.md`：取台站和事件中心所在格点的剖面，按到各自固体地表的深度做慢度平均。

**可视化：** `checker_diagnostics.png`（震中图、深度直方图、P 走时–震源距图、Wadati 发震时刻差直方图）；`location_sections.png`（东西和南北深度剖面、台站中位 P 残差地图）；`location_model_ensemble.png`（开启模型组时）。

## 7. 阶段 5：相对定位

**目的：** 双差或聚类重定位是否只改善了相对位置，而没有引入整体平移或虚假结构。

**输入：** 重定位后的目录（`--catalog`）和重定位之前的绝对定位目录（`--catalog-before`），按 `event_id` 对应；可选 `--dtcc`（hypoDD 格式 dt.cc，报告事件对数、每对观测数和相关系数分位数）。重定位阶段同时对重定位后的目录运行阶段 2–4 的检查。

| 检查 | 计算 | 门槛 | 类别 | 依据 |
|---|---|---|---|---|
| `relocation_shift` | 移动事件东、北、深度位移的中位数 | 水平和深度各 ≤ max(1.5 km, 重定位前报告的中位不确定度) | 判定 | 合成整体加深 2 km 查出；Kīlauea 重定位输入误当输出（深度基准不一致，整体 1.07 km）查出；Magna 采纳的双差 0.87 km 不报警 |
| `relocation_large_moves` | 位移超过 5 km 的移动事件占比 | ≤ 5 % | 判定 | Magna 双差 2.7 % |
| `relocation_thinning` | 每个事件 20 个最近邻最小主轴标准差的中位数，前 ÷ 后 | ≤ 5 | 判定（population） | 合成"压到 4 个点"（模仿模板到时做双差）查出 |
| `relocated_share` | 位置有变化的事件占重定位前已定位、且拾取 ≥ 8 个事件的比例 | — | 只报告（1.2） | 小事件常无法连接；它曾诱导 Agent 放宽连接门槛、使目录离散（§11 第 4 条） |

hypoDD 和 GrowClust 都不读台站高程，所有台站在模型深度 0：目录深度以海平面为基准、台站在其上 1–3 km 时，要先把深度和模型换算到台站高程再换回（工具 README 和知识 skill 已写明；合成检验见 [`06`](progress/checker_validation/06_trial_and_tool_fixes.md)）。

**可视化：** `relocation_comparison.png`（前后并排的震中图和两个方向的剖面、位移矢量、位移和深度变化直方图）。

## 8. 阶段 6：震级

| 检查 | 计算 | 门槛 | 类别 | 依据 |
|---|---|---|---|---|
| `magnitude_range` | 震级中位数；低于 −2 的事件占比 | 中位数在 [−1, 5]，−2 以下 ≤ 5 % | 判定 | 查出 Prague tools 单位错误 |
| `magnitude_detection` | 由震级和最远检测台站的震源距，按 Hutton & Boore (1987) 的距离项反推该台站处的 Wood-Anderson 振幅，对较小的一半事件取中位 log A（mm） | [−2.3, 0.5] | 判定 | 干净 human-in-loop −1.7 至 −0.2；Kīlauea min −2.55、Prague tools −4.52 查出；Magna +0.67 查不出。没有波形或响应时的备用 |
| `magnitude_recompute` | 按拾取数均匀抽 20 个事件，去响应到位移，IASPEI 标准 WA 响应（静态放大 1），水平分量半峰峰值（nm），IASPEI 标准式；报告"目录 − 复算"的中位数；细节含台站项、偏差随距离的趋势、台站 ML 离散、目录对复算的斜率 | \|中位数\| ≤ 0.5 | 判定 | 最可靠的震级检查：Prague tools −2.60、Kīlauea min −2.29（mm 配 nm 常数）、Ridgecrest tools −1.18（单零点 WA 响应用在位移上）；区域标定差异（+0.2 左右）正确地不报。常数偏移指向单位或常数，随距离变化指向响应或距离校正 |
| `largest_events_magnitude` | 拾取台站最多和震级最大的各 5 个事件，长窗口（S 后 max(30 s, 4 (S−P))）、剔除削波记录复算 | \|中位数\| ≤ 0.5，没有震级的事件 ≤ 1 | 判定 | Prague tools −2.63、Ridgecrest tools −0.94（M7.1 记为 5.3）、Kīlauea tools 两个最大事件没有震级。ML 在 6 级以上饱和，真实大震需要矩震级 |
| `b_positive` | 相邻事件的正震级差（δ = 0.2）估计 b；细节含标准 b 值（最大曲率 + 0.2 作 Mc）及其完备性 | — | 只报告（population） | 标准 b 值在大震序列早期因不完备偏低（human-in-loop：Ridgecrest 0.49、Kīlauea 0.60）；Ridgecrest 两个运行标准 b 0.55、b-positive 0.98 和 1.20。两者一起读 |

**可视化：** `magnitude_distribution.png`（频度–震级图；震级对最远检测台站震源距的散点图，叠加 log A = −2.3、−1、0.5 mm 的等振幅曲线）。

## 9. 让 Agent 看图

正式运行用的是 Claude Code × GLM-5.3。GLM-5.3 自己看不到图：用 Read 打开 PNG 时，它调用 Z.ai 服务端的 `analyze_image`，由另一个视觉模型返回文字描述（2026-10-30 测试）。两次测试都判断正确，包括一张拾取整体提前 2.5 s 的对齐图和一张正常的对齐图（问题保持中性）。前提是图的范围能容纳问题：对齐图最初只显示 ±2 s，2.5 s 的偏移使初动落在图外，已改为 ±4 s。

## 10. 有效性与边界

**检验方法。** 在两类目录上运行 checker：每个案例 human-in-loop 的定位轮次（应当基本干净，衡量误报）和已完成的正式 Agent 运行（相对最终目录的误差已知，衡量检出）；合成回归测试（`seismo_checker/examples/smoke/run.sh`，14 个场景，每个阶段的干净输入不报警、每种植入错误由预期的检查报警，约 5 分钟）；离线重放（同一批拾取只换一个因素，判断 checker 和 `compare.py` 的结论是否正确）。各轮检验见 [`progress/checker_validation/`](progress/checker_validation/README.md)。

**能可靠查出的（A 层：错误有结构，数据冗余足以判断）：**
- 震级的单位、常数和仪器响应错误（复算、范围、检测距离、大事件震级）；
- 定位设置造成的深度堆积（网格或搜索区顶部、固定或试探深度、台阶界面）和分层条带；
- 拾取的整体时移、重复拾取、没有用上的台站，关联中拾取过少的事件；
- 发震时刻的离散（Wadati 离散）和严重的整体时间错误（Wadati 偏差超过 1.5 s）；
- 相对定位的整体平移、过度收缩和大位移。

**部分能查出的（B 层：需要对照实验区分原因）：** 深度整体偏差（S−P 深度在超过 1.5 km 时方向可靠，门槛以下不可靠）；分层条带既可能是模型错，也可能是正确台阶模型的界面；孤立事件。

**看不到的（C 层：所有台站或事件共有的误差，被发震时刻、台站校正、震级常数吸收）：** 速度模型整体偏快或偏慢、近地表和基准面造成的发震时刻与深度整体偏差（0.3–1.5 s 量级）；震级定标的绝对水平（0.1–0.4 级）；主震尾波中的漏检；模板匹配门槛过高造成的漏检。这些留给知识 skill 的"checker 看不到的问题"和不确定度报告。

**对可信标准的覆盖（第一轮正式运行和 B 层运行）：** 深度堆积全部查出；震级实现错误全部查出，区域定标差异查不出；发震时刻离散查出，整体偏差只查出严重的；深度偏差部分查出；水平偏移、水平离散、偏离构造基本查不出；大事件漏检查不出，大事件震级偏低查出。

**只报告的项目和原因（给 Agent 看的是通用说明）：** 走时截距、台站残差和方位项（结构使正确目录也偏离）；台站覆盖外的事件（局部台网之外可以有真实地震）；模型组（通用模型之间差得比误差还大）；深度约束、堆积与定位设置、台站延迟（归因信息）；发生移动的比例（会诱导放宽连接）；b-positive（与标准 b 一起读）；S 拾取–初动偏差（AIC 在 P 尾波中不可靠）。

**1.2 删去或合并的检查：**

| 检查 | 删去原因 |
|---|---|
| `pick_snr` | 干净目录也有 30–64 % 低信噪比拾取；比例移入 `pick_onset_offset` 的细节 |
| `event_travel_time_fit` | human-in-loop 1.4–18 %、Agent 运行 0.7–8.6 %，分不开 |
| `events_outside_network` | Kīlauea human-in-loop 28 % 是真实事件；1.3 由按台站凸包计算的 `events_beyond_stations` 代替 |
| `azimuthal_gap` | 几何信息并入 `depth_constraint` |
| `station_time_steps`、`wadati_events` | human-in-loop 目录也有 1.5 s 台阶、0.5–51 % 的异常事件，分不开 |
| `day_night_ratio` | 需要 ≥ 14 天，基准任务最长 8 天 |
| `rate_after_largest` | 从未报警，数值无意义 |
| `b_value` | 并入 `b_positive` 的细节（final 自己低于原门槛） |

**循环性：** 检查规则和门槛都是在这六个案例上总结和校准的（例如 Wadati 偏差的 1.5 s 门槛来自试水运行）。报告 S2c、S3 结果时，按"规则来源于该案例 / 不来源于该案例"分开统计（[`00_B_Research_Plan_Checker.md`](00_B_Research_Plan_Checker.md) §4），并用不参与校准的保留案例检验门槛。

## 11. 主要经验

1. **checker 稳定挡住了 A 层错误，但起作用的常是工具里正确的参考计算。** B 层中不带 checker 的变体 6 个案例有 3 个犯了震级响应或单位错误，带 checker 的两个变体 12 次运行 0 次；Agent 照用了 checker 的复算代码或知识资源里的参考实现，而不是被报警纠正（[`04`](progress/checker_validation/04_tier_b_backend.md)）。正确的参考实现本身就是有效的知识载体。
2. **时间和深度偏差主要来自速度模型的近地表和基准面，这是 checker 的边界。** 单因素重定位复现了 B 层运行的主要偏差：模型顶面放在海平面（Kīlauea −0.37 s）、采用通用模型（Magna +0.35 s）、近地表太快的已发表模型（Maple +1.27 s）。不给区域模型时，数据只给方向不给水平：表层越慢越厚，Wadati 偏差越正，相关 −0.87 至 −1.00，但正确模型处的值因案例而异；三个案例里任何低速表层都修不好（[`05`](progress/checker_validation/05_near_surface_magnitude_matching.md)）。
3. **检查和测量值不是选择标准。** 按最小的 Wadati 偏差、RMS、最浅深度比例、截距或 S−P 深度偏差挑速度模型，每一种都至少在一个案例上选错；B 层 Kaikōura 的 Agent 正是按 S−P 深度、截距和 Wadati 在通用模型中选了 iasp91，深度偏 +3.0 km（[`04`](progress/checker_validation/04_tier_b_backend.md)、[`05`](progress/checker_validation/05_near_surface_magnitude_matching.md)）。README 和知识 skill 都写明了这一点。
4. **报警会诱导表面修复。** B 层有 4 次报警驱动的改动使结果变差：深度分层报警后台阶改梯度；S−P 深度报警后去掉台站校正、改 Vp/Vs；为提高移动比例放宽连接；`compare.py` 选中离散更大的参数。试水中，Agent 把正确的 S−P 深度报警解释为"拾取提前 1.7 s"，用同号的台站延迟吸收（[`06`](progress/checker_validation/06_trial_and_tool_fixes.md)）。对策是症状手册写明哪些改动不该做，并把只会诱导修改的检查降为只报告。
5. **处置完整不等于处置正确。** 评分端的核对只能查每个报警有没有处置、`fixed` 是否属实、`justified` 有没有证据，判断不了理由是否成立；后者靠评分和决策审计。审计时要先确认偏差出在哪一步（Kaikōura 的例子一开始被归错，[`04`](progress/checker_validation/04_tier_b_backend.md)）。
6. **小批量预测移动，不预测采纳结论。** 代表性小批量能推出目录会怎样移动（深度差 ≤ 0.3 km），但堆积、分层只在全量的弱事件里形成，比较结论推不到全量；记录最好的事件连移动方向都会反（[`02`](progress/checker_validation/02_replay_compare_pilot.md)）。由此有了 `scope` 和"小批量验证、全量判定"的协议。
7. **定位程序的深度基准约定是隐蔽的系统误差源，修工具比教 Agent 可靠。** HypoInverse CRH 模型忽略台站高程（Maple 时间偏差 +0.56 s，CRE 后 −0.08 s）；NonLinLoc 接口的深度搜索默认从参考高程开始，浅部事件被压在搜索顶面；hypoDD 和 GrowClust 把所有台站放在模型深度 0（合成数据上相对误差大 5 倍）。前两项改了接口默认值，第三项写进文档（[`06`](progress/checker_validation/06_trial_and_tool_fixes.md)）。
8. **checker 单独使用不如和知识结合。** 试水中，只有 checker 的 Agent 没取到已发表模型的数值，自拟了一个过慢的模型，结果最差（4 项不通过）；有知识的 Agent 从原图数字化同一模型、查明基准面，只剩 1 项（[`06`](progress/checker_validation/06_trial_and_tool_fixes.md)）。后续主实验用 checker + 知识，checker 单独版本只在需要消融时跑。
9. **震级压缩来自测量方式和定标。** 只保留信噪比高的记录使小事件偏大 0.1–0.25、斜率陡 0.01–0.17；密集序列中的长窗也会压缩；剩下 0.04–0.12 是定标（C 层）。复算斜率不能升级为判定：标准复算本身也有压缩，而且 Agent 常直接沿用复算代码（[`05`](progress/checker_validation/05_near_surface_magnitude_matching.md)）。
10. **评分口径本身也要检验。** 区域外事件比例把台网内真实的区域地震算作错误（提示词不写区域），改为按台站覆盖判定；震级斜率从 12 对算出也被判不通过，改为至少 30 对（[`07`](progress/checker_validation/07_scoring_questions.md)）。
11. **运行有效性要靠基础设施保证。** Agent 曾向共享评测环境装包，改为只能装进运行目录下的虚拟环境，并记录运行前后的环境指纹；Agent 多按 URL 而不是 DOI 访问文献，泄漏扫描分为扣留产品（命中即排除）和待审访问（人工核对）两层。
12. **从数据建模型是可用的方法，但会失效，且失效时数据不报警。** 不给区域模型时，整列缩放加台站校正、按残差选，在 Kīlauea、Kaikōura、Maple、Prague 改善了时间或深度，在 Ridgecrest 没变化，在 Magna 使深度偏深 1.9–6.6 km；台站校正和深度一起漂移，阻尼不能阻止。唯一的无参考警示是残差最小值落在合理速度范围之外（只见于 Magna），样本太少，不能作为检查；写进知识 skill，作为带保护条件的建模方法，并要求报告残差附近各模型的深度范围（[`08`](progress/checker_validation/08_velocity_from_data.md)）。
13. **水平偏移来自台站延迟和最终目录的框架，不来自前端。** 逐项替换显示，换成专家拾取最多改变 0.26 km、限定台站组合不到 0.04 km；Kaikōura、Maple 加上台站延迟后偏移从 1.5–3.0 km 降到 0.2–0.5 km；Magna、Ridgecrest 的最终目录框架来自双差重定位，单靠绝对定位复现不了（差 2.3、0.85 km）。整批平移在没有参考时看不出来，所以只写进知识，不加检查（[`09`](progress/checker_validation/09_horizontal_shift.md)）。
14. **检测差距主要是没有用模板匹配，不是门槛。** 去掉模板匹配，最终目录只剩 8–56 % 的事件、归一化召回 0.72–0.98（有模板匹配时 0.99–1.85）；六个 tools 运行中五个没把模板匹配检测加进目录（Ridgecrest 跑了全量只作核对）。零假设检验在六个案例上都给出 9.5；门槛从 9.5 提到 10 代价很小，提到 16.3 丢掉 36–79 % 的事件。漏检在产品里看不出，只写进知识（[`10`](progress/checker_validation/10_template_threshold.md)）。

## 12. 在实验中的用法

- **S2c（工具 + checker）：** checker skill（`data/agent_resource/skills/catalog-checker/SKILL.md`）说明工具存在、每个阶段测什么、何时运行，以及合同：提交 `work/checker/final/checker_report.json`（在提交的目录上运行）和 `work/checker/dispositions.json`（每个报警一条 `fixed`：改了什么、报警出现在哪份报告；或 `justified`：证据）。工具说明在 `seismo_checker/README.md`，包括 `compare.py`、`pilot.py`、`region.py`；不提供原因或修复方法。合同文件为各案例的 `output_contract_checker.json`（后端变体在 `tasks/<case>/backend/`）。
- **S3（工具 + 知识 + checker）：** 另有知识 skill（`data/agent_resource/skills/catalog-knowledge/`）：小批量协议、两个候选间的决定与对照实验、按 A/B/C 三层的症状手册、checker 看不到的问题（速度模型的基准面、常速层与梯度、不用区域模型时如何约束近地表、定位程序的深度基准；震级定标和压缩；主震尾波），以及震级资源（`data/agent_resource/magnitude/`）。所有案例都不提供具体速度模型（2026-11-03 决定）。
- **消融：** 只做 checker 对比 checker + 知识，且只在需要回答具体问题时、用能回答问题的最少运行；B 层已有的 `backend` 和 `backend_checker` 运行作为基线复用。
- **评分：** `SeismoAgentBench/scoring/catalog_metrics/checker_audit.py` 用运行时的 checker 版本在提交的文件上重跑，核对报告是否针对提交文件（SHA-256）、报警是否一致、每个报警有无处置、`fixed` 是否属实、`justified` 有无证据，并统计 Agent 运行 checker 的次数；处置记录的列表和以 `flag_id` 为键的对象两种写法都能读（`03_Scoring_Method.md` §2.7a）。
- **迭代：** A 层离线重放（`workflows/development/replay/`），B 层后端任务（`workflows/development/backend_tier_b/`），C 层完整正式运行。改动后只做冒烟测试和离线检验，攒到一起再统一跑 Agent。
