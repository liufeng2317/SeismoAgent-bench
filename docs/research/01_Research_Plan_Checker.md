# 研究计划 B：把地震学知识和工具引入通用 Agent 的 checker（seismo checker）

**定位：** 主线工作，论文大纲见 [`paper/01_Outline.md`](../../paper/01_Outline.md)。如果效果不足以单独成文，退回 [研究计划 A：基准](./00_Research_Plan_Benchmark.md)。本计划要深度：在现有案例上把方法做扎实，不追求案例和模型的覆盖面。

## 1. 为什么需要高精度地震目录

地震目录是地震学大多数后续研究的输入，精度直接决定能得到什么结论：

- **断层成像：** 相对定位到百米级，才能看出断层面、分支和破裂的几何；
- **余震和震群的演化：** 完整性和发震时刻决定能否看清迁移、前震、触发和流体扩散；
- **地震预测和危险性：** ETAS 一类模型和 b 值分析依赖完整、震级标度一致的目录；
- **诱发地震和火山监测：** 交通灯制度和火山活动预警需要在几天内得到可靠的深度和震级。

高精度目录目前要靠专家花数周反复调试：选速度模型、调关联参数、做模板匹配和双差定位、校正震级。这一过程难以复制，也难以在新序列发生时迅速完成。通用 Agent 能写代码、调用工具，但缺少判断"结果对不对"的地震学经验。

## 2. 核心贡献

> **把地震学的知识和工具，通过一个不依赖参考目录的 checker，引入通用 Agent 的 harness，让 Agent 能检查并修复自己构建的目录，朝高精度目录靠近。**

1. **seismo checker：** 把专家诊断目录的经验写成确定性的检查，覆盖六个阶段（数据、拾取、关联、绝对定位、相对定位、震级）。它只报告症状（测了什么、超出预期多少），不给原因和修复，不用参考目录，不含任何案例的数值。
2. **知识 skill：** 专家在看数据之前就知道的东西：小批量先验证再全量、两个候选怎样取舍、"症状 → 可能原因 → 区分实验"手册，以及检查看不到的误差（速度模型和近地表、定位框架、模板匹配、震级定标）。
3. **接入方式：** 工具库、checker 和知识都只是放进 Agent 环境的文件，外加一条输出约定：提交 checker 报告，并对每个报警给出处置（已修复，或附证据说明理由）。不改 Agent 的循环，不加子 Agent，所以同样的做法适用于任何通用 harness。

## 3. 应用场景

- **新序列的快速目录：** 大震或震群发生后几天内给出接近研究级的目录；
- **临时台阵和节点台阵：** 布设密集但缺少分析人员的观测，由 Agent 承担常规处理；
- **历史数据重处理：** 用统一流程重新处理已有波形，得到一致的高精度目录；
- **诱发地震和火山监测：** 持续产出目录，用 checker 报警提示需要人工复核的地方。

在这些场景里，专家的角色从"自己做每一步"变成"审核 Agent 的处置记录"。

## 4. 对相似工作的启示（要检验的假设）

对其他领域把专业工具交给通用 Agent 的工作，本研究要检验以下几点是否成立：

1. 确定性的症状报告加"每个报警都要处置"的约定，能否比让模型自我批评更有效地防止它为错误找理由；
2. 领域知识以什么形式交给 Agent 最有效：文档、参考实现，还是检查报告；
3. 只报症状的报警会不会诱导"改到检查通过为止"的表面修复，以及怎样避免；
4. 哪些误差 Agent 用自身数据能发现，哪些必须依靠外部知识（所有台站或事件共有的偏差）；
5. 以同一数据上工具加专家经验的可达结果作为目标，是否比直接对照参考目录更能说明 Agent 差在哪里。

## 5. 实验设计

- **案例：** 现有六个案例（Prague 2011、Magna 2020、Maple Creek 2017、Kīlauea 2018、Ridgecrest 2019、Kaikōura 2016），覆盖基础、中等、困难三级和诱发、震群、火山、大震、多断层五种情形。checker 的规则在这六个案例上总结，结果按"规则来源于该案例 / 不来源于该案例"分开报告。
- **Agent 框架：** 只用 Claude Code（GLM-5.3）。贡献在于接入方式，不在于比较模型。
- **实验：**

| 实验 | 内容 | 回答的问题 |
|---|---|---|
| E1 checker 的可靠性 | 在可达结果（应当干净）上统计误报；在误差已知的目录上统计检出；合成数据中植入每类错误，看是否由对应的检查报出 | 报警可信吗？能看到哪些误差？ |
| E2 后端消融 | 拾取和关联固定，比较"只有工具 / + checker / + checker 和知识"，每次 1–3 小时 | checker 和知识分别在定位和震级上起什么作用？ |
| E3 完整流程（主实验） | S1 `tools` 对 S3 `knowledge`，每个案例各两次；需要时加 S2c `checker`（只有 checker，没有知识） | 能弥合多少差距？ |
| E4 处置分析 | 报警数、真修复、表面修复、证据不足的理由；Agent 何时、多少次运行 checker | Agent 怎样使用 checker？ |

## 6. 评估

- **精度标准：** 已发表的高精度地震目录和官方业务目录。每个目录只承担它能支撑的角色（检测、绝对定位、相对结构、震级）；震级以官方目录为准。
- **可达结果：** 同一数据上由工具加专家经验（human-in-loop）得到的目录，代表 Agent 引入工具和专家经验后能达到的结果，用来计算差距弥合率 (S3 − S1) / (可达结果 − S1)。
- **可信目录标准：** 与计划 A §3.2 相同。先判事件是否真实（台网覆盖外的比例、盲审中的假事件比例），再判：
  - **时间：** 发震时刻偏差和离散（≤ 0.3 s），以及大事件后的检测是否下降；
  - **空间：** 水平偏移、深度偏差（≤ 1 km），水平离散，偏离构造和深度堆积的比例；
  - **强度：** 相对官方目录的震级偏差、离散和标度斜率，以及大事件是否齐全。

  完整性（召回率、归一化召回、Mc）单独报告。
- **主要指标：** 可信标准的不通过判据数；各维度的差距弥合率。

## 8. 风险

- **看不到的误差：** 速度模型和近地表、震级定标水平、主震尾波中的漏检，只靠 Agent 自身的数据判断不了，只能靠知识；知识能否用上，取决于有没有可用的区域资料。
- **表面修复：** 报警可能诱导 Agent 改到检查通过为止。手册要写明哪些改动不该做，只会诱导修改的检查降为只报告。
- **循环性：** 规则和门槛在这六个案例上总结，可能高估效果；分开报告规则来源案例和其他案例。
- **效果可能太小：** 如果 S3 相对 S1 的改善在重复运行的离散之内，退回计划 A，把 checker 作为基准中的一个条件来报告。
