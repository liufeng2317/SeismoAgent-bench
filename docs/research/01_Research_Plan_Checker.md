# 研究计划 B：把专家经验写成自动检验（seismo checker）

**定位：** 主线工作，论文大纲见 [`paper/01_Outline.md`](../../paper/01_Outline.md)。如果 checker 的效果不足以单独成文，退回 [研究计划 A：基准](./00_Research_Plan_Benchmark.md)；两者共用案例、评分和运行。

## 1. 问题

专家级目录来自"运行 → 诊断 → 修复上游 → 重跑"的循环。驱动这个循环的是经验：哪些选择重要、症状最可能由哪个上游选择造成、改了之后如何在没有参考答案时确认改对了。

> **这种经验能否写成不依赖参考目录的自动检验，让通用 Agent 检查并修复自己构建的目录？它能弥合多少与专家的差距，边界在哪里？**

## 2. 依据

证据详见 [`progress/expert_experience_evidence.md`](./progress/expert_experience_evidence.md)。

- **选择的影响很不均匀。** 在专家会考虑的范围内，检测参数只让归一化召回变化 ≤ 0.07，换用模板匹配则变化 0.2–0.6。超出这个范围，单个错误选择（固定深度、网格边界、速度界面、震级单位）造成的误差是专家误差的 5–10 倍，而且在召回率上看不出来。
- **Agent 的错误正落在经验能覆盖的地方。** 换上专家的后端后，深度和时间误差大部分消失；检测差距来自没有把模板匹配的检测加进目录；Agent 还会为明显的错误找理由（Prague 把 ML −8 解释为"极安静的微震"）。

## 3. 设计

| 部分 | 形式 | 内容 |
|---|---|---|
| checker | `seismo_checker/`：确定性命令行工具，不属于 `seismotools/` | 按六个阶段（数据、拾取、关联、绝对定位、相对定位、震级）检查 Agent 自己的产品，**只报告症状**（测了什么、超出预期多少），不给原因和修复；不用参考目录，不含案例数值 |
| 知识 | Agent Skill（`data/agent_resource/skills/`） | 小批量先验证、两个候选怎样取舍、"症状 → 可能原因 → 区分实验"手册、检查看不到的误差（速度模型、近地表、水平框架、模板匹配、震级定标） |
| 契约 | 输出约定增加两项 | 对提交产品的 checker 报告；每个报警一条处置（`fixed` 说明改了什么，`justified` 给证据）。评分端重跑 checker 核对 |

**原则：**
- 不改 Agent：checker 和知识只是加进环境的文件，不定制循环，不加子 Agent，结论才适用于通用 Agent。
- 检查不是选择标准：一个模型让检查值更好看，不代表它更对。
- 误差按可检测性分三层：A 层自身数据能看到，B 层需要对照实验区分，C 层只靠自身数据看不到（所有台站或事件共有的偏差）。

现行检查和版本见 [`04_Checker_Design.md`](./04_Checker_Design.md)，当前冻结版本是 `checker-v1.3`（含知识 skill）。

## 4. 检验

1. **checker 本身：** human-in-loop 目录应当干净，用来衡量误报；误差已知的 Agent 目录用来衡量检出；合成回归测试检查每种植入错误是否由对应的检查报出。
2. **后端消融（迭代用）：** 拾取和关联固定，比较"只有工具 / + checker / + checker 和知识"，每次 1–3 小时。
3. **完整流程（正式比较）：** S1 `tools` 对 S3 `knowledge`，同一案例、同一模型；S2c `checker` 只在需要消融时运行。主要指标是可信标准的不通过数，以及按维度的差距弥合率 (S3 − S1) / (最终 − S1)。
4. **循环性：** 规则是在这六个案例上总结的。结果按"规则来源于该案例 / 不来源于该案例"分开报告，并用一个保留案例检验。
5. **处置：** 统计报警数、真修复、表面修复（只为让检查通过的改动）和证据不足的理由。

## 5. 现状（2026-11-05）

- **能挡住实现类错误。** 后端消融中，只有工具的变体在三个案例上犯了震级单位或响应错误（偏差约 −1.0 至 −1.4）；带 checker 的变体都没有犯。深度堆积这类看得见的症状也被修好（[图](./assets/checker_effect/checker_effect_summary.png)）。
- **对速度模型类偏差没有帮助。** 时间和深度偏差没有一致改善，报警还诱导了把误差从深度挪到时间的改动。有一次知识变体（正确使用已发表模型和基准面）把三项一起修好，只有一次运行。
- **检测没有测过。** 后端消融的前端是固定的；新知识针对模板匹配的部分要靠完整流程检验。
- 不通过总数：只有工具 24，+ checker 19，+ checker 和知识 20（六个案例，每格一次运行，样本很小）。新版 checker 和知识还没有经过 Agent 运行。

## 6. 风险

- **C 层误差是边界：** 速度模型和近地表、震级定标水平、主震尾波中的漏检，checker 看不到，只能靠知识；而知识能不能被正确使用，取决于有没有可用的区域资料。
- **表面修复：** 只报症状的报警会诱导 Agent 改到检查通过为止。对策是手册写明哪些改动不该做，并把只会诱导修改的检查降为只报告。
- **效果可能太小：** 如果正式比较中 S3 相对 S1 的改善在重复运行的离散之内，就把 checker 作为基准的一部分来报告（计划 A），不单独作为主要贡献。

## 7. human-in-loop 干预编码（计划中）

把六个案例专家流程中的每项干预归为四类：执行或工具、方法选择、无参考诊断、依赖参考的诊断。按阶梯效果加权后各类的占比，给出 S3 能弥合的最大差距；最后一类是没有参考目录时任何 Agent 都到不了的部分。
