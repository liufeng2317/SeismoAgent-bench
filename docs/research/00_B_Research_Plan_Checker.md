# 研究计划 B：把地震学家的经验变成自动检验——让通用 Agent 检查并修复自己构建的地震目录

*Encoding Seismologists' Experience as Automated Checks for Agent-Built Earthquake Catalogs*

**定位：** 主线工作，论文大纲见 [`paper/01_Outline.md`](../../paper/01_Outline.md)。如果效果不足以单独成文，退回 [研究计划 A：基准](./00_A_Research_Plan_Benchmark.md)。本计划要深度：在现有案例上把方法做扎实，不追求案例和模型的覆盖面。

## 1. 问题与意义

### 1.1 问题

> **能否把地震学家判断"目录对不对"的经验，写成不依赖参考答案的自动检验，交给通用 Agent，使它在没有专家介入时，从连续波形构建出高精度地震目录？这种检验能把 Agent 推进多远，边界在哪里？**

### 1.2 为什么高精度地震目录重要

地震目录是地震学大多数研究的输入，精度直接决定能得到什么科学结论：

- **断层和地下结构：** 相对定位达到百米级，才能看出断层面、分支和破裂几何，揭示应力和流体的分布；
- **地震过程：** 完整性和时间精度决定能否看清前震、余震迁移、触发和流体扩散，这是理解地震如何开始和传播的关键证据；
- **地震危险性：** ETAS 一类预测模型和 b 值分析依赖完整、震级标度一致的目录，系统偏差会直接传给危险性估计；
- **诱发地震和火山监测：** 交通灯制度和火山活动预警要求在几天内得到可靠的深度和震级。

深度学习使拾取和检测变得廉价，近年的高精度目录因此成倍地揭示出过去看不到的结构。但从检测到高精度目录，中间仍有大量需要专家判断的步骤：选速度模型、调关联参数、做模板匹配和双差定位、校正震级，并在每一步判断结果是否可信。这些判断需要专家花数周反复调试，难以复制，也难以在新序列发生时迅速完成。**今天产出高精度目录的瓶颈不在算法，而在专家的判断。**

### 1.3 为什么是现在

通用 Agent 已经能长时间自主写代码、调用工具和调试，有能力执行完整的处理流程。它们缺的是领域经验：知道哪些选择重要，能看出结果哪里不对。真实的科学处理没有标准答案可对照，Agent 只能依靠自身数据判断，而这正是它们最弱的地方：会为明显的错误找理由，会在没有依据时继续往下做。

### 1.4 已有工作的空缺

- **Agent 的自我验证**（如 CRITIC、VerifiAgent）用通用工具或另一个模型来检查答案，面向有明确对错的通用任务，不涉及物理一致性，也不处理"没有标准答案"的科学数据。
- **领域科学 Agent** 多数通过定制的 Agent 循环或多 Agent 结构引入领域知识，换一个 harness 就要重做，也难以分清增益来自知识还是来自结构。
- **地震学的自动质控**（台网的波形质控、目录的统计检验）面向分析人员，只给出指标，不和处理过程中的决策和修复连在一起。
- **自动化目录流程**（如 QuakeFlow、LOC-FLOW）把专家的选择固定在流程里，遇到不同的台网和构造就需要专家重新调整。

## 2. 核心贡献

> **把地震学家判断目录的经验写成不依赖参考目录的自动检验（seismo checker）和配套知识，以文件和输出约定的形式接入通用 Agent，让它检查并修复自己构建的目录，朝高精度目录靠近；同时给出这种自动检验能做到什么、做不到什么。**

1. **seismo checker：** 把专家诊断目录的经验写成确定性的检查，覆盖六个阶段（数据、拾取、关联、绝对定位、相对定位、震级）。它只报告症状（测了什么、超出预期多少），不给原因和修复，不用参考目录，不含任何案例的数值。
2. **知识 skill：** 专家在看数据之前就知道的东西：小批量先验证再全量、两个候选怎样取舍、"症状 → 可能原因 → 区分实验"手册，以及检查看不到的误差（速度模型和近地表、定位框架、模板匹配、震级定标）。checker 管"看出问题"，知识管"知道怎么做、看不到的问题怎么防"，两者一起构成贡献。
3. **接入方式：** 工具库、checker 和知识都只是放进 Agent 环境的文件，外加一条输出约定：提交 checker 报告，并对每个报警给出处置（已修复，或附证据说明理由）。不改 Agent 的循环，不加子 Agent，设计上可用于任何通用 harness。本研究只在 Claude Code 上实验，可移植性是设计属性，不作为实验结论。
4. **可检测性的边界：** 把目录误差分为三层：Agent 自身数据能看到的、需要对照实验才能区分的、只靠自身数据看不到的（所有台站或事件共有的偏差）。这说明了无参考自动检验的适用范围，对其他领域同样适用。

## 3. 应用场景

- **新序列的快速目录：** 大震或震群发生后几天内给出接近研究级的目录，支持早期的科学判断和应急决策；
- **临时台阵和节点台阵：** 布设密集但缺少分析人员的观测，由 Agent 承担常规处理；
- **历史数据重处理：** 用统一流程重新处理已有波形，得到时间和空间上一致的高精度目录；
- **诱发地震和火山监测：** 持续产出目录，checker 报警提示需要人工复核的地方。

在这些场景里，专家的角色从"自己做每一步"变成"审核 Agent 的处置记录"：哪里报警、Agent 改了什么、为什么认为剩下的报警没问题，都有记录可查。

## 4. 假设与成功标准

### 4.1 "高精度"的定义

一个目录在某一维度上算高精度，是指它与主要高精度参考目录的差异，不大于两个独立高精度参考目录之间的差异（只有一个高精度参考时，用可达结果与该参考的差异代替）。按维度：

- **检测：** 归一化召回 ≥ 1，即达到独立参考之间能互相召回的水平；完整性震级 Mc 不高于参考目录间的差异；
- **定位：** 水平离散和深度偏差不大于参考目录之间的相应差异；
- **震级：** 相对官方目录的偏差、离散和标度斜率不大于高精度参考相对官方目录的相应值。

可信目录标准（§6）是底线，高精度是目标。

### 4.2 要检验的假设

- **H-B1 报警可靠：** checker 在可达结果上很少报警，并能报出植入的每一类可检测错误。
- **H-B2 消除可检测的错误：** 加上 checker 和知识（S3）后，Agent 自身数据能看到的错误（如震级单位、仪器响应、深度堆积、网格边界）不再出现在提交的目录里。
- **H-B3 弥合差距：** S3 相对 S1 不通过的判据更少，各维度的差距弥合率为正，并且超出重复运行的离散。
- **H-B4 边界：** 只靠自身数据看不到的误差（速度模型和近地表、定标水平），S3 只有在知识提供了可用的区域资料时才能改善。
- **H-B5 处置的质量：** 多数报警得到真修复，表面修复（只为让检查通过的改动）占少数。

### 4.3 成功标准（建议，冻结前确定）

- **H-B1 成立：** 可达结果上平均每个案例的报警不超过 1 个；合成数据中植入的每类可检测错误都由对应检查报出；
- **H-B2、H-B3 成立：** 至少一半案例中 S3 的不通过判据少于 S1，差别超出两次重复的离散；
- **规则来源无关：** 规则来源于该案例和不来源于该案例的结果方向一致。

H-B4 无论结果如何都要报告，它界定方法的适用范围。若 H-B2 或 H-B3 不成立，退回计划 A，把 checker 作为基准中的一个条件报告。

## 5. 实验设计

- **案例：** 现有六个案例（Prague 2011、Magna 2020、Maple Creek 2017、Kīlauea 2018、Ridgecrest 2019、Kaikōura 2016），覆盖基础、中等、困难三级和诱发、震群、火山、大震、多断层五种情形。checker 的规则在这六个案例上总结，结果按"规则来源于该案例 / 不来源于该案例"分开报告。
- **Agent 框架：** 只用 Claude Code（GLM-5.3）。贡献在于接入方式，不在于比较模型。
- **实验：**

| 实验 | 内容 | 检验 |
|---|---|---|
| E1 checker 的可靠性 | 在可达结果（应当干净）上统计误报；在误差已知的目录上统计检出；合成数据中植入每类错误，看是否由对应的检查报出 | H-B1 |
| E2 后端消融 | 拾取和关联固定，比较"只有工具 / + checker / + checker 和知识"，每次 1–3 小时 | H-B2、H-B4，分开 checker 和知识的作用 |
| E3 完整流程（主实验） | S1 `tools` 对 S3 `knowledge`，每个案例各两次；需要时加 S2c `checker`（只有 checker，没有知识） | H-B2、H-B3 |
| E4 处置分析 | 报警数、真修复、表面修复、证据不足的理由；Agent 何时、多少次运行 checker | H-B5 |

## 6. 评估

- **精度标准：** 已发表的高精度地震目录和官方业务目录。每个目录只承担它能支撑的角色（检测、绝对定位、相对结构、震级）；震级以官方目录为准。
- **可达结果：** 同一数据上由工具加专家经验（human-in-loop）得到的目录，代表 Agent 引入工具和专家经验后能达到的结果，用来计算差距弥合率 (S3 − S1) / (可达结果 − S1)。
- **可信目录标准：** 与[计划 A §4.2](./00_A_Research_Plan_Benchmark.md) 相同。先判事件是否真实（台网覆盖外的比例、盲审中的假事件比例），再判：
  - **时间：** 发震时刻偏差和离散（≤ 0.3 s），以及大事件后的检测是否下降；
  - **空间：** 水平偏移、深度偏差（≤ 1 km），水平离散，偏离构造和深度堆积的比例；
  - **强度：** 相对官方目录的震级偏差、离散和标度斜率，以及大事件是否齐全。

  完整性（召回率、归一化召回、Mc）单独报告。
- **高精度：** 按 §4.1 逐维度判断。
- **时间和成本：** 每次运行的墙钟时间、token 用量、checker 运行次数，以及审核处置记录所需的人工时间（抽样估计），用来支撑"几天内给出目录"的应用场景。

## 8. 对相似工作的启示（要检验的问题）

对其他领域把专业工具交给通用 Agent 的工作，本研究检验以下问题：

1. 确定性的症状报告加"每个报警都要处置"的约定，能否比让模型自我批评更有效地防止它为错误找理由；
2. 领域知识以什么形式交给 Agent 最有效：文档、参考实现，还是检查报告；
3. 只报症状的报警会不会诱导"改到检查通过为止"的表面修复，以及怎样避免；
4. 哪些误差 Agent 用自身数据能发现，哪些必须依靠外部知识；
5. 以同一数据上工具加专家经验的可达结果作为目标，是否比直接对照参考目录更能说明 Agent 差在哪里。

## 9. 风险

- **看不到的误差：** 速度模型和近地表、震级定标水平、主震尾波中的漏检，只靠 Agent 自身的数据判断不了，只能靠知识；知识能否用上，取决于有没有可用的区域资料。
- **表面修复：** 报警可能诱导 Agent 改到检查通过为止。手册要写明哪些改动不该做，只会诱导修改的检查降为只报告。
- **循环性：** 规则和门槛在这六个案例上总结，可能高估效果；分开报告规则来源案例和其他案例。
- **效果可能太小：** 见 §4.3；不成立时退回计划 A。
