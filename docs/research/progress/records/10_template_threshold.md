# 模板匹配：门槛、误检与召回（2026-11-05）

[05](05_near_surface_magnitude_matching.md) 评估过模板匹配阶段要不要加检查。当时的结论是：Agent 的门槛偏保守，问题在漏检，而漏检从产品本身看不出来，所以没有加检查。这次把当时的估算做成可重复的分析，覆盖六个案例，回答三个问题：
1. 模板匹配给最终目录带来多少召回；
2. 门槛每提高一点损失多少；
3. Agent 的检测差距中，门槛占多少。

## 方法

脚本 `workflows/development/replay/template_threshold.py`，输出 `outputs/template_threshold/`（含 `summary.md`，不纳入版本库）。

- **专家运行：** 每个案例取最终目录所用的专家 Match&Locate 运行（`hil_relocation/cases/<case>.yaml` 的模板来源），以及它的零假设运行（各通道随机平移至少 600 s，覆盖 1–2 天）。
- **误检比例：** 门槛 T 处零假设运行每天的检测数，除以真实运行每天的检测数。
- **召回：** 把最终目录删减为"拾取事件 + `ml_nmad ≥ T` 的模板匹配事件"，用评分器打分，得到对各检测参考的召回、归一化召回，以及保留下来的最终目录事件比例。T = 无穷，即最终目录去掉全部模板匹配事件。
- **Agent 的用法：** 从六个正式 tools 运行的工作目录和报告读出。

## 结果

| 案例 | 误检比例 9.0 / 9.5 / 10 | 通过（≤ 2 %）的最低门槛 | 归一化召回：无模板匹配 → 9.5 → 10 → 16.3 | 保留的最终目录事件：无模板匹配 / 10 / 16.3 | tools 运行如何使用 |
|---|---|---|---|---|---|
| Prague | 5.4 % / 0.8 % / 0.2 % | 9.5 | 0.96 → 1.85 → 1.83 → 1.44 | 29 % / 92 % / 49 % | 未运行 |
| Kīlauea | 4.5 / 0.5 / 0.0 | 9.5 | 0.98 → 1.22 → 1.20 → 1.10 | 56 / 92 / 64 | 未运行 |
| Kaikōura | 11.0 / 1.5 / 0.2 | 9.5 | 0.89 → 1.17 → 1.17 → 1.00 | 44 / 100 / 53 | 未运行 |
| Maple | 3.5 / 0.5 / 0.0 | 9.5 | 0.72 → 0.99 → 0.99 → 0.94 | 8 / 80 / 21 | 只跑了一天的试验（门槛 10），全量数据已准备但未运行 |
| Ridgecrest | 4.7 / 0.5 / 0.1 | 9.5 | 0.83 → 1.38 → 1.37 → 1.19 | 29 / 94 / 51 | 全量运行（10，CC ≥ 0.3），只作完整性核对，没有加入目录 |
| Magna | 7.0 / 1.0 / 0.2 | 9.5 | 0.78 → 1.10 → 1.06 → 0.84 | 50 / 80 / 55 | 全量运行，合并后只保留有 PhaseNet 拾取印证的检测，实际最低 16.3 |

说明：
- 归一化召回 = 对主要检测参考的召回 ÷ 独立参考之间能达到的召回，大于 1 表示超过参考目录之间的互相召回。
- Kaikōura 最终目录的模板匹配事件最低是 10，所以 9.5 和 10 相同。
- 各参考目录的召回见输出的 `summary.md`。

## 结论

1. **检测上的差距主要来自没有用模板匹配，不是门槛。**
   - 去掉模板匹配事件后，最终目录只剩 8–56 % 的事件，归一化召回从 0.99–1.85 降到 0.72–0.98。
   - 六个 tools 运行中，五个没有把模板匹配的检测加进目录。三个根本没运行；Maple 只做了试验；Ridgecrest 跑完了全量却只用来核对完整性。
   - 这是"工具必要但不充分"的直接证据：工具在手，Agent 没有用到产品里。
2. **零假设检验给出的门槛在六个案例上都是 9.5。** 误检比例在 9.0 时为 3.5–11 %，9.5 时为 0.5–1.5 %，10 时不超过 0.2 %。这是同一工具、相近设置下的结果；模板数、通道数、频带变了，门槛不一定能照搬，所以知识里仍写"用零假设检验选"，不写具体数值。
3. **门槛的代价随高度急剧上升。**
   - 从 9.5 提到 10，模板匹配检测减少 0–18 %，归一化召回只降 0–0.04。
   - 提到 16.3（Magna 的 Agent 实际用的门槛），丢掉全部事件的 36–79 %。
   - 所以 Magna 的门槛确实造成了损失（保留 55 % 对 80 %）；在其他案例上，门槛不是主要问题。
