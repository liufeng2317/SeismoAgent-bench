# 和速度模型无关的深度核对：近台 S−P 深度（2026-11-08）

问题：地震学专家用和速度模型无关的证据核对绝对深度，最常用的是近台 S−P 时间。能不能把它做成给 Agent 的独立核对脚本？脚本 `workflows/development/velocity/depth_time_check.py`：用远于两倍震源深度的台站从 S−P 时间和震源距求 K = Vp·Vs/(Vp−Vs)，在近于一倍震源深度的台站由 K·(S−P) 反推深度，报告与目录深度之差（按深度三分）；另报近台和全部台站的 Wadati Vp/Vs，以及候选模型目录给出的深度和时刻范围。

## 检验

12 次真实深度偏差已知的运行（开发窗口或全量评分；真实偏差 = 目录 − 参考目录）。目录偏浅时，近台 S−P 深度应更深（偏差为正）。

| 运行 | 真实偏差（km） | 近台 S−P 偏差（km） | 方向 |
|---|---|---|---|
| Magna 开发第一轮 | −1.75 | +2.66 | 对 |
| Magna S1 | −1.69 | +1.92 | 对 |
| Magna 开发第二轮 | +1.18 | +0.79 | 错 |
| Ridgecrest 开发第二轮 | +1.13 | +0.63 | 错 |
| Ridgecrest S1 | −2.51 | −1.31 | 错 |
| Prague S1 | +1.30 | +0.40 | 错 |
| Maple 开发第二轮 | +1.51 | +0.19 | 错 |
| 其余 5 次（真实偏差 −0.4 至 +0.84） | | −0.33 至 +1.27 | 整体偏正约 1 km |

按深度三分时，偏差随深度变化很大（最深三分之一常为 −3 至 −6 km）。

## 结论

- 只有目录明显偏浅（超过 1.5 km）时方向可靠，和 checker 的 `sp_depth_offset` 一样（记录 18）；其余情况整体偏正约 1 km，且随深度变化，不能作为独立核对给 Agent。
- 原因：K 来自远台，远台的 S−P 走过折射路径；"近台"按目录自己的深度筛选，是循环的。要真正独立，需要近源的 Vp 和 Vp/Vs（这又回到速度模型）或深度震相、地面真值事件。
- 候选模型给出的深度和时刻范围仍可作为不确定度报告，已在知识 skill 的 `not_visible.md` 中要求；脚本留在开发工具中。
