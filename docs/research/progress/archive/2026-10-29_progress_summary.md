# SeismoAgentBench 进展总结（截至 2026-10-29）

> **更正（2026-10-30）：** 本文数值来自 metrics v1。Maple Creek 的结果显示 v1 的 headline 会掩盖散乱或有系统偏差的目录，评估已升级为 metrics v2（门限 2 s / 5 km、全部匹配做偶然匹配校正、直接与 final 比较、增加可用性判定），所有结果已重新评分，部分数值有变化（例如 Prague tools recall_norm 1.38 不变，final 1.83 → 1.85；Magna tools 0.88 → 0.87）。最新数值见 `docs/research/progress/archive/STATUS_AND_PLAN.md`，改动说明见 `docs/framework/02_Catalog_Metrics.md` §12。结论方向不变，且更明确：目前没有任何 Agent 运行达到"可信目录标准"（事件真实性、时间、空间、强度四个维度，完整度单独报告）。

## 一句话概述

我们整理了 6 个地震监测案例，用 human-in-loop 的方式为每个案例构建了专家级地震目录作为基准，制定并冻结了评估准则（metrics v1），并在 Prague 和 Magna 两个案例上完成了第一批正式 Agent 测试（Claude Code × GLM-5.3）。

初步结论如下：
- 没有工具库时，Agent 基本跑不通：两个 min 运行都没有交出有效结果；即使补救评分，Prague min 的检测量也只有 tools 的三分之一，还带有拾取时间换算错误；
- 有了工具库，Agent 能完成任务，但检测量只有 human-in-loop 最终目录的约 75 %（recall_norm：Prague 1.38 对 1.83，Magna 0.88 对 1.16）。差距基本就是模板匹配的增量：Agent 调用了 Match&Locate，却只新增了 155 和 6 个事件，human-in-loop 分别新增约 4,300 和 2,750 个。Magna 的 S 波拾取召回也明显偏低（0.67 对 0.85）；
- 但即使有工具，它在定位和震级上仍会出现系统性错误，而且自己发现不了。

这说明工具是必要条件：不给工具，任务基本无法完成。但工具不是充分条件：要得到科学上可用的目录，还需要"自检/纠错"的经验（检查器）。

## 1. 六个地震监测案例

每个案例的任务完全相同：给定一段连续波形和台站信息，从零构建地震目录，包括拾取、关联、定位和震级。

| 案例 | 序列与背景 | 评估时间窗 | 数据 | 参考目录（已发表） |
|---|---|---|---|---|
| Prague 2011 | Oklahoma 注水诱发，Mw 5.7 后的余震 | 11-11 – 11-19（8 天） | 23 台，约 7 GB | Cochran 2020、McMahon 2017、Isken 2017、ComCat |
| Kaikōura 2016 | Mw 7.8 后的余震，网络跨度约 260 km | 12-01 – 12-09（8 天） | 53 台，约 12 GB | Chamberlain、Tan、Lanza、GeoNet |
| Maple Creek 2017 | Yellowstone 震群（最大 Mw 4.4） | 06-11 – 06-19（8 天） | 27 台，约 4.4 GB | ComCat、Shelly（模板匹配，只有时间） |
| Kīlauea 2018 | 火山顶部塌陷期地震 | 05-01 – 05-09（8 天） | 25 台，约 6.5 GB | Shelly、Wei、Matoza、ComCat |
| Ridgecrest 2019 | M6.4 与 M7.1 主震序列 | 07-04 – 07-07（3 天） | 约 5 GB | Shelly、Liu、Ross、AWR、官方目录 |
| Magna 2020 | Utah Mw 5.7 余震 | 03-18 – 03-26（8 天） | 47 台，约 11 GB | Pang 2020、Baker（人工拾取）、UUSS |

六个案例覆盖了多种场景：
- 构造类型：诱发、构造、火山、震群；
- 尺度：从局部台阵到区域台网；
- 难度来源：主震尾波、只有垂直分量的台站、复杂速度结构等。

每个案例都有多个独立发表的参考目录。这让我们能先衡量"参考目录彼此之间能对上多少"，再评价 Agent。

## 2. 用 human-in-loop 构建专家基准

**方法。** 由研究者逐步引导 Agent 式的处理流程：PhaseNet 拾取 → GaMMA 关联 → NonLinLoc 绝对定位 → 台站校正 → Match&Locate 模板匹配 → 双差重定位 → 震级。每一轮的结果都和参考目录对比，再由人诊断问题、修改上游设置并重跑。各案例迭代了 7–11 轮，得到最终目录，称为 human-in-loop agent。

**唯一标尺：final（最终版），作为 Agent 的上限。** 它在迭代中参考过参考目录的反馈，所以到 final 的差距里有一小部分（如 Ridgecrest 的分层速度模型、Magna 的 ML 校准）是 Agent 不借助参考目录就补不上的。这部分用 expert ladder 逐步拆分说明。第一轮结果（blind）没用模板匹配，和带工具的 Agent 不在同一条件下，因此不作为对比标尺。

**结果（metrics v1）。**
- recall_norm 是召回率除以"参考目录之间互相能召回的上限"（ceiling）。
- 大于 1 表示这份目录比任何一个参考目录对其他参考的覆盖都更完整。

| 案例 | 事件数 | recall_norm | 整体偏移 (km) | 定位离散 (km) | 深度偏差 (km) | 震级中位差 |
|---|---|---|---|---|---|---|
| Prague | 6,767 | 1.83 | 0.17 | 0.31 | +0.12 | −0.23 |
| Kaikōura | 12,924 | 1.17 | 1.13 | 2.78 | −0.87 | −0.12 |
| Maple Creek | 12,422 | 1.15 | 0.59 | 0.66 | +1.46 | +0.15 |
| Kīlauea | 5,198 | 1.16 | 0.59 | 0.66 | +0.54 | −0.27 |
| Ridgecrest | 17,902 | 1.39 | 0.37 | 0.21 | −0.09 | −0.09 |
| Magna | 5,412 | 1.16 | 0.95 | 0.48 | +0.09 | +0.08 |

迭代过程本身也是重要发现（详见 `docs/research/00_B_Research_Plan_Checker.md`）：

- **专家能力主要体现在"纠错"上。** 在专家的合理范围内调参数，检测只变化 ≤ 0.07。换方法（模板匹配）则在每个案例上提升 0.2–0.6。超出合理范围的单个错误选择，带来的误差是专家误差的 5–10 倍，比如速度模型、网格边界、震级尺度。
- **评估体系反过来查出了专家目录自身的缺陷，并已修正**（2026-10-28）：
  - Ridgecrest 的 M7.1、M6.4 主震被质量控制规则误删；
  - 链式相对震级压缩了大地震的震级；
  - Match&Locate 在大地震尾波中产生了"幽灵"事件。

## 3. 评估准则（metrics v1，2026-10-28 冻结）

在正式测试前预先确定指标并冻结。此后任何修改都记为 v2，并对所有结果重新评分。指标分为以下几层，不设综合总分。

| 层 | 内容 |
|---|---|
| L0 完成度 | 输出是否符合约定；内部一致性 |
| L1 检测 | 召回率按参考目录间的上限归一（recall_norm）；精度用"被任一参考或专家目录支持的比例"（union support）加上盲审估计的虚假率 |
| L2 位置 | 把偏差拆成整体偏移（shift）和离散（scatter）；深度剖面（检查是否堆积在某个深度） |
| L3 结构 | 偏离已知断层结构的事件比例；事件间距误差 |
| L4 / 强度 | 震级偏差和斜率、Mc、b 值；按 M2+/M3+/M4+/M5+ 分档计算 F1 和误差 |
| L5 拾取 | 对照人工拾取评估（Magna 用 Baker，Maple 用 Shelly） |
| L6 过程 | 成本、耗时、轮数；泄漏检查（扫描工具调用中是否访问参考数据或专家结果） |

两项配套分析：
- **盲审**：从没有任何参考支持的事件中分层抽 50 个，看波形判断真伪，再由第二个人抽查 10 个。
- **组件替换**：用专家的速度模型和定位器重新定位 Agent 自己的拾取，以此区分误差来自前端（拾取、关联）还是后端（模型、定位）。

规则约定：失败的运行在检测指标上记 0 分；补救评分只作参考，不计入正式结果。

## 4. 工具库与任务包

- **工具库 seismotools**：11 个工具，均经过合成数据和真实数据验证。包括 PhaseNet、GaMMA、PyOcto、REAL、NonLinLoc（含 EDT）、HypoInverse、hypoDD、GrowClust、ccdt 互相关、Match&Locate 等。
- **三个任务变体**：
  - min：只给任务和数据；
  - tools：额外提供工具库；
  - guided：额外提供专家的工作流程指引，作为另一个维度，可选。
- **正式运行前的检查与修正**（2026-10-28）：
  - prompt 中补齐输出字段约定和处理时间窗；
  - tools 中列出 Match&Locate；
  - 清除工具库里指向专家结果和参考目录的内容；
  - 运行器改为保留 Agent 写在临时目录里的文件，并在会话结束时清理残留的后台进程。

## 5. Agent 测试结果（Prague、Magna；Claude Code × GLM-5.3，各一次）

|---|---|---|---|---|
| 正式状态 | 失败（输出放错位置） | 有效 | 失败（会话中断后无输出） | 有效 |
| 耗时 | 4.7 h | 5.8 h | 4.1 h（之后后台流水线崩溃） | 7.5 h |
| recall_norm | 0（补评 0.44） | **1.38**（final 1.83） | 0 | **0.88**（final 1.16） |
| 模板匹配新增事件 | — | 155（final 约 4,300） | — | 6（final 约 2,750） |

| 整体偏移 / 离散 (km) | 补评：0.36 / 0.47 | 0.20 / 0.26（final 0.17 / 0.31） | — | **2.50** / 0.38（final 0.95 / 0.48） |
| 深度偏差 (km) | 补评：+1.98（拾取整体早 2.5 s） | **+1.24**（final +0.12） | — | **−1.72**（final +0.09） |
| 震级中位差 | 补评：−0.82 | **−2.77**（单位错误；final −0.23） | — | +0.67（final +0.08） |
| 盲审虚假率 | — | 0.06 % | — | 0.17 % |
| 泄漏 | 无 | 无 | 无 | 无 |

**典型错误**都能用 Agent 自己的数据发现，不需要参考目录：

1. **Prague min，拾取时间换算错误。** 所有台站的拾取都早 2.5 s，正好等于 PhaseNet 的 blinding 长度。这个误差传导到发震时刻（−2.2 s）和深度上。
2. **Prague tools，震级单位错误。** 公式要求振幅单位是 nm，代入的却是 mm 单位的 Wood-Anderson 记录，结果整体偏低 2.7。Agent 看到 ML 低到 −8，却解释为"超安静台阵记录到的真实微震"。
3. **Magna tools，定位整体平移。** Agent 自己设定了速度模型，又用定位残差反推台站校正，导致整个目录整体移位。改用专家定位器后，偏移从 2.5 km 降到 1.6 km，深度偏差从 −1.7 km 降到 −0.8 km，说明主要误差来自后端。
4. **两个 min 都栽在流程纪律上。**
   - Prague：把结果写到了临时目录。
   - Magna：把没在真实数据上跑通的阶段交给无人看管的后台流水线，然后结束了会话。流水线后来在模板匹配阶段崩溃，最终没有任何输出。

## 6. 当前结论（初步：单模型、每个配置只跑了一次）

1. **工具是必要条件。** 没有工具时，两个 min 都没交出有效结果。Prague min 补救后 recall_norm 只有 0.44，tools 是 1.38；此前 Ridgecrest 预实验也是 min 0.51、tools 1.18，方向一致。
   - 没有工具时，Agent 要从头实现整条流程：耗时长，环节多，既容易在流程上出错（输出位置、会话管理），也容易在实现上出错。比如 Prague min 的 2.5 s 拾取偏差，就来自它自己写的 PhaseNet 调用。
   - tools 运行按工具库里验证过的方式调用，拾取没有偏差：和专家拾取相比中位差 0.000 s，96 % 在 0.1 s 以内。
2. **工具不是充分条件：它解决了"能不能做"，没有解决"做得对不对"。** 与上限（final）相比：
   - 检测量只有约 75 %，差距基本对应模板匹配：Agent 调用了 Match&Locate，但把它当作验证已有目录的手段，或在去重、筛选中删掉了大部分检测，只新增 155 和 6 个事件。工具在手不等于会用。
   - Magna 的 S 波拾取召回偏低（0.67 对 0.85）。
   - 定位上，目录内部的离散已接近或优于 final（Prague 0.26 对 0.31 km），但出现了大的系统偏差：深度偏差 +1.24 km 和 −1.72 km，Magna 整体平移 2.5 km。
   - 震级尺度出错（Prague −2.77）。

   这些误差集中在后端选择（速度模型、台站校正、震级尺度），这和 Ridgecrest 预实验的组件替换结论一致。
3. **Agent 无法识别自己的系统性错误。** 2.5 s 的时间偏移、2.7 个单位的震级偏差、2.5 km 的整体平移，都能用简单的、不需要参考目录的检查发现（拾取与初动的偏差、发震时刻与深度的耦合、震级量级是否合理、台站校正有没有方向性）。但 Agent 没有做这些检查，或者做了也给出了错误解释。
4. **这支持本基准分阶段的设计：** 工具提供"能做"的能力，专家经验提供"做对"的能力，也就是"症状 → 原因 → 上游修复"的检查器。S0 → S1（min → tools）已经显示了工具的作用。接下来的 S2、S3 要检验：给了检查器之后，通用 Agent 能否产出可用于科学发现的结果？检查器能弥补多少剩余差距？
5. **评估体系本身的价值：** 多参考目录、上限归一、偏移/离散分解、组件替换和盲审，既能定位 Agent 的错误来源，也查出了专家基准自身的缺陷。

## 7. 下一步

- 剩余 4 个案例的正式运行正在排队，按 Maple Creek → Kīlauea → Kaikōura → Ridgecrest 的顺序依次运行，每个案例跑 min 和 tools。完成后对每个运行做评分、组件替换和盲审。
- 盲审需要第二个人抽查：Prague 和 Magna 的 tools 运行各 10 张图，用于计算两人标注的一致率。
- 视结果决定是否重复运行。重复的规则是：两次运行的差异超过阶段效应的一半时才重复。
- 之后按计划进入 S2（tools + 检查器）和 S3（tools + 检查器 + 修复经验），检验"检查器"能弥补多少差距。
