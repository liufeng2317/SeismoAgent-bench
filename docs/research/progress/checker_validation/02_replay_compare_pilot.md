# 方案比较与小批量：离线重放（2026-10-31）

从设计文档 [`../../04_Checker_Design.md`](../../04_Checker_Design.md) 迁出（2026-11-04）。离线重放（A 层）的设计，比较器 `compare.py` 在换速度模型场景上的表现，Prague 堆积的成因，小批量能否代表全量，以及由此定下的小批量协议。


正式运行一次要 5–27 小时，主要耗在后台计算，所以对 checker、比较规则和知识的修改不能靠重跑 Agent 来检验。离线重放（[`workflows/development/replay/`](../../../../workflows/development/replay/README.md)，第 A 层）复用已完成运行的拾取、目录和波形：用运行自己的拾取构造一个候选结果（例如换速度模型重定位），Agent 视角只看 checker 和 `compare.py`（不读参考目录），基准视角再用参考目录评分，判断 Agent 视角的决定是否正确。一个全量场景 10–82 分钟，一个小批量 1–3 分钟。

**比较器（`seismotools/checker/interface/compare.py`）。** 输入同一阶段、同一输入的两份报告（当前结果和候选结果），只用参与判定的检查，每项检查有方向（越小越好、越接近零越好、越大越好、在范围内）和噪声容差；结论按预先固定的规则给出：更好（有改善、无变差）、更差、矛盾（有改善也有变差）、不确定（改善全部来自比例类检查，同时删掉了 5 % 以上的事件）、无差别。`--change` 说明改的是什么，已知不能比较该类改动的检查列出但不计入（换速度模型时的分层条带）。候选结果仍有报警时另行提示：少错不等于对。

六个速度模型替换场景（tools 运行，区域模型按专家方式使用；真值按该类改动能影响的可信标准维度判定）：

| 场景 | compare | 真值 | 一致 |
|---|---|---|---|
| Kīlauea 区域模型 | 更好 | 更好（时间偏差修好） | 对 |
| Prague 区域模型 | 更差 | 更好（深度偏差 +1.10 → 0.00 km） | 错 |
| Magna 区域模型 | 矛盾 | 更差 | 未定 |
| Magna 加 2 km 盆地层 | 矛盾 | 更差 | 未定 |
| Maple 区域模型 | 矛盾 | 更差 | 未定 |
| Ridgecrest LITHO1.0 | 矛盾 | 更差 | 未定 |

比较器偏保守：四个更差的模型都没有被采纳，错过了 Prague 的改进。Prague 判错是因为重定位后 5.9 % 的事件落在 1.75 km 同一深度，触发单一深度值报警。四个"矛盾"都是真的更差：这时 checker 本身不足以决定，需要知识（排查手册、对照实验）接手，这正是 checker 与知识结合的理由。

**Prague 堆积的成因：台阶界面。** 堆在 1.75 km（参考高程下 2.03 km）的 225 个事件约束较差（震相中位数 9，其余 13；方位角空隙 136°，其余 98°；最大似然深度比概率密度期望浅约 1 km）。对照实验只重定位这些事件加 200 个随机事件：同一模型改为节点间线性梯度后，单一深度值的比例从 100 % 降到 8 %；保持台阶、把走时网格从 0.5 km 加密到 0.1 km 后，堆积移到 2.22 km，紧贴参考高程下 2.25 km 的台阶界面（另一个 91 个事件的 1.97 km 堆积同样移到 2.22 km）。即：约束差的事件被台阶界面吸住；0.5 km 网格下插值把堆积挪到界面旁的网格节点，所以看起来不在界面上（此前"不在模型界面上"的判断是错的）。

**对照实验：同一区域模型改为线性梯度（全量）。**

| 场景 | compare | 真值 | 深度偏差（km） | 其他变化 |
|---|---|---|---|---|
| Prague 台阶 / 线性 | 更差 / 矛盾 | 更好 / 更差 | +1.10 → 0.00 / +0.03 | 线性：时间偏差 0.06 → 0.23 s，区域外 9.4 → 11.9 % |
| Maple 台阶 / 线性 | 矛盾 / 矛盾 | 更差 / **更好** | −2.18 → −3.25 / −1.28 | 线性：界面堆积消失（单值 21 % → 3 %） |
| Magna 台阶 / 线性 | 矛盾 / 矛盾 | 更差 / **更好** | −1.94 → −1.59 / −0.88 | 线性：深度偏差判据由不通过变为通过，区域外 2.7 → 16 % |

1. 台阶还是线性，影响和选哪个模型一样大：Maple、Magna 的区域模型按台阶使用更差，按线性使用比 Agent 自己的模型更好；Prague 反过来，台阶更好。不能事先规定一种表示方式，要对照比较。
2. 比较器在九个场景里对 1、错 1、未定 7（其中 5 个真的更差，2 个真的更好）。没有采纳过更差的结果，但也错过了三个改进。Prague 台阶的深度改进（1.10 → 0.00 km）checker 本身看不到：S−P 深度只从 1.04 变到 0.79 km，在容差以内。
3. 由此写入知识 skill 的排查流程（[`data/agent_resource/skills/catalog-knowledge/`](../../../../data/agent_resource/skills/catalog-knowledge/SKILL.md)）：出现深度堆积或分层时，只对堆积事件做线性梯度和加密网格两个对照实验，区分"表示方式造成的假象"和"模型错误"；是假象时，把线性版本和"台阶模型但不计这项检查"两个候选分别与当前结果比较。三个改进中，按这个流程 Maple、Magna 的线性版本仍然是"矛盾"（S−P 深度改善，但区域顶部出现小堆积），说明还需要第二层判断：这时候选结果是否仍然不可信（Maple 仍有 5 项不通过，Magna 仍有 2 项），而不是只看比较结论。

**小批量能否代表全量。** 每个场景在约 300 个事件上做同样的改动，与全量比较。

| 抽样规则 | 目录移动（深度）与全量之差 | 目录移动（时间）与全量之差 | 判定与全量一致 |
|---|---|---|---|
| 记录最好的事件（拾取台站最多） | 0.25–3.5 km，两例方向相反（Magna、Maple） | ≤ 0.04 s | 1/6 |
| 随机、等时间段、按拾取数分层 | 15/18 ≤ 0.3 km，Ridgecrest 0.4–0.8 km | ≤ 0.07 s | 6/18 |
| 组合（代表性 + 最繁忙 + 最大，见下） | 0.02–0.27 km，Ridgecrest 0.80 km | ≤ 0.11 s | 1/6 |

1. 目录会怎样移动，代表性小批量能推到全量；记录最好的事件不能，而这恰是人工排查最自然的选法。
2. 小批量上的比较结论推不到全量：堆积、分层只在全量的弱事件里形成，300 个事件上比例类检查的噪声也太大。缩小规模反转结论的现象在通用 Agent 研究中也有报告（ABE-Ralph：13.3 % 的缩小规模运行反转了论文的核心结论，见 [`reference/notes/`](../../reference/notes/README.md)）。
3. 用"原偏差 + 小批量中位移动"外推全量偏差，在改动对不同事件影响差别很大时失败（Ridgecrest：预测约 +0.1 km，实际 +2.31 km；被压顶的事件移动特别多）。

**逐个对象的检查与总体分布的检查。** 同一检查在小批量与全量上的结论（四种单一规则，50 对报告，含一个冒烟场景）：逐个拾取、事件、台站的检查（关联比例、S/P 比、走时截距、Wadati、台站残差、方位角空隙）全部一致；总体分布的检查经常翻转（分层条带 37/50、单一深度值 42/50、孤立事件 44/50、边界堆积 46/50）；拾取过少和 S−P 深度的数值接近全量，只在门槛附近翻转。据此每项检查有 `scope`：`item` 或 `population`（深度堆积和分层、孤立和重复事件、繁忙时段、b 值、事件率、重定位变薄）。`run.py --pilot` 在小批量上只报告 population 检查的数值、不判定。

**小批量工具（`seismotools/checker/interface/pilot.py`）。** `events` 模式（已有初步目录，用于后端决策）和 `windows` 模式（还没有目录，用于拾取和关联参数；可提取 MiniSEED）。每个小批量三部分：代表性（60 %，时间 × 记录质量分层；只有这部分代表全目录，用于估计目录移动）、最繁忙时段（20 %，高事件率下的行为和运行时间）、最大事件（20 %，削波、长 S 波列、大事件震级）。`windows` 模式的最繁忙时段优先按拾取率选，没有拾取时按 10 分钟滑动背景上的瞬态扫描（Prague 检验：按全时段背景选出的窗口只有 6 个事件，是白天噪声；滑动背景 18 个，按拾取 28 个，全目录最忙半小时 30 个）。

**由此得到的协议：小批量验证正确性和预测效果，全量判定科学性和采纳。** 小批量阶段：检查代码和工具用法（单位、符号和基准面约定、仪器响应、列格式，这类错误对所有事件都一样）、所有 `item` 检查、运行时间外推、候选方案会让目录怎样移动。全量阶段：固定参数后运行，用同一个 checker 和 `compare.py` 判定 `population` 检查和是否采纳；报告小批量预测与全量结果的一致程度。与已有工作的区别（[`reference/notes/README.md`](../../reference/notes/README.md)）：R&D-Agent 在 10 % 子集上把代码调通，但不检验子集结论能否推到全量；MLE-STAR 在 3 万行子集上选方案，同样不检验；地震学目录论文里没有找到成文的小批量协议，也没有小批量对全量的定量检验。
