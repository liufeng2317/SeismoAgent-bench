# checker 首轮检验与有效性分类（2026-10-30 至 10-31）

从设计文档 [`../../04_Checker_Design.md`](../../04_Checker_Design.md) 迁出（2026-11-04）。checker 1.0 在 human-in-loop 定位轮次和第一轮正式运行上的检验：方法、合成回归测试、各阶段结论、对可信标准的覆盖和据此做的修改。附录保留 1.0 各阶段检查表的原始读数。

## 检验方法与结果（2026-10-30）

**方法：** `workflows/development/tools_case_validation/validate_checker.py` 在两类目录上运行 checker：每个案例 human-in-loop 的定位轮次（组件替换所用轮次的拾取、关联和定位结果，应当基本干净，衡量误报），以及每个已完成的正式 Agent 运行（相对 final 的误差已知，见 [`progress/SCORE_TABLE.md`](../SCORE_TABLE.md)，衡量检出）。`--stages` 按阶段运行（数据阶段每个案例只跑一次，因为同一案例的运行输入相同），结果写入被忽略的 `outputs/checker_stages*`。可视化不参与检验，但会对代表目录生成，人工检查图是否清楚、样本选得是否有代表性。

**合成回归测试：** `seismo_checker/examples/smoke/run.sh` 生成 10 个台站、80 个事件、2 小时 50 Hz 的合成数据（含平坦速度响应的 StationXML），运行 14 个场景：每个阶段的干净输入不报警；混合采样率、预处理时移 0.3 s、拾取整体早 2.5 s、10 % 重复拾取、40 % 事件压在同一深度、震级偏 −3、重定位整体加深 2 km、重定位压到 4 个点、震级按 nm/mm 混用偏 −2.68（与复算一致的目录不报警），各自由预期的检查报警（其他阶段对同一错误的连带报警单独列出并允许）。全部通过，约 5 分钟。写测试时发现并修正了三个问题：S−P 很短时 S 的 AIC 搜索找到 P 初动；完全压缩的簇厚度为 0 时比值变成 NaN 而不报警；稀疏目录中泊松涨落被当成分层条带。

**各阶段的检查：**

| 阶段 | 报警 | 仅报告或作安全检查 | 需校准或复核 |
|---|---|---|---|
| 数据 | 预处理时移（其余数据检查是输入说明：有数据无元数据、每日台站数、混合采样率、数据缺口） | 台网几何、分量类型、响应、方位角 | — |
| 拾取 | 无拾取台站、重复拾取、P 拾取–初动偏差 | 无拾取台站日、S/P 比、拾取信噪比、S 拾取–初动偏差 | — |
| 关联 | 拾取过少的事件 | 已关联占比、忙碌时段关联、重复事件、事件走时一致性 | — |
| 绝对定位 | 深度堆积、深度分层条带、Wadati 离散、S−P 深度（1.5 km） | 台网外、孤立（安全检查）、Wadati 发震时刻、走时截距、方位空隙、台站残差、模型组 | — |
| 相对定位 | 整体平移、局部变薄、大位移、移动比例 | dt.cc 统计 | 只有一个真实的干净样本（Magna r6） |
| 震级 | 震级范围、震级–检测距离、震级复算 | b 值、大震后事件率 | — |

**仅报告和输入说明如何实现：** `checks.py` 中的 `REPORT_ONLY` 表列出所有测得准、但在检验集上分不开干净和有错目录的检查（含拾取信噪比、事件走时一致性、方位空隙），`INPUT_CHECKS` 列出描述输入数据的检查；`run.py` 在写报告前统一设定每项的类别（`kind`：product / input / report_only）。`REPORT_ONLY` 的原因会显示给 Agent，因此只写通用说明、不出现案例名或案例数值，案例证据只记在本文。S 拾取–初动偏差在拾取检查内部只报告。seismotools 中的代码和注释同样不出现案例名。

**主要结论：** 质量类检查能可靠区分。时间和深度的物理一致性检查测得准，但被结构偏差盖住：相对 human-in-loop 的差值能反映真实误差，绝对值在干净目录上也会报警。速度模型造成的整体偏差只靠 Agent 自己的数据无法可靠判定，这是 checker 的边界，也是 S3 中知识部分（速度模型的选择方法）要解决的问题；checker 能提供的是"对模型有多敏感"的测量。新加的检查里，分层条带和震级–检测距离补上了以前查不出的两类错误（速度分层界面上的深度堆积、震级整体偏移）；关联的混合错误仍然只能通过图和代表事件的摘要提供给 Agent。

**最终版对已评分运行的覆盖（2026-10-30，不含模型组）：** 干净的 Kaikōura、Maple、Magna human-in-loop 不报警；Prague、Kīlauea、Ridgecrest 的 human-in-loop 中间轮次报出的（2.0 km 分层面、地表或网格顶部堆积、5 个无拾取台站）都是那一轮的真实问题。

| 运行 | 未通过的可信标准（已知误差） | checker 报警 | 查出 |
|---|---|---|---|
| Prague tools | 深度 +1.1 km；震级 −2.77（单位错误） | 震级范围、震级–检测距离、拾取过少的事件 | 震级 ✓，深度 ✗ |
| Magna tools | 水平偏移 2.35 km；深度 −1.94 km；震级 +0.67 | S−P 深度 2.03 km、分层条带 | 深度 ✓，水平 ✗，震级 ✗ |
| Maple tools | 时间 +1.15 s；深度 −2.18 km；水平离散；偏离构造 | 无拾取台站 30 %、拾取过少的事件 31 %、分层条带 | 只有质量问题；时间、深度 ✗ |
| Maple min | 几乎全部 | 6 项 | 能判断整体有问题 ✓ |
| Kīlauea min | 时间 −0.96 s；深度 +1.3 km；堆积；震级 −2.43 | Wadati 离散、堆积、分层条带 93 %、震级–检测距离 | 堆积、震级 ✓；时间、深度 ✗ |
| Kīlauea tools | 只有时间 −0.36 s | 无拾取台站 20 %、堆积、分层条带 11 % | 唯一的失败原因 ✗ |

按维度：强度（震级偏移 ≥ 2 级）、真实性（拾取和关联质量）、空间人为痕迹覆盖得好；发震时刻整体偏差 0/4、深度整体偏差 1/4、水平偏移没有对应检查。每个已评分运行都至少有一项时间、深度或水平偏差未通过可信标准，所以预期单靠 S2c 没有运行能达到可信标准；S2c 应当减少未通过的标准（尤其是强度），剩下的系统偏差留给 S3 的知识部分。一个侧面证据：Wadati 发震时刻偏移的绝对值被结构偏差盖住，但 Agent 运行减去同案例干净目录的值后，6 个运行的符号全部与已知发震时刻偏差一致——信息在数据中，缺的是只有知识（区域速度模型、Vp/Vs、台站校正）才能提供的参照。

**试过但不加的检查：** 事件在地表之上、同一台站 S 早于 P、拾取早于发震时刻、整小时没有事件，在所有目录上都接近 0 或与对错无关；"能量时窗无事件"（检测遗漏）只看得到大事件，而大事件所有目录都找到了（但震级常被低估，见 [01_first_validation.md](01_first_validation.md)）（Maple、Magna 0–2 %，Kīlauea 干净目录也有 39 % 是火山噪声），召回率的差距来自需要模板匹配的小事件。完整性和速度模型一样，是只看 Agent 自己的数据判断不了的边界。

## 有效性分类（2026-10-31）

**依据：** 最终版 checker（震级阶段，含拾取波形检查和震级复算）在 17 个目录上的结果：11 个 Agent 运行（第一轮正式运行全部，含 Ridgecrest、Kaikōura 的 min 和 tools）和 6 个 human-in-loop 目录（输出 `outputs/checker_v3`），逐项对照每个运行未通过的可信标准（[`progress/RESULTS_OVERVIEW.md`](../RESULTS_OVERVIEW.md)）。

**有效：报的是真问题，在接近 final 质量的目录上不误报。**

| 检查 | 查出的真实问题 | 误报 | 说明 |
|---|---|---|---|
| 深度堆积、边缘堆积 | Maple min、Kīlauea min、Ridgecrest tools（33 % 压顶）、Kaikōura min（49 %）和 tools（12 %） | 无（human-in-loop 中间轮次报出的都是那一轮的真实问题） | 最可靠的定位检查；可信标准"深度堆积"的不合格全部查出 |
| 深度分层条带 | Maple min 52 %、Kīlauea min 93 %、Kaikōura min 49 %、Kīlauea tools 11 %（换区域模型后 3 %）、Maple tools 7 %、Magna tools 6 % | 无 | 能间接反映速度模型错误；但正确的台阶模型也会在界面上形成条带（Prague 换区域模型后 13.5 %），**不能用来比较模型** |
| 震级复算 | Prague tools −2.57、Kīlauea min −2.31、Ridgecrest tools −1.12 | 无；区域标定差异（Magna +0.24、Kaikōura tools −0.32）正确地不报 | 最可靠的震级检查，把实现错误和标定差异分开 |
| 震级–检测距离、震级范围 | 与复算相同的运行 | 无 | 与复算重复；没有波形或仪器响应时的备用 |
| Wadati 离散 | Maple min 0.63、Kīlauea min 0.67、Kaikōura min 1.78、Kaikōura tools 0.52，都对应发震时刻不合格 | 无 | 门槛余量小：干净目录最高 0.46，门槛 0.5 |
| 无拾取台站 | Maple tools 30 %、Kīlauea tools 20 %（只有垂直分量的台站）、Ridgecrest human-in-loop 第一轮 | 无 | 真问题，与可信标准的关系是间接的 |
| 重复拾取 | Maple min 11 % | 无 | 触发少 |
| P 拾取–初动偏差 | 合成数据上的 −2.5 s 整体偏差 | 无 | 真实运行中没有这类错误，有效性只有合成验证 |

**部分有效：**

| 检查 | 局限 |
|---|---|
| S−P 深度 | 超过 1.5 km 的两个报警方向都对；门槛以下的数值方向常常相反（附录 §6 表）。门槛以下的数值应当在报告中隐藏方向或加注 |
| 拾取过少的事件 | Maple min、tools 报得对；Prague tools 报 21 % 但真实性维度合格。属于质量指标，不是准确性指标 |
| 孤立事件 | Ridgecrest min 12 % 对应"偏离构造"不合格；human-in-loop 最高 9 %，余量小 |

**无效（已为仅报告，本次再次确认）：** 台网外事件、Wadati 发震时刻偏移、走时截距、台站残差（离群和方位）、模型组、拾取信噪比、S 拾取–初动偏差、事件走时一致性（Kaikōura min 0.64 是唯一突出值）、已关联占比、忙碌时段关联、S/P 比、方位空隙。无拾取台站日（所有目录约 0）和重复事件（≤ 1 %）从未触发，开销小，保留作安全检查。

**错误：** b 值（final 自己低于门槛，附录 §8 表）；大震后事件率（无效且数值无意义）；已降级的 S 拾取–初动偏差和模型组。

**对可信标准的覆盖：**

| 可信标准 | 覆盖 |
|---|---|
| 深度堆积 | 全部查出 |
| 震级偏移 | 实现错误 3/3；区域标定差异（Magna、Maple min、Ridgecrest min、Kaikōura tools）查不出，由知识部分的区域系数库处理 |
| 发震时刻 | 离散类全部查出（Wadati 离散）；整体偏差（Maple tools、Kīlauea tools）查不出 |
| 深度偏差 | 部分：S−P 深度 2 个，堆积间接反映 2–3 个 |
| 水平偏移、离散、偏离构造、区域外 | 基本查不出（孤立事件 1 个） |
| 大事件 | 漏检（主震尾波）查不出；最大事件的震级偏低由新增检查部分查出（附录 §8），见下 |

**大事件：两个独立的问题。** 可信标准"大事件"统计的是参考目录中 M ≥ 4 的事件被匹配上的比例，即漏检。(a) **主震尾波中的漏检**：Ridgecrest tools 漏掉的 12 个 M4+ 事件中 10 个在 M7.1 后 1 小时内；Kaikōura tools 只漏 1 个 M4.6，不在主震附近。尾波期间所有台站能量都高，能量扫描和事件率都分辨不出，这是与完整性同类的边界，留给知识部分（大震后用模板匹配补检）。(b) **最大事件的震级被低估**：数据阶段能量最强的 4 个时窗在所有运行里都有事件，但 Ridgecrest tools 把 M7.1、M6.4 记为 5.3、5.2（min 为 6.0、6.0），Kaikōura tools 有时窗事件没有震级。新增的"大事件震级"检查（附录 §8）针对 (b)；按拾取数抽样的震级复算覆盖不到最大的事件。

**作为方案比较器：** 同一批拾取、Agent 自选模型与区域模型的两个目录（§2.4 of [`00_B_Research_Plan_Checker.md`](../../00_B_Research_Plan_Checker.md)），按"报警少者为好"选对 3/5：Kīlauea（报警 3 → 0，Wadati 偏移 0.43 → 0.05 s，与真实发震时刻偏差同时消失）、Magna（区域模型 19 % 压顶）、Maple（区域模型 42 % 分层条带）选对；Prague（区域模型界面条带 13.5 %，但实际更好）和 Ridgecrest（LITHO1.0 消除压顶但整体偏深 2.3 km）选错。比单独判断有用，但需要知识补充：台阶模型的界面条带不代表模型错；所有候选都不合格时应寻找更好的知识而不是挑最不差的。

**据此做的修改（2026-10-31）：**
1. b 值、大震后事件率改为仅报告（`REPORT_ONLY`）。
2. S−P 深度：只有超过门槛时报告方向；门槛以下只报大小，并写明方向不可靠。
3. 新增"大事件震级"检查（附录 §8）：候选事件取拾取台站最多的和目录震级最大的，用长窗口、剔除削波记录复算。没有用能量扫描，因为最大的事件同时也是拾取台站最多的，不必另做耗时的扫描。合成回归测试加入对应预期，14 个场景通过。
4. 报告的预期范围说明中写明：分层条带也会出现在正确分层模型的界面上，不能单独用来比较模型；拾取过少的事件衡量约束程度，不是定位对错。

## 附录：checker 1.0 各阶段检查表与检验读数（2026-10-30/31）

以下是 1.0 版时的检查表（含后来在 1.2 中删去的检查），保留当时的检验读数；现行检查见设计文档 §3–附录 §8。

### 附录 §3 阶段 1：数据与预处理

**目的：** 在拾取之前确认用了哪些台站、数据是否完整、分量是否齐全、预处理是否合理。

**输入约定：** `--waveforms` 指向 `NET.STA.LOC.CHA__start__end.mseed` 命名的波形目录。目录或其上一级有 `waveform_inventory.json`（基准任务的输入都有）时，覆盖率、缺口和采样率直接从中读取（由 MiniSEED 头信息统计）；没有时 checker 自己读头信息。`--processed-waveforms` 指向 Agent 预处理后的记录，命名规则相同；只需包含 checker 选中的时窗所在的台站日，报告的 `processed_files_needed` 列出这些文件。很多工具（例如 PhaseNet）在内部做预处理，Agent 可以只用这个选项检查自己显式做的预处理。

**数值检查：**

| 检查 | 计算 | 预期范围 | 状态 |
|---|---|---|---|
| 有数据的台站 | 有元数据的台站中处理时段内有波形的占比；列出有元数据无数据、有数据无元数据的台站 | 有数据无元数据的台站时写输入说明（无法定位使用） | 已实现，输入说明 |
| 每日台站数 | 每天有数据的台站数 | 某天低于中位数一半时写输入说明 | 已实现，输入说明 |
| 台网几何 | 孔径、最近台站间距中位数、以台网中心为准的最大方位空隙 | 报告 | 已实现 |
| 分量与采样率 | 每个台站的分量类型（ZNE、Z12、只有垂直）、仪器类型；采样率是否一致；Z12 通道是否缺方位角；N/E 通道方位偏离标称值超过 5°；缺少仪器响应的通道 | 同一台站采样率不一致时写输入说明，其余报告 | 已实现，输入说明 |
| 数据缺口 | 每个通道日覆盖率低于 90 % 的占比 | ≤ 5 % | 已实现，输入说明（Maple 输入 8.6 %，属于输入数据本身的问题，Agent 应当知道但改变不了） |
| 预处理时移 | 预处理后的记录与同一记录零相位 2–20 Hz 滤波结果的互相关时移，取代表记录的中位数 | \|中位数\| ≤ 2 个采样点（至少 0.02 s；[03_attribution_and_thresholds.md](03_attribution_and_thresholds.md)） | 已实现，仅在提供 `--processed-waveforms` 时计算 |

**代表时窗的选择（固定规则）：** 每个台站的垂直分量取每秒一阶差分的峰值，除以该台站全时段的中位峰值；某 20 s 区间内比值超过 8 的台站数最多（相邻两个区间合并以覆盖台网内的走时差）、彼此相隔至少 1 h 的 4 个区间即为代表时窗，大概率是地震。每个时窗取比值最高的 6 个台站，从最早的能量起始前 8 s 开始画 40 s。

**可视化：** `data_stations.png`（台站按分量和仪器类型着色，标出台网中心和 30° 方位扇区）；`data_availability.png`（台站 × 日覆盖率）；`data_window_N.png`（左列原始记录、中列预处理后记录，右列垂直分量的信号和噪声频谱；没有 `--processed-waveforms` 时中列是标准处理，图上注明）。

**检验：** 六个案例的输入上，除 Maple 的数据缺口外不报警；合成数据上，混合采样率和 0.3 s 的预处理时移都能查出。Prague 一次运行约 2 分钟（扫描 552 个日文件）。

### 附录 §4 阶段 2：震相拾取

**目的：** 拾取方法和参数是否合适：台站是否都用上、拾取是否准、有没有系统偏差。

**数值检查：**

| 检查 | 计算 | 门槛 | 状态 |
|---|---|---|---|
| 无拾取台站 | 有波形的台站中没有任何拾取的占比；列出其中只有垂直分量的台站 | ≤ 10 % | **报警**：Maple tools 30 %、Kīlauea tools 20 %（都是只有垂直分量的台站）；Ridgecrest human-in-loop 第一轮 12 % 也是真实问题；其他 human-in-loop ≤ 8.5 % |
| 无拾取台站日 | 在其他日子有拾取的台站，有数据却无拾取的台站日占比 | ≤ 5 % | 安全检查（各目录 ≤ 0.6 %） |
| 重复拾取 | 同台站同震相、间隔 ≤ 0.3 s 的拾取占比 | ≤ 2 % | **报警**（Maple min 11 %） |
