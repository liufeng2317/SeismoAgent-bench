# 近地表约束、震级压缩与模板匹配：离线诊断（2026-11-03）

从设计文档 [`../../02_Checker_Design.md`](../../02_Checker_Design.md) 迁出（2026-11-04）。不提供具体速度模型之后，检验只凭数据能否约束近地表；震级标度压缩的来源；`compare.py` 是否应在换模型时不计 `sp_depth_offset`；模板匹配阶段是否需要检查。


决定（2026-11-03）：所有案例都不向 Agent 提供具体速度模型，只提供用法知识（基准面、台阶与梯度、定位程序差异）和"如何约束近地表"的方法。[04_tier_b_backend.md](04_tier_b_backend.md) 的审计显示时间和深度偏差主要来自近地表，于是先离线检验：不给区域模型时，Agent 能否只凭数据把近地表约束住。

**近地表（`workflows/development/replay/near_surface.py`，输出 `outputs/near_surface/`）。** 每个案例用正式 tools 运行的拾取，取 `pilot.py events` 的代表部分 500 个事件，用 NonLinLoc EDT_OT_WT 定位。候选模型：通用 CRUST1.0 柱（Vs 取数据自身的 Wadati Vp/Vs，顶面放在台站平均高程），以及在它上面加 1/2/3 km 厚、Vp 2.5/3.5/4.5 km/s 的低速表层，共 10 个。每个候选记录 Agent 不看参考就能算的量：Wadati 发震时刻偏差、走时截距、S−P 深度偏差（带符号）、台站残差均值、RMS 中位数、最浅深度处的比例；再对 human-in-loop 最终目录评分（时间、深度偏差）。

| 案例 | 通用柱 时间 / 深度 | 有候选通过（0.3 s、1 km） | Wadati 与时间偏差的相关 | 最佳候选的 Wadati 偏差 |
|---|---|---|---|---|
| Prague | +0.06 s / +0.69 km（通过） | 7 / 10 | −1.00 | −0.16 s |
| Kīlauea | +0.11 / −1.13 | 3 | −0.99 | −0.17 |
| Magna | +0.28 / +1.12 | 3 | −0.98 | −0.50 |
| Ridgecrest | −0.53 / +2.39 | 0 | −0.99 | −0.17 |
| Maple | +1.59 / −3.22 | 0 | −0.34 | −0.15 |
| Kaikōura | +0.46 / −4.63 | 0 | −0.87 | +0.08 |

在有候选通过的三个案例上，按单一量选候选：最小 |Wadati 偏差|、最小 RMS、最浅深度比例最小各错 1 个（都错在 Magna），最小 |走时截距|、最小 |S−P 深度偏差| 各错 2 个；没有一个量三个案例都选对。以 |时间|/0.3 + |深度| 作综合误差，六个案例平均：通用柱 3.88，按 Wadati 选 3.91，按 RMS 选 4.01，按最浅比例选 4.17，按 S−P 选 3.65，按截距选 3.50，事后最优 2.63。

结论：
1. **数据只给方向，不给水平。** 同一案例内，表层越慢越厚，Wadati 偏差越正、发震时刻越早，几乎一一对应（六个案例中五个相关 −0.87 至 −1.00）；但正确模型处的 Wadati 偏差因案例而异（−0.5 至 +0.1 s），不存在"调到零"的目标。所以不能写成选择规则，只能用来检查候选是否按地质预期移动。
2. **低速表层不是通用修复。** 三个案例里没有任何候选能同时通过时间和深度判据（Ridgecrest 所有候选时间都偏早，Maple、Kaikōura 深度偏浅 2.7–4.6 km），误差在更深的结构、定位程序或拾取。与 [04_tier_b_backend.md](04_tier_b_backend.md) 单因素实验一致（Maple、Magna 单换模型修不好）。
3. **候选间的离散就是不确定度。** 各案例候选间的时间差 0.3–0.9 s、深度差 0.6–5 km；在没有独立信息时应作为不确定度报告。

写进知识 skill（`symptoms/not_visible.md` 新增"不用区域模型时约束近地表"一节，不含案例名）：按地质（沉积、盆地、火山沉积的厚度和速度）构建一个无表层候选和两三个覆盖合理范围的候选；Vs 用数据的 Wadati Vp/Vs；Wadati 偏差、截距、S−P、RMS、最浅比例只用来核对方向，不用来选；按地质证据先定、写明理由，候选间的离散作为不确定度报告，并声明近地表未被独立信息约束。

**震级压缩（`workflows/development/replay/magnitude_scale.py`，输出 `outputs/magnitude_scale/`）。** 按参考震级均匀取 300 个事件（Prague、Maple、Ridgecrest），用标准 ML 从波形重算，每次只改一项处理；斜率是 (M − Mref) 对 Mref 的回归斜率（评分器的算法），以 human-in-loop 最终目录在同一参考上的斜率为基线（参考自身的误差就会使斜率为负）。

| 案例 | 最终目录 | Agent 目录 | 标准重算 | 1 Hz 高通 | 记录 SNR ≥ 3 | 长窗（S + 30 s） | 仅 100 km 内 |
|---|---|---|---|---|---|---|---|
| Prague | −0.21 / −0.23 | −0.36 / −0.08 | −0.27 / −0.22 | −0.26 | **−0.34 / −0.05** | −0.30 | −0.27 |
| Maple | −0.31 / +0.15 | −0.50 / +0.16 | −0.43 / +0.15 | −0.43 | **−0.61 / +0.40** | −0.44 | −0.43 |
| Ridgecrest | +0.01 / −0.09 | −0.08 / +0.05 | −0.02 / −0.09 | −0.02 | −0.04 / −0.01 | **−0.09 / +0.06** | −0.02 |

（斜率 / 中位偏差。）
1. **按记录自身的振幅选记录（SNR 门槛）造成压缩。** 小事件只留下恰好信号强的台站，偏大 0.1–0.25；斜率比标准重算陡 0.01–0.17。Prague 的 Agent 目录斜率（−0.36）与 SNR 选择（−0.34）相近。
2. **长窗在密集序列中造成压缩**（Ridgecrest −0.07），因为窗内混入其他事件。
3. **高通和距离限制没有影响。**
4. **剩下的是定标。** 标准关系本身比用区域定标的最终目录陡 0.04–0.12（C 层）。

写进知识 skill（`symptoms/magnitude_completeness.md` 新增"压缩的震级标度"条目，`magnitude/README.md` 附录 §3 表加两行）：测量前按距离、数据质量和响应选台站，不按被测振幅选；没有可测振幅的事件给上限；大多数事件用 S 波列窗，长窗只用于最大事件并检查窗内无更大事件；用区域定标；不看参考的检验是"全部记录"和"保留记录"两种震级之差是否随震级减小而增大。checker 的 `magnitude_recompute` 细节中 `slope_catalog_vs_recomputed` 明显小于 1 是压缩的迹象，但它不能升级为判定检查：在 B 层 12 个带 checker 的运行上，它与评分器的震级标度判据不一致（Maple knowledge 1.01 却不通过，Magna checker 0.78 却通过；Prague 两个变体 0.92–0.93 不通过，Kaikōura 0.94–0.95 通过），因为标准复算本身相对参考也有压缩（上表），而且多个 Agent 直接沿用了复算代码，斜率近于 1 是循环的。保持只报告（在细节中）。

**换模型时 `compare.py` 是否应不计 `sp_depth_offset`（2026-11-03，否）。** 用 [02_replay_compare_pilot.md](02_replay_compare_pilot.md) 的 15 组换模型记录重算：不计它时判对 4 → 6、判错 3 → 5、未决 8 → 4，新增的两个错误都是把真正更好的梯度模型判为更差。它在 7 次"改善"中 3 次真更好、4 次真更差，单独不能排序，但留在规则里使 compare 停在 `mixed`，不下错误结论。保持原规则。

## 模板匹配阶段的检查（评估后不新增）

2026-11-03 评估：六个案例专家流程的零假设检验（通道随机平移 ≥ 600 s）显示误检比例随 nMAD 门槛急剧下降（8 → 9.5 时从 34–94 % 降到 0.2–1.8 %），假检测集中在门槛附近；但仅有的两个 Agent 全量模板匹配（Ridgecrest、Magna tools）门槛都很保守（10.05、16.3），门槛附近几乎没有检测，误检不是问题；问题是漏检（以专家模板集估算，Magna 门槛 16.3 只保留 nMAD ≥ 9.5 检测的 38 %，Ridgecrest 10.05 保留 89 %）。漏检从产品本身看不出来，Agent 运行太少也无法校准判定门槛，故不新增检查；知识 skill 的零假设检验条目补充"用零假设检验在一组门槛上选通过的最低门槛，而不是取一个保险的高值"。
